# M01 / CPU-Ara AXI width recommendation

> 记录日期：2026-10-09。2026-10-11 按任务/主题命名迁移；下方保留原始内容与验证边界。后续同主题变更在文件头追加修改记录。
Date:2026-10-09. HEAD278434024. Analysis only; no production RTL/profile or vendor Word changes.
Read L01 width handoff and targeted local definitions. Current VCU118 add_sources specifies NR_LANES=2 and VLEN=2048. AraDataWideWidth=32*NrLanes, so current Ara source is64-bit. A wider global crossbar alone does not double its source bandwidth, although aggregate traffic and LLC refill/eviction service may benefit.
Recommendation: preserve DW64/AW48 baseline for two lanes unless profiling shows shared-path contention; evaluate DW128 first for four lanes or substantial concurrent CPU/DMA/Ara traffic. Avoid DW256/512 global changes for this baseline. WT vector profile has128-bit I-cache and256-bit D-cache lines;128 is a static candidate, not validated. WB scalar profile cannot inherit the same choice without addressing its line/DW assertion. Global width forwards into CVA6 config.
If evaluating128, keep benchmark capacity comparable: unchanged LLC geometry doubles capacity to256KiB and line to128B; NumBlocks4 instead of8 is a candidate to retain128KiB/64B, subject to elaboration and functional validation. Preserve software/SPM consistency. Ara converter max reads currently4 is another possible bottleneck, not automatically to be increased.
Vendor CPU-facing port should match selected SoC width64 or128 using native mixed-width support; NPU independent256 path remains. DDR does not require every master to fill physical bandwidth. Compare64@533.25=4.266GB/s vs128@333.25=5.332GB/s ideal aggregate data-path per direction, with timing/source limitations explicit.
Evidence: hw/cheshire_soc.sv606,818,860-864; hw/cheshire_pkg.sv498,560,603,650-651; add_sources.vcu118.tcl786-787; WT profile and wt_axi_adapter; std_nbdcache assertion. Official Ara https://github.com/pulp-platform/ara/blob/main/hardware/src/ara_soc.sv also uses32*NrLanes, corroborative only; local revision authoritative.
No compile/simulation/STA/board test. Need representative vector and concurrent-traffic measurements, same-frequency/capacity comparison, cache refill/narrow/atomic/DMA verification before selecting128. No decision to modify lane count or frozen configuration. Existing files preserved, handoff uncommitted.
