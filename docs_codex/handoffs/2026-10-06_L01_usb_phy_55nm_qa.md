## 外部补充与结论边界

- [SpinalHDL USB OHCI 官方文档](https://spinalhdl.github.io/SpinalDoc-RTD/master/SpinalHDL/Libraries/Com/usb_ohci.html)：LS 1.5 Mbps / FS 12 Mbps，内部 PHY 需至少 48 MHz、12 MHz 整数倍时钟，部署可无需外置 PHY。网页为更新版本，仅补充原理；本地模块结构以生成文件为准。尝试访问与生成头匹配的上游两份 Scala 文件，网页获取返回 cache miss，未声称完成该版本上游复核。
- [Synopsys PHY 数据页](https://www.synopsys.com/resources/usb-2-0-phy-ip-datasheet.html)：商用完整 USB 2.0 PHY 属混合信号 IP，支持 UTMI 及 HS/FS/LS。
- [芯原官方 USB2 PHY 页面](https://www.verisilicon.com/cn/IPPortfolio/USB2PHY)：列出包括 55 nm 在内的 silicon-proven 工艺节点及模拟前端/UTMI 接口；不是所有节点与所有列举 foundry 的组合均获确认。
- 工程判断：数字 RTL 可作为向 55 nm 标准单元映射的输入，但本轮未综合/STA；完整 USB 端口需要符合 USB 电气要求的工艺 I/O/收发器、时钟、ESD、板级供电和电阻等配套。当前证据不足以确认本项目具体 55 nm PDK 可直接使用。
- 设计建议：先确认 host/device、LS/FS/HS 与具体 foundry/PDK。若购买 UTMI/ULPI PHY，当前 D+/D− 数字端口不能直接对接，需重做接口集成或换控制器组合；增加 HS PHY 不会使当前 LS/FS OHCI 具备 480 Mbps 协议能力。

## 后续问答：方案完整性与现有设备（同日）

- 用户继续询问方案是否完整、仅使用该方案能否接入现有设备；HEAD 仍为 `5ddec4fb4`。
- 结论：上游提供可实际运行的 LS/FS 数字主机方案；官方报告 mass storage、键鼠、音频输出和 hub 的运行案例。但本地工程不构成已经验收的端到端 USB 产品，不能把上游案例当本地通过。
- 官方还提示部分 hub 与 LS 设备的组合存在兼容问题，部分现代设备不能在 FS 下工作。具体设备必须确认 LS/FS 模式及匹配的设备类驱动，不能仅凭 USB 2.0/3.x 名称保证兼容。
- 本地 `sw/include`、`sw/lib`、`sw/tests` 的定向 USB/OHCI/tinyUSB 搜索仅命中基址声明和功能位，未找到完整裸机 USB 主机栈；不否认 SDK 第三方 Linux/U-Boot 中另有通用驱动。
- 当前 `add_sources.vcu118.tcl` 的两份 verilog_define 列表均无 USE_USB；结合 wrapper 配置分支确认该配置关闭 USB。fixture 仍把 PHY 时钟绑零。
- `UsbOhciAxi4.v:1040` 四端口 overcurrent 输入绑零；当前数字端口不能自动提供板级 VBUS 电源、过流保护、端接、ESD 或插座。
- 澄清：没有模拟 PHY 宏不等于 LS/FS 方案一定需要另购完整 PHY；上游可依赖适用 FPGA I/O 和外围电路工作。ASIC 是否可沿用须以具体工艺 I/O 的电气能力为依据。
- 需补齐时钟/复位、符合 USB 电气条件的接口及 VBUS 等外围、主机控制器驱动/枚举/设备类栈、DMA 缓存一致性，再做端到端验证。此 OHCI 为 host，不能直接当 PC 的 USB device 使用。
- 新增外部电路依据：[TI USB OHCI host 参考原理图](https://www.ti.com.cn/cn/lit/pdf/tidrc67)，含收发器、15 kΩ 下拉、VBUS 电源开关及插座，作为外围电路示例，不表示直接适配本地 RTL。
