## 1. 结论与用户反馈

现有问题主要来自四个层面：**信息选择、领域表达、最终尺寸、设计约束**。颜色和圆角只是外在表现。建议新 skill 优先建立“技术事实与图意 → 图式选择 → 出版尺寸布局 → 输出与检查”的工作方式，保留旧 skill 已具备的可编辑性和导出验证。

用户本轮明确反馈：

- 彩色圆角框过多，像演示模板。
- 文字拥挤，层次与连线不清。
- 布局过于模板化，缺少领域图式。
- 图稿受聊天上下文影响，自动加入周围的说明文本框等不必要文字。

因此，新方案需要控制**哪些内容值得进入图面**。即使一句话事实正确，也不意味着它应当占据一个框。

本报告用“模板化、内容冗余、语义不足”等可检查的问题替代含混的“AI 味”。不根据外观判定作者是否使用 AI，也不设置无法验证的“AI 检测分数”。

## 3. 官方规范：必须按年份和出版阶段区分

### 3.1 IEEE 通用图稿要求

[IEEE 尺寸和分辨率指南](https://journals.ieeeauthorcenter.ieee.org/create-your-ieee-journal-article/create-graphics-for-your-article/resolution-and-size/)优先建议矢量图。其页面列出的常用宽度为单栏 88.9 mm、双栏 182 mm；非矢量彩色/灰度图要求大于 300 dpi，黑白线稿大于 600 dpi。提高已有低清图片的 dpi 标签不能补回细节。这是通用参照，实际仍以目标模板的栏宽为准。

[IEEE 文件格式指南](https://journals.ieeeauthorcenter.ieee.org/create-your-ieee-journal-article/create-graphics-for-your-article/file-formatting/)列出 PDF/EPS/PS/PNG/TIFF 等交付格式，要求处理好字体嵌入或文字轮廓；建议图中文字在最终尺寸约 9–10 pt。**9–10 pt 是该指南的建议，不是所有会议统一的硬性下限。** SVG 和原生 PPTX 可以作为编辑母版，但不应自动视为投稿文件。

[IEEE 可访问性建议](https://journals.ieeeauthorcenter.ieee.org/create-your-ieee-journal-article/create-graphics-for-your-article/)强调颜色之外再用线型、标记、明暗或直接标签表达区别。灰度打印仍能理解是实际检查项。

旧 skill 要求母版文本可编辑，与最终投稿 PDF 的字体嵌入并不冲突。建议默认使用嵌入字体的出版 PDF，始终保留原 SVG/PPTX 文本；如特定交付必须转轮廓，仅处理另存的出版副本。

## 5. 可以复用的设计规律

### 5.1 用图说明关系和机制

画图前先形成一句内部设计陈述，例如“本图说明请求者如何汇聚到 DDR，以及哪些访问经过 LLC”。这句话用于约束内容，**不自动作为图内横幅**。

选择内容时，对每个元素检查：它是研究对象、端口、连接、状态、参数、证据，还是对话中顺带产生的解释？后者通常进入正文或交接。删除与图意无关的内容，比删除几个圆角更有效。

同一篇工作可以需要总览、机制、时序、实验四种图。一个总览图不必同时解释总线所有通道、软件所有步骤、全部验证风险。

### 5.2 按领域使用图形语法

| 图类 | 应优先表达 | 合适的视觉元素 |
|---|---|---|
| 模拟/混合信号电路 | 器件、反馈、信号极性、偏置、采样相位 | R/C/MOS/放大器/开关符号、节点连接、I/Q 或差分对称支路；必要波形单独子图 |
| 数字数据通路 | 算子、选择、状态寄存、数据位宽 | MUX、加法器、乘法器、寄存器、FIFO、SRAM 阵列、总线分支 |
| SoC 架构 | 发起端、目标端、互连、域边界 | 总线骨架、带端口模块、存储 bank、相关单元放大图 |
| 缓存/存储机制 | 地址字段、索引、比较、选择、命中/替换 | 字段切分、set×way 阵列、比较器、命中向量、选择器 |
| 体系结构机制 | 数据移动、映射、并行、顺序约束、代价 | 逐拍/逐步小例子、before/after 同尺度面板、数据块/队列/映射矩阵 |
| AI 模型 | 张量形状、算子、支路、训练/推理差别 | H×W×C、token/窗口、加/乘/拼接、输入输出实例、共享权重和重复次数 |
| 定量结果 | 数值关系、尺度、条件、误差 | 标准绘图库生成的曲线/散点/柱图；单位、基准、误差定义 |
| 定性结果 | 可比较的局部差异 | 同一输入与裁剪、同一放大率、共享色标、方法名、失败案例 |

结构越规整越好与结构越不规则越自然，都是错误的绝对规则。SRAM、PE 阵列本来就应该规整；反馈环、树形互连不应被强压为三个等宽卡片。几何结构应服务真实关系。

### 5.3 控制抽象层级

总览图可将 AXI 请求/响应归纳成接口，但必须说明箭头语义。详细接口图才展开各通道和方向。不能用一个箭头既代表“请求向前”，又代表“数据双向传输”，还让读者以为它表示物理单向线。

模块层、端口层、电路层混合时，采用明确的局部放大对应；不要在 CPU 框旁放一个放大几十倍的 MUX，却不给它所属位置。硬件图中的虚线域应命名为 clock/power/security/physical 或 logical group 中的具体一种；几何框不会自动形成硬件域。

### 5.4 让重点形成层次

建议从黑白草图开始确定结构，新增机制或关键数据路径再用少量强调色。上下文可以较弱，但仍须读得清楚。无需把每个模块都设成同样大的、同样醒目的色块。

论文图常把说明交给 caption；图面由短标签、连接和局部符号承担主要表达。尤其不应默认在图顶写聊天式大标题，在图底堆“注意、范围、依据、下一步”。必要的 `(a)`、`(b)` 及短子图名可以保留。

### 5.5 颜色必须有稳定含义

建议起点为黑/灰加 1–2 个强调色，必要时扩展。这个数量是审美默认，不是期刊要求。数据类型、模块家族、状态或比较组可以分别成为配色依据，但同一幅图不应让同一个颜色无说明地承担冲突含义。

数据流图可把 weights、activations、partial sums 固定为不同颜色；硬件总览可按功能类别着色；热图应有连续色标。红色不必永远表示错误，也不能同时默认表示新增、危险、读请求和性能最优。

在颜色之外保留名称、线型或符号。关键连线用深色，避免浅灰细线只在白底大屏上可见。浅色填充可以使用，但不应因此把所有框都变成 UI 卡片。

### 5.6 连线先于装饰排布

先决定入口、出口、汇聚点和返回环，再摆放模块，最后放标签。SoC 图尽量保持主路径明确、分支短；跨线不等于相连，连接点语义需统一。逻辑信号的交汇点与总线汇聚端口不能混淆。

正交折线是硬件图的常用选择，不是唯一选择。ResNet 的弧形 bypass、MAERI 的树形边都服务结构。不要为追求线条整齐，把多个独立端口合并或删去返回路径。

线宽只能在图例/规则支持时表达“主路径、控制、选中”等含义，不能仅凭粗线暗示更高带宽。未知位宽不填写猜测值。

### 5.7 文本是标签，不是缩小后的正文

图内标签尽量采用模块名、信号名、参数、单位或必要的短动作。模块框中的默认内容可以是“名称 + 一项关键参数”；复杂算子/电路可包含更多必要符号，不设僵硬的每框两行上限。

使用统一字体层级，数学量、上下标、希腊字母和正文记号一致。英文论文按其模板及符号体系；中文教材使用可靠的中文字体，并实际核验 fallback。不能因为 SVG 属性写了某个字体名就宣称渲染使用了该字体。

PPT 可编辑文本与精细数学排版可能存在限制，需在新后端规划中明示。不应把所有数学式静默转 path，也不应伪称每个字都可编辑。

### 5.8 参数以最终物理尺寸为准

以下是建议基线，目标场所规则优先：

| 项目 | 本项目建议起点 | 调整原则 |
|---|---|---|
| 图内普通标签 | 最终尺寸 9–10 pt | 按场所明确下限和实际可读性调整；不以 6 pt 作为通用目标 |
| 轮廓/普通连线 | 最终尺寸约 0.6–0.9 pt | 细节密度与打印结果优先，没有统一官方范围 |
| 强调路径 | 约 1.0–1.3 pt | 相对普通线有限增强，不喧宾夺主 |
| 面板边界 | 无框或较轻的边界 | 只有分组/域语义才保留大框 |
| 节点形状 | 直角矩形与领域符号优先 | 已有图或参考明确需要圆角时保留 |
| 画布 | 目标栏宽/图槽宽先确定 | 不默认 16:9；展示模式可以另设版式 |
| 留白 | 给标签、连接、面板间距留出可辨空间 | 不硬设统一百分比，不用过多留白迫使字体缩小 |

上述线宽等数值应在未来样例评审中微调，当前不是实现参数冻结。

### 5.9 实验图需要证据，不只需要外观

图表使用真实数据与可重现脚本。性能倍率应说明基线，能效/吞吐须带单位及工作负载/精度/运行条件。区分 measured、simulated、estimated；不从结构图推断已经测得的性能。

条形图原则上从零开始；折线图如采用局部范围，应明显显示轴范围且不误导。对数轴明确标记。只有存在相应统计意义时才绘制误差条，并说明是标准差、置信区间还是其他量；芯片不同样品/PVT 扫描也不能用随机误差条替代。

视觉结果比较应使用相同 ROI、比例和显示处理；不对某一方法单独增强。照片、die shot、注意力热图可作为独立位图面板，但不能生成虚构的“实测芯片”或“模型结果”装作证据。

## 6. 防止聊天文字进入图面的规则

### 6.1 三个位置各负其责

| 内容 | 默认位置 | 本项目例子 |
|---|---|---|
| 对象/信号/位宽/关键容量 | 图面 | `CVA6`、`AXI4`、`64 b`、`128 KiB` |
| 会改变结构理解的状态 | 图面简短标识，并在图注解释 | `proposed`、`optional`、`not to scale`；必要的拓扑前提 |
| 支路的本质作用 | 图面短标签 | `RAW bypass`、`GB access` |
| 方法假设、缩写展开、例子条件、箭头含义 | caption | 示意的 bank 分配；只画请求方向、未展开响应 |
| 源码路径/提交号/未完成验证/工程后续动作 | 伴随文档/证据报告 | HEAD、哪些测试未跑、后续由谁确认 |
| 对话回应与提醒 | 通常省略或留在聊天 | “请注意”“不要误认为”“待用户确认后再做” |

不是把必要事实藏到图外：若某个前提一旦忽略会导致错误架构理解，应在图面保留短标记，caption 给出完整条件；不够独立成图时，保留一条必要的精简注释，而不是强行执行零注释。

### 6.2 具体改写示例

| 现有表达倾向 | 图面候选 | 图注/文档承接 |
|---|---|---|
| “NPU 计算引擎 / 独立于 DDR 搬运器” | `NPU` 与独立 `DMA` 模块 | 说明 DDR master 由搬运器发起 |
| “GB 容量、bank 数、位宽与频率待定” | `GB SRAM`；如容量影响图意，标 `capacity TBD` | 待定参数清单放伴随文档 |
| “搬运器也是 GB 访问者” | 直接把 DMA 接到正确的 GB 访问端口 | 图注说明该连接的读写语义 |
| “三口成立条件……若……可增加 S3……” | 三个请求源、S0/S1/S2；必要时标 `shared DMA` | 明确本图假设统一搬运出口；四口另画候选图，不压成底部段落 |
| “SPM 绕过的是 LLC Tag 管理，不等于 CPU L1 一定不缓存” | 若图意涉及 L1，则画出 L1 与 SPM 路径；否则不加独立说明框 | caption 保留这一边界，教材正文解释缓存属性 |
| “未新增目标运行 / HEAD / 日期 / 源码依据” | 不进入正式论文图面 | provenance/交接记录保存，不删除证据 |

新 skill 应从对话提取“事实与约束”，再独立编写标签。不能直接把最近一条聊天答复分段填进彩色框。文本检查只能提示疑似冗余句，仍需判断语义；不能通过关键词机械删除 `proposed` 等必要状态。

## 7. 当前两张图与旧 Skill 的定向检查

### 7.1 已有优点

- 源码/参数/候选方案边界有记录，没有把未实现部分伪装成验证结果。
- SVG 文本与 PowerPoint 原生对象保持独立，不是整图 PNG。
- LLC 图已经采用地址字段、set×way 阵列、选中行和用途位图，有可保留的领域结构。
- DDR 图的三个请求源与主要数据流有可用骨架，不能因美化随意改变它们。

### 7.2 可以确认的出版尺寸问题

检查输入：

- [DDR 互连 SVG](../2026-10-10_ddr_lvds_isp_gb/ddr_interconnect.svg)，`viewBox=1920×1080`，74 个 text 元素。
- [LLC/SPM 最终 SVG](../2026-10-10_llc_cache_spm/source_final/llc_cache_spm.svg)，`viewBox=1680×1120`，177 个 text 元素。

本次两份 SVG 未使用需额外计入的缩放变换。若按整张 viewBox 等比缩放到 `W_mm`，有：

`最终字号(pt) = SVG font-size / viewBox宽 × W_mm / 25.4 × 72`

| 图稿 | 当前常见标签值 | 缩到 182 mm 双栏宽 | 缩到 88.9 mm 单栏宽 |
|---|---|---|---|
| DDR | 17–23 SVG 单位 | 4.57–6.18 pt | 2.23–3.02 pt |
| LLC/SPM | 大量标签为 18–22 SVG 单位 | 5.53–6.76 pt | 2.70–3.30 pt |

这是假定整图进入该栏宽的计算，**不是说它们已被这样投稿或打印**。如果裁成局部子图，缩放比会改变，必须重新算。

旧导出器 `scripts/svg_to_pptx.py::create_deck()` 固定 `slide_width=12801600` EMU，即 14 英寸；`min_text_pt` 反映这张 PPT 的字号。LLC 图 17 单位在该画布上得到 10.2 pt，与现有交接一致；同一图缩到论文双栏只有约 5.22 pt。后者才是论文验收应关注的量。已有报告并非算错，而是它验证的用途与论文不同。

### 7.3 视觉层次问题

现有图将大标题、副标题、分区标题、模块正文、补充段落和底部证据同时放进画布。多个外层浅色圆角框又包围多个内层圆角框，模块的实际硬件差异不容易通过形状辨认。信息多不等于关系清楚。

因此建议保留内容证据，通过拆图与 caption 分工减轻画面。文字删减应改变呈现位置，不应丢失 Cache/SPM 转换、候选 GB、三口条件等技术边界。

### 7.4 旧 Skill 的能力缺口

| 当前约定或实现 | 本次确认的限制 | 新方案需补充 |
|---|---|---|
| 强调母版/导出可编辑 | 没有先确定图意和图型的步骤 | 内部 figure brief 与图式选择 |
| 保持圆角、沿用可用布局 | 对保真转换合理；用于新图时缺少领域默认 | 新图与保真转换分开决策 |
| PPT 页面固定 14 in 宽 | 最小字号不代表出版尺寸 | 显式最终宽高与 effective font/stroke 报告 |
| 不支持 `stroke-dasharray` | 虚线只能拆成很多独立线段 | 规划原生虚线/语义边界支持或有声明的降级 |
| 不支持 SVG `image` | AI 实例图/die photo 等混合面板不能直接走原路径 | 单独允许有来源的位图面板，同时保留矢量标签/连接 |
| 检查整个 PPTX 无 media | 对纯结构图有效 | 混合图改为允许清单，仍禁止整图扁平化替代结构 |
| 文字数量、对象数量一致 | 不能证明端口归属、箭头含义或标签可读 | 内容/连接检查、最终尺寸视觉检查 |
| 多个 SVG 基元对应原生对象 | 不等于语义分组、拖动后自动重连 | 如后续需要，单独实现 group、connector 端点关系 |
| 不默认阴影/装饰 | 还不能阻止外围长文本和卡片堆积 | 图面内容准入规则与简洁 caption 分工 |

## 8. 两张现有图的优化规划

本节仅描述后续候选方案，本次没有重绘。

### 8.1 DDR / LVDS / ISP / GB

建议先制作两个相互引用的图，而不是缩小一张大图：

1. **系统连接图**：保留 CVA6/Ara、主互连/LLC 路径、NPU/GB、图像 DMA、DDR 三个入口。核心是请求者、目标端与旁路。使用总线骨架和简短端口标签；控制面若非本图主题，由 caption 明确省略。
2. **图像与 GB 数据流图**：展开 RAW/ISP 选择、像素流、GB 客户端与 DMA。本图解释数据经过哪里，不把 DDR 控制器内部调度再画成大段说明。

把既有模块与拟新增模块用一种稳定的短标识区分；底部不再放长句式“三口成立条件”，但 caption 必须保留统一 DMA 出口的假设。不要为减少框数把 NPU 计算引擎与 DMA 合并为一个实际并不存在的 IP。

### 8.2 LLC / Cache / SPM

建议在论文模式形成三个紧凑面板，或根据栏宽分成两张图：

- `(a)` 访问机制：地址拆分 → set 索引 → tag 比较 → hit/way 选择 → data。可以只详细展开代表 way，其余用 `×8` 或明确省略，避免重复几十个相同 `T/V/D` 标签。
- `(b)` 阵列用途：同一数据阵列的 cache/SPM 用途位图；保留 `0x00/0x0F/0xFF` 示例和总容量守恒；颜色只编码用途。
- `(c)` 转换顺序：软件准备 → 请求提交 → 硬件协调/刷新 → 契约规定的完成确认。必要的前提放 caption，不能把 `COMMIT` 清零画成全部刷新完成。

若本图只是教学解释多路组相联，转换流程可独立成图。若目标是介绍可重配置存储，则阵列复用应成为主体。不能未经图意确认同时追求两种重点。

## 9. 新 Skill 的规划

### 9.1 定位与保留关系

候选名：`publication-figures`，名称尚待用户建议。旧 `svg-pptx-diagrams` 原样保留，用于对照、保真转换与既有流程。

新 skill 的核心职责建议为：按领域惯例组织论文结构/机制图，输出可编辑母版与按目标尺寸检查的出版图；支持用户要求的中文技术报告模式。它不负责凭空构造技术事实，不以“顶会风格”替代具体图式。

新 skill 不应依赖一个绝对路径下、随时会变化的旧 skill。实施时可审计后复制并版本化最小导出后端，或采用明确版本的共享后端。第一版具体选择要结合代码维护成本，不在本轮改旧文件。

### 9.2 按需读取的内容设计

以下为候选资源职责，**不是已经创建的目录**：

| 资源 | 目的 |
|---|---|
| `SKILL.md` | 触发范围、简短工作流程、图面内容规则、验证与真实能力边界 |
| `references/figure-grammar.md` | 电路、SoC、存储、数据流、AI 机制与定性/定量结果的选择条件 |

### 9.3 工作流程

1. **读输入并确认事实边界**：用户目标、技术对象、连接、必要参数、已有/拟新增状态；沿用本次已确认信息，不重复询问。
2. **生成内部 figure brief**：本图解释什么、面向谁、目标场所/栏宽、必须出现的内容、应进入 caption 的条件。brief 不自动进图面。
3. **选择图式**：拓扑、原理图、映射/时序、对比面板或混合结果图；复杂性超出尺寸容量时拆图。
4. **布局**：先主关系和连接，再位置/标签/局部展开，最后字体、线宽和颜色。
5. **内容检查**：所有显示的连接和数字都有依据；删除聊天残留；必要状态没有被删除。
6. **导出与查看**：可编辑 SVG/PPTX、出版 PDF、最终尺寸预览与灰度预览；照片等保留独立位图元素。
7. **交付**：母版、出版图、caption、来源/验证记录。说明 Office 实测与否、尚未满足的目标规范。

用户明确要求“只转换、不改变布局”时仍走保真转换，不强行加新设计。用户要求论文图时，默认不添加说明板；要求讲解图时，可增加必要的短注释，但也不自动复制整段聊天。

### 9.4 导出与验证能力的实施优先级

| 优先级 | 后续内容 | 为什么 |
|---|---|---|
| P0 | 图面内容筛选、物理尺寸、最小字号、caption 分离、领域图式 | 直接解决本轮四类反馈 |
| P1 | 端口/连接清晰、虚线、符号、自定义宽高、字体嵌入 PDF | 提高论文图的表达与交付质量 |
| P1 | 保留旧文字一致性与原生对象验证，补预览人工检查 | 保住可编辑交付的已有价值 |
| P2 | 图片面板白名单、定性结果裁剪一致性、混合图导出 | 使 skill 能可靠支持视觉论文/die shot；不能沿用“任何 media 都失败” |
| P2 | 语义分组、连接器绑定、上下标/数学文本增强 | 提高编辑体验；不应阻塞第一批纯结构图改进 |

定量图优先通过标准绘图库生成有数据来源的矢量图，不必强求每一个数据点在 PPT 中都可编辑；如用户明确需要原生图表，需要作为独立能力验证。结构图的原生可编辑承诺不能自动扩展成所有图类型都完全可编辑。

## 10. 后续对照试验与验收

### 10.1 对照的公平性

建议授权实施后先选三项：DDR 拓扑、LLC/SPM、一个模型机制图。每项统一技术事实、最终尺寸、语言和必须保留的关键内容，比较旧流程与新流程。

同时展示图注与图面，避免新方案把必要信息全部丢进隐藏文档后假装更简洁。若旧版通过拆图后也能改善，应如实记录，不把收益全部归因于配色或新 skill。

### 10.2 分开检查“正确”与“好看”

硬性通过条件建议：

- 无错误/虚构连接、信号方向、容量、参数或实验数字。
- 新增/未实现状态、必要前提和箭头语义没有被隐藏。
- 不出现没有用途的外围说明板、聊天式提醒和证据日志。
- 最终字号符合目标场所；无文本截断、非预期覆盖或难以分辨的交叉线。
- 色彩不是唯一语义，灰度仍可读。
- 承诺的可编辑对象真实存在；图片仅用于允许的独立面板；出版文件字体/尺寸受检。
- Office 未实测就明确报告，不以 SVG 预览替代 PPTX 外观验收。

设计比较建议由用户或目标读者回答：第一眼能否找到本图要说明的机制；能否追踪指定数据流；能否说出基线与改进差异；是否仍像通用演示模板。可以记录完成时间/错误次数和偏好，不使用虚构的客观“学术感 95 分”。

机器可以发现过小字号、越界、未声明图片、丢字、部分遮挡。机器不能仅凭路径几何判断所有相交线是否有电气连接，也不能证明技术事实正确或读者必然理解。视觉与语义复核仍然必要。
