## 2. 当前连接的准确落点

官方随附 [Cheshire 集成说明](../../docs/tg/integr.md) 定义外部 AXI/Reg 接口与类型生成；[架构说明](../../docs/um/arch.md) 说明 LLC 位于主存前，假设下游内存由它独占或具备相应一致性条件。对本版本再核 [cheshire_soc.sv](../../hw/cheshire_soc.sv)、[cheshire_pkg.sv](../../hw/cheshire_pkg.sv)、[typedef.svh](../../hw/include/cheshire/typedef.svh)：

- `gen_ext_axi_mst` 将外部 master 接入当前 `axi_in_req`，仍通过原系统互连；它不是新的 LLC 下游旁路。
- `gen_llc_atomics` 在 LLC 前实例化 `axi_riscv_atomics_structs`。`Cfg.LlcOutConnect=1 && LlcNotBypass=1` 时进入 LLC；仅关闭 `LlcNotBypass` 是整个 LLC 实例旁路，不是给某一类 NPU 流量新增支路。
- 控制面扩展经 `reg_ext_slv_req_o / reg_ext_slv_rsp_i`。当前生成 Reg 类型的数据 32 位、字节选通 4 位；设备自己的访问宽度和副作用还必须单独声明。
- DefaultCfg 是地址 48、数据 64、USER 2、发起者 ID 2 位的一个源码默认值；实际 profile/外围使能会改变端口数和派生 ID。`AxiSlvIdWidth = Cfg.AxiMstIdWidth + clog2(gen_axi_in(Cfg).num_in)`，LLC 输出再加 `Cfg.LlcNotBypass` 位。交付必须保存实际类型宽度，不能把任何旧板型的数值固定给供应商。
- 默认外存译码窗口为 `[0x80000000, 0x100000000)`，这是 2 GiB 窗口，不是已安装容量。`LlcOutRegionStart/End` 同时被外存路由和 CPU 可缓存/可执行区域生成消费。

### 官方描述与本地实现的差异

随附 LLC/Cheshire 文档中存在“通过 AXI cache control 绕过”的通用描述；本地 [axi_llc_config.sv](../../.bender/git/checkouts/axi_llc-5fb8850caad4fcfa/src/axi_llc_config.sv) 的 bypass 选择由地址规则与 `conf_regs_i.flushed` 决定。不能仅修改 AxCACHE 就承诺当前实例的选择性旁路。缩小 LLC 缓存地址范围还需重核 SoC 路由，否则 CPU 到新共享区可能变成译码错误。此项是版本适用性差异，不擅自修改 RTL 去追齐文档。

后续候选连接为：CPU及Ara普通内存访问→原系统互连64→原子适配→LLC→新增DDR前合流边界；NPU的256-bit DDR数据口绕过LLC，在该边界接入DDR。Ara若扩4 lanes，其单一128-bit AXI出口拟在128→64转换之前按物理地址分流，GB支路直达独立片上SRAM，普通支路继续原路径。ISP的独立端口与合流方式仍待预算。合流可由供应商多端口Controller承担，也可在必要时采用外部互连，模块和端口未定。这是用户需求引出的定制候选，非当前实现或官方完整参考方案；具体契约见§12。

## 3. 契约填写方法与所有权

每个 IP 建立一份记录：`IP名称/修订、接口版本、来源受控位置、提供者、核对者、状态、验证证据路径`。状态只能为“待输入/已约定未实现/源码已接入未验证/对应测试通过”；不能只填“支持”。数值没有资料时填“待输入”，禁止用下列算例替代供应商值。受限手册不复制进仓库，只记录获授权的接口摘要和受控位置。

| 记录 | 负责填写/核对 | 必须绑定的版本 |
|---|---|---|
| 新 IP 数据/控制接口 | I01/IP 方，E01 接入核对 | 顶层、寄存器定义、模型、驱动接口同一交付版本 |
| DDR Controller/PHY | 用户转交供应商，M01/P01 | Controller+PHY匹配修订、目标DRAM组织、初始化表与模型 |
| SoC 地址/ID/路由 | E01/M01 的同一时段协调者 | 固定 Cfg/profile、顶层、类型展开、地址与链接布局 |
| buffer 与运行软件 | S01/M01；OS输入由S01 | ABI、内存属性、驱动、设备描述、OS/裸机版本 |
| 约束/电气/测试 | P01/供应商/板级负责人 | 工艺、PAD、时钟复位、时序角、DFT交付 |
| 验证清单与结果 | V01 | 测试输入、配置、模型、日志、结果与未覆盖项 |

## 4. AXI 数据面：双方逐项填一致

方向以“新设备作为 AXI master，DDR 作为 subordinate”为参照。AW/AR/W 从 master 发出，B/R 从 subordinate 返回；READY 方向与对应 VALID 相反。LLC 出口在合流处也是一个 master。不能把从设备内部命名的 `slv` 方向直接复制给 SoC 顶层。

| 字段 | 必填内容及当前状态 | 验收责任/反例 |
|---|---|---|
| 地址、数据、ID、USER 位宽 | 双方位宽；设备最大可寻址位；USER逐位用途；**供应商/新IP待输入** | M01/E01 检查扩宽/缩窄前的合法范围；不能简单丢高位导致非法地址别名 |
| 地址语义 | SoC 物理字节地址或端口相对偏移；base/size/end；对齐与保留区 | M01/S01 测试首尾合法字节及两侧越界；区间右端不含 |
| Burst 子集 | FIXED/INCR/WRAP允许项、最大LEN、SIZE、非对齐、窄访问、4KiB边界 | V01按实际子集与转换层验证；LLC refill 的当前8拍INCR不代表所有透传请求只有8拍 |
| WSTRB | 每字节写掩码、零选通行为、窄写 lane 对应 | V01读改写比对未选中字节；不能用全字写替代字节写 |
| ID/顺序 | 每输入的在途数、每ID规则、响应路由、是否需 remap/serialize | E01/M01派生扩展ID；同ID同方向保持序，跨ID不依赖偶然返回顺序 |
| AW/W 配合 | 独立握手、写数据路由、允许接受顺序与缓冲上限 | V01让AW/W分别停顿，确认每个W归属正确；AXI4没有WID可补救错误路由 |
| 背压/服务 | 各通道允许等待、最长不能服务间隔来源、内部缓冲压力传播 | VALID等待时payload保持；“平均带宽足够”不代替有期限流的服务保证 |
| 响应/错误 | R/B响应、R拍数/RLAST、错误归属、sticky状态/IRQ | 每个被接受事务按契约结束；错误不伪装成功或永远悬挂 |
| 属性/原子 | AxCACHE/PROT/QOS/LOCK/ATOP实际支持与过滤点 | 下节原子边界；不因接口叫AXI4就默认支持AXI5 ATOP |
| 复位/时钟 | 各域频率范围、CDC位置、有效极性、放行/排空规则 | P01/V01验证两侧独立复位与在途事务；禁止只复位一端并立即复用buffer |

来源：本地 [axi_xbar 官方随附说明](../../.bender/git/checkouts/axi-ecdc900686449c15/doc/axi_xbar.md) 对 ID、译码、顺序与背压的定义；[axi_llc_ax_master.sv](../../.bender/git/checkouts/axi_llc-5fb8850caad4fcfa/src/eviction_refill/axi_llc_ax_master.sv) 的 `NumBlocks` 整行事务。上述表是需要落实的契约，未填写的能力不宣称已有实现。

## 5. 控制寄存器、中断与任务身份

主线任务不是“写一个 START 后等 DONE”，而是同一任务身份从配置到结果的完整交接。每类 IP 至少填写以下语义，不在本轮分配实际寄存器偏移：

| 操作 | 需由 IP 方给出的字段/行为 | 集成验收 |
|---|---|---|
| 识别与初始化 | IP版本、能力、合法访问宽度、复位值、只读/读清/W1C等属性 | 软件能确认预期修订，保留位遵守规定；读操作不意外触发任务 |
| 准备参数 | buffer设备地址、长度单位、stride、格式/量化、上限与对齐 | 完整参数是否原子生效；64位参数在32位Reg上如何更新避免半新半旧 |
| 提交 | doorbell/队列tail/START语义、重复写、busy时行为 | 一次合法提交恰好对应一个任务；返回“接收”与完成分开 |
| 执行进度 | 状态、已处理字节/行、所有权、请求在途计数 | 不把帧末标记或命令出队当作全部AXI写已完成 |
| 完成与错误 | task token/epoch、最终长度、错误码、结果有效范围 | 任务身份与结果可追踪；错误码由谁读/清，清除副作用明确 |
| IRQ | 源条件、脉冲/电平、域、屏蔽、合并、清源与控制器complete次序 | 事件既不丢失也不重复提交；PLIC complete不能代替设备清源 |
| 停止/取消/复位 | 停止接受、排空、终止或作废、旧响应/IRQ处理 | 超时不自动转移所有权，确认不会迟到写旧buffer后才释放 |

初版可建议用 token 加 epoch 区分运行批次，但其位宽、回绕条件、寄存器偏移与驱动 API 都待 IP 契约确定，不能写成现有功能。Reg 实验的读写/副作用教学复用 [实验F](../learning/labs.html#lab-f)，真实设备语义仍需厂商/自研 IP 方交付。

## 6. 可见性、原子与旁路必须共同评审

### 6.1 普通帧缓冲

建议第一版使用隔离的数据区、明确生产者/消费者和全路径不缓存或已经验证的维护协议。这里的“不缓存”是每一层路径的实际属性：CPU L1、Ara路径、LLC缓存地址规则、DDR前互连都要检查；`volatile`、一条fence、Linux PTE或DMA API名字不能单独建立它。避免同一物理页有混用的缓存/非缓存别名，缓冲边界按实际cache line隔离，不与CPU锁或普通对象共享可写回行。

CPU→设备：CPU填数据→落实所需cache clean/排空与排序→达到共享可见点→发布描述符/doorbell→设备读取。设备→CPU/Ara：设备写数据→按控制器/互连契约完成必要响应与可见性→发布完成身份→消费者执行所需同步/invalidate→读取及独立校验。B响应是AXI事务结束的依据之一，不自动等于CPU缓存已最新或所有跨master访问均已排序。

Linux使用用户虚拟地址、内核指针、DMA地址的转换与生命周期；裸机也必须检查设备可达性和物理区。OS原理见 [设备地址](../learning/virtual-memory.html#device-addresses)。本轮不分配DMA区基址、大小或新缓存规则。

### 6.2 AMO 与 LR/SC 的观察范围

官方 [axi_riscv_atomics README](../../.bender/git/checkouts/axi_riscv_atomics-40ad8d2d0e0daa8b/README.md) 要求其下游对相关存储拥有独占或一致性保障。当前适配器在 LLC 上游，处理 AMO/LRSC 后下游无需直接实现这些事务；本地 `axi_riscv_lrsc.sv` 清下游 lock，AMO模块清相应ATOP。普通AXI4 DDR可以承接转换后的访问，但新旁路writer改变了“谁能写同一位置”的条件。

若CPU对共享字做LR、设备旁路写该字、CPU再SC，上游reservation观察器未必看到设备写，不能保证期望的共享域语义。设备不发AMO也不能消除这个问题。只把原子适配器移到LLC后，会留下LLC不支持上游原子、CPU/LLC命中及旧副本问题；增加第二个原子单元同样不是全系统一致性方案。

契约必须选一项并给证据：首版禁止CPU/设备并发原子共享同一控制数据，利用隔离buffer与MMIO通知；或为确需共享的控制域单独设计所有相关访问的统一可观察路径/一致性机制。后者是待架构评审的工程任务。CPU在不受旁路影响的私有区域的原子访问，不因新增旁路就一概被判无效。

## 8. 一帧的可填写实例

本例与 [accelerators#buffer-lifetime](../learning/accelerators.html#buffer-lifetime) 使用相同假设，**不是传感器/ISP/NPU选型**：1920×1080，每像素2字节，60帧/秒，无stride填充时每行3840字节、每帧4,147,200字节，两帧8,294,400字节。单向平均有效载荷248,832,000 B/s，ISP写一次加NPU读一次至少497,664,000 B/s；NPU输出/权重/中间张量/CPU读取另加。

### 8.1 逐缓冲填写生命周期

| 步骤 | 所有者/数据动作 | 必填契约与观察 |
|---|---|---|
| 分配帧F | CPU/驱动准备设备可达缓冲，设置容量与格式 | 物理/DMA地址来源、stride、边界、缓存属性、task身份；CPU准备完才交出 |
| 采集/ISP生产 | LVDS/ISP接收并写F | 不能背压时最大连续输入率；帧末不代表AXI写完；错误/实际长度记录 |
| ISP完成 | ISP停止修改F，发布完成身份 | 必要写响应及结果可见点；通知顺序、迟到事务处理 |
| NPU消费 | 获得F读所有权，按已声明布局读取 | 没有未完成写；参数与帧版本一致；多个读者的释放计数由谁维护 |
| Ara/CPU后处理 | 按需消费NPU结果，不并发改仍在用的F | 地址翻译与缓存交接、算子分工/数值参考；当前未实现NPU/Ara调度器 |
| 归还F | 最后消费者结束后交回分配方 | 所有读写已终止，不仅“软件停止等待”；下一epoch才允许覆盖 |

双缓冲允许F0/F1不同阶段重叠，不消除每块buffer的依赖；若消费者持续慢于生产者，两块buffer仍会耗尽。队列满时背压、降帧或丢弃谁，应由产品/I01明确定义，不能交给驱动静默覆盖。

### 8.2 服务间隔与容量不能混为一个带宽数

按平均速率计算，100μs无服务需吸收 `ceil(248832000×0.0001)=24884` 字节，只是下界。最终FIFO容量应覆盖最大连续到达率×最长服务间隔，另加已在途字节、跨域/调度粒度及裕量。需要I01/传感器方给行间/帧间组织与峰值，M01/DDR方给仲裁/刷新条件下的服务保证；没有这两个输入不能冻结FIFO深度。

DDR可用带宽还取决于读写混合、地址模式、行冲突、刷新和其他master，理论峰值不作为实测值。一帧延迟按输入到可消费结果测，稳定吞吐按正确完成帧/时间测，方法与 [measurement](../learning/measurement.html#boundaries) 一致；本轮只核算式，不填写性能结果。

## 12. 独立Global Buffer与DDR需求更新

更新日期2026-10-09。以下区分用户确认、当前源码事实、设计候选、待输入与验收；优先于历史文档中“CPU/Ara均走LLC”的概括，但不改原固定ASIC提取基线。

### 12.1 用户已确认的应用场景

NPU与Ara协同完成模型推理。近期主Xbar维持64-bit，后续根据性能再决定是否128-bit；选择64-bit是控制适配和验证工作量，不是要求缓存容量永远不增长。NPU计划通过256-bit AXI数据通路访问DDR并绕过LLC。GB已明确为独立片上SRAM，NPU搬运DDR数据，Ara另有通路访问GB并共享中间结果。模型、算子分工和实际性能目标待输入。

用户尚未冻结Ara4-lane实施、VLEN、GB组织、DDR速率/容量/通道数或厂商端口组合。既有1333档、DQ64/单通道/2 GiB和2133性能档保留为历史申请或比较候选，不由本次讨论升级为采购配置。

### 12.2 当前源码事实与候选数据流

本次定向复核：
- `hw/cheshire_pkg.sv` 默认DW64/AW48、Ara2/2048；当前VCU118加源脚本仍为NR_LANES=2、VLEN=2048。
- `hw/cheshire_soc.sv:606` 定义 `AraDataWideWidth=32*Cfg.AraNrLanes`；:818接入Ara，:841起接失效过滤器，:861起转换到系统宽度，:889接主Xbar。现有连接没有本次GB分流。
- 同文件 `gen_llc_atomics` 位于LLC之前；既有LLC外存出口是DDR合流候选的一路输入。
- 本地 `ara-2c7b103275a16c87/config/4_lanes.mk` 默认4/4096，4/2048只是另一个讨论候选，不能只选预设就声称VLEN不变。

- `hw/cheshire_idma_wrap.sv` 的控制Regbus随系统位宽，`idma_reg64_2d_reg_top.sv` 固定DW32；既有控制接口问题在DW64下仍开放。NPU自有搬运引擎与Cheshire iDMA必须分别命名，尚未选择。
- `ara-2c7b103275a16c87/hardware/src/vlsu/vstu.sv:425` 仍有B通道错误不能处理的TODO；收到B而报告store完成不等于成功可靠上报。

候选连接如下，箭头表示数据通路，不表示已经接线：

```text
CPU普通主存 ─────────────────────────→ 主Xbar64 → 原子适配 → LLC ─┐
Ara4候选：单VLSU/AXI128 → 现有失效过滤 → 按物理地址分流              │
                                     ├ 普通：128→64 → 主Xbar64 ──┘
                                     └ GB：128 → 适配/CDC/仲裁 ↔ 独立GB SRAM
NPU DDR主口256 ↔ 待定DDR合流边界 ↔ Controller/PHY ↔ DDR
                     ↑ LLC外存出口亦接入此处
NPU计算/搬运接口 ↔ GB（接口宽度、bank、端口及并行度待定）
```

分流置于现有filter之后、宽度转换之前是保守设计建议，保留普通路径既有行为；若改置于filter之前，需要另证缓存属性与别名安全。GB支路不经过主Xbar和LLC，才可能避开其64-bit限制。先经过64-bit再扩宽不能创造持续带宽。Ara仍共享同一VLSU/AXI出口、队列和每方向吞吐，不能把普通支路与GB支路当作两个独立向量访存引擎。

NPU256是发起端需求，DDR Controller的实际端口宽度、数量、时钟和转换位置待供应商manifest与预算确认。优先利用厂商已有混合位宽/转换能力；若无法满足才评估现有适配模块。它也不证明GB有256-bit原生多端口SRAM。CPU是否需直接访问GB待确认，不能由Ara新支路推断CPU已可访问。

### 12.3 三类流量及最小预算方法

以每帧、每次推理或每token为统一工作单位，按阶段分别记录读/写有效字节、时间窗口、端点、重复次数、是否可重叠，避免同一搬运跨两个接口时重复计入DDR。

| 账本 | 计入内容 | 不应计入/边界 |
|---|---|---|
| CPU/Ara普通路径DDR流量 | LLC miss/refill、eviction/writeback及实际到达DDR的旁路访问 | LLC命中与GB内部访问不计；不能把CPU/Ara指令请求字节直接当DDR字节 |
| NPU/搬运器DDR流量 | DDR→GB输入/权重/KV/激活，GB→DDR输出/回写，溢出及重复tiling搬运 | 一次DDR→GB在DDR账上是一次读；GB落盘为SRAM写，不能再算一次DDR写 |
| GB内部流量 | 搬运写入/读出GB、NPU计算访问、Ara读写、中间结果交接 | GB驻留复用不重复计DDR；仍消耗bank/端口服务与能量 |

对单位工作，`D_DDR = D_CPU_Ara + D_NPU搬运 + D_ISP及其他`，各项均为实际DDR读写有效字节之和；`B_avg = D_DDR × 单位工作数/秒`。同时单列每阶段的突发字节和期限，以`D_stage / 可服务时间窗口`检查局部需求。多个源只在确实重叠的窗口叠加，不能用全程平均掩盖短时饥饿。

DDR共享理论峰值为`DQ/8 × MT/s × 10^6 B/s`；有效能力需用相同流量下的效率、刷新、读写切换、地址行冲突和仲裁验证。AXI每方向理论上限为`W/8 × f`，但路径瓶颈、在途数和背压可能降低持续供数。效率、余量和各口频率当前待输入，不把历史60%–75%情景当保证。

GB带宽按bank和物理端口建服务预算：同一周期/时间窗内，NPU计算、搬运和Ara竞争同一bank时，需求不得超过实际可提供读写服务。128-bit与256-bit接口标称带宽不能直接相加当作SRAM能力；单双口语义、读写能否并行、冲突、CDC和最小服务保证需共同填写。双缓冲/tiling能帮助重叠，是否成立取决于容量、bank映射、所有权和调度。
