## 2. 对上一轮结论的修订

1. **外设与 Ara 已有成果进入保留和独立复审阶段。** 上轮实际修改集中于现有 18–26 章和两页诊断；尚无新的读者试读或目标运行证据。新任务不能因为总 Prompt 再次列出这些主题，就覆盖已有文本和用户图稿。
2. **07 改为“可立即编写限定范围”。** 范围是完整的 RTOS/Linux 教学主线、版本明确的官方参考实例和条件化实验说明。不是“只写需求清单”，也不是“立即完成本平台 OS 移植”。OS 类型、版本、BSP、内存与运行环境影响工程落地，不阻止教授调度、上下文、虚拟内存、驱动、系统启动。
3. **CVA6 缩小主线深度，软件与 ASIC 增加机制深度。** 不要求所有章节同样详细，也不以统一模板拉长篇幅。CPU 用法服务软件，Ara 内部服务向量执行，SRAM 消费者服务 ASIC 适配。

5. **“操作系统需求未决”需要拆开。** 教学和论文实验需要 OS 已确认；具体平台方案、论文指标、OS 版本和向量任务切换策略未决。RTOS/Linux 仍不是 E01 裸机 ASIC 提取的强制前置。

## 5. 两个重点增补包怎样做到“系统”而不过度展开

### 5.1 RTOS/Linux：先让两个任务运行，再让一个用户程序运行

这是教学必做项，不再放入“以后也许需要 OS”的附录。建议按四个连续任务写：

1. **任务 A→B→A。** 从普通函数调用已有的栈/ABI 出发，区别同步异常和异步中断；解释硬件保存什么、软件还要保存什么。画两份任务栈、保存区、当前/就绪/阻塞状态，按 yield、定时器、设备事件走完切换与返回。随后讲临界区、信号量/队列、互斥和优先级反转。用一个定时采样/工作任务/日志输出例子解释“为何需要调度”，不要仅列 RTOS 服务名。
2. **同一指针在什么地址空间有效。** 从已有链接地址、物理存储和缓存属性，推到保护、特权、页表、虚拟地址和进程空间；先讲正常翻译与授权访问，再引出设备缓冲为何需要专门契约。不要把 CPU 虚拟地址直接交给一个假定可用的 DMA。
3. **从固件到第一个用户进程。** 区分工具链、平台固件、可选加载阶段、硬件描述、内核、根文件系统、库和用户程序；描述镜像/参数交接、控制台、内存/定时/中断建立、首个用户进程。具体启动组合需基于选定官方版本说明适用条件，不能默认某条链已在本地运行。
4. **同一设备在裸机、RTOS、Linux 中被怎样使用。** 用已有 UART 输出/事件作为对照：调用入口、阻塞/唤醒、ISR 与线程、资源所有权、正常关闭。先用户程序使用已有设备接口，再解释平台驱动/设备描述；DTS 不等于驱动，设备文件也不等于直接访问 MMIO。新 IP 驱动仅作为条件化设计例。

每个机制先独立解释，再选版本明确的官方实现作参考实例，最后对照本地具备/缺失的部分。此处不指定 RTOS 产品或 Linux 版本；后续文档任务可以为教学挑选官方参考，须说明并非产品选型，也不能自动下载/升级工程依赖。

FP/RVV 上下文只在基本调度清楚后引入：架构可见状态、保存范围、具体 OS port 的支持、进入切换时仍在途的操作。不能用“CPU 支持 V”替代“OS 能安全抢占向量任务”。本地没有 port 时明确缺层，不编造调度接口或成功日志。

**完成标准：**读者能画 A→B→A 的状态与栈变化，区分系统调用/异常/中断，指出一次 Linux 启动各阶段的输入输出，并解释为什么用户 buffer 不能未经处理交给设备。教材章节可以完整满足这些解释目标，真实移植仍需另外验收。

### 教学验收记录不能只填“通过”

每章提交一条可复述的正常过程，列出前置、输入、状态变化、输出、完成条件、正确性判断；再附 2–4 道任务题和答案所在锚点。例如：

- 给出数组符号和 ELF 段，解释谁把数据放到哪里、何时能调用 main、UART 输出为什么发生。
- 任务 A 等待设备后切到 B，再由事件唤醒 A：哪些状态由硬件保存，哪些由 port 保存，哪个栈继续使用。
- Linux 用户程序交出 buffer：指出哪个边界需要地址、访问权和所有权转换，哪些缓存条件仍未证实。
- 当前 SRAM 消费者假定一个读延迟，候选宏增加一拍：指出错误会发生在哪里，以及要验证的改动范围，不能只说“加寄存器”。
- 一帧计算算子更快却端到端更慢：列出搬运、同步、驱动、调度和缓存因素，并说明怎样分别计量。

作者自查、独立 Agent 复审和真实读者试读分别记录；前两项不能替代第三项，也不替代目标运行。
