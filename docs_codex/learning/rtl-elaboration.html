H01 · 参数化 RTL 与展开

源码定义、参数传递、实例展开与综合实现的阶段关系。

RTL 预处理、编译与展开参数化数组、数量与位宽Cfg.Uart 的参数传递与结构展开配置来源与展开结果验证源码阅读与验证练习源码依据本章自测
学习目标

追踪一个 Cfg 字段到 generate 分支，并区分配置生成、预处理、展开与综合。

前置：能阅读 module、assign 与 always 块。证据：2026-09-23，源码基准 ae2b69fe0；原理推导与源码静态确认，动态证据另见硬件实验与证据。

RTL 预处理、编译与展开

源码文件提供模块定义；只有实例化并满足展开条件，才在层级中产生实例。预处理器先处理 `ifdef，编译器解析包/类型/模块，展开器确定参数并展开 generate。综合器随后可传播常量、删除无用逻辑并映射单元。模拟器看到的层级不是最终芯片面积报告。

构造本工程例子读法
package 与 struct packedcheshire_cfg_t / DefaultCfg一组常量被封装传给顶层；不是一组软件可写寄存器
常量函数gen_axi_in(Cfg)展开时计算索引和计数，不是综合出一颗处理器运行函数
parameter typeaxi_ext_llc_req_t传入已打包的通道类型；字段宽度必须和数值参数一致
generate if/forgen_uart / gen_cva6_cores选择实例、复制实例；不是每个周期都重新选择的运行时分支
普通 always_comb ifSPM 地址重映射地址随事务改变，通常形成组合选择逻辑
生成的寄存器包PLIC/CLINT已有生成物带固定尺寸，改 NumCores 不会自动重生成

参数化数组、数量与位宽

logic [N-1:0] 是 N 位，req_t [N-1:0] 是 N 份打包请求；数组每份又含 AW/W/AR 等字段。$clog2(N) 表示编码 N 个来源所需位数，但 N=1 时为零，部分接口用 idx_width/iomsb 避免零宽声明。占位端口宽度不等于该功能已经启用。

宏 CHESHIRE_TYPEDEF_AXI_CT 统一建立请求/响应类型。切换 AXI 数据宽度后，WSTRB、外部 wrapper 类型、DMA 和 LLC 存储容量都要一起审查；模块可能编译通过，却在端口转换处截断字段。

Cfg.Uart 的参数传递与结构展开

// 源码节选：hw/cheshire_soc.sv
if (Cfg.Uart) begin : gen_uart
  reg_uart_wrap #(...) i_uart (...);
end else begin : gen_no_uart
  assign uart_tx_o = 0;
  assign intr.intn.uart = 0;
end

同一字段还被 gen_reg_out() 消费，用于加入 UART 地址规则和 Reg 目标。只看实例分支会漏掉地址图；只看地址图又会漏掉输出绑零。关闭后的 TX=0 是当前源码行为，不能按常见串口空闲高电平自行想象成 1。

  1. 最终源码清单：唯一 profile、decoder 实现、宏定义。

本章自测

把 Cfg.Uart 写成运行时 MMIO 会生成 UART 吗？

不会。Cfg 是硬件参数，运行时只能操作已存在的电路。

module 的默认 Cfg=0 是否推荐使用？

不是。许多参数类型/零值只是占位，必须由正确的上层实例传入。

综合删除了模块，是否说明源码没有它？

不是。实例可能因常量或无可观测输出而被优化；应分别保留展开与综合证据。
