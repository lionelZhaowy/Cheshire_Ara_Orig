28.1 LVDS、ISP 与 NPU 的接口约定

LVDS 描述低压差分电气传输，图像接入还需传感器的 lane 数、位时钟、字对齐、帧行同步和像素格式。ISP 要声明输入输出格式、边界处理、帧缓冲与背压；NPU 要声明 tensor 布局、精度、任务描述符、DMA、完成和错误。控制寄存器、数据口、中断以及复位恢复由同一任务契约约束。

图像吞吐先用宽×高×每像素字节×帧率估算，再乘上实际读写遍数。例如 ISP 写一遍、NPU 再读一遍已经是两次存储流量，乒乓缓冲还增加容量。持续输入不能无限背压时，需要定义溢出、丢帧及恢复策略，和 VGA 的有期限消费形成对应。

28.2 AXI4 DDR 与设备旁路

用户已确认供应商可提供 AXI4 DDR，旧 AXI3 桥规划不再是必选项。接口契约需列地址/数据/ID/USER 宽、容量映射、burst 与窄访问、最大在途、顺序、错误响应、时钟复位及初始化完成。现有 FPGA 的 64→512 位、ID 适配和 MIG UI CDC 是板级实现，后续应按供应商 AXI 接口重新核对。

用户要求 NPU/ISP 数据绕过 LLC，减少其分配和替换压力。可在 DDR 上游增加互连，把 CPU/Ara 的 LLC 出口与设备数据口汇合；这仍共享 DDR 带宽。CPU/设备共享区域要统一缓存属性、所有权和通知协议，旁路写还需考虑上游 AMO/LRSC 的观察范围。把原子单元移位置并不会自动生成全系统一致性。

28.3 NPU / ISP 旁路 LLC 的系统接入规划

用户规划让 NPU/ISP 数据流绕过 LLC，并与 LLC 下游在 DDR 前合流。新增一层互连需要合并 ID 空间、保存 W 路由和读写顺序、限制各端在途量，并定义背压与带宽保障。当前 SoC 的外部 master 入口通常仍进入原系统拓扑，接到该入口不自动等于实现 DDR 旁路。

28.3.1 逐 IP 的数据与控制交付

模块数据与控制接口接入前需要的规格
NPUAXI 主端搬张量；Reg/AXI-Lite 控制；状态/IRQ；可选本地 SRAM算子、数据类型、布局、地址位宽、描述符/队列、错误与取消、对齐、支持的 burst、量化与数值规则
ISP流输入/输出或 DDR 缓冲；控制寄存器像素格式/位深、行/帧边界、stride、裁剪、背压或丢帧规则、最大突发与缓冲量
LVDS 接收PAD/PHY → 解串 → 字/行/帧恢复 → CDC FIFO电气与速率、lane 数、时钟方式、训练、码字对齐、帧协议；LVDS 本身不规定图像包格式
DDR AXI4 IP共享从端 + 控制面 + PHY见DDR 接口表；端口容量和响应约束成为上游设计输入

28.3.2 分阶段验收

分阶段验收：先用独立内存模型验证设备描述符和结果；再接 Reg/IRQ、检查只提交一次及错误传播；然后接共享 SPM 或预留 DDR 区、执行所有权交接；最后增加多主竞争、长背压、复位中断与错误注入。每阶段记录配置、事务数/字节数、数值比对和超时恢复，不能只看 DONE。

描述符控制区、完成邮箱和数据区应按用途分配，但本轮不分配生产地址。驱动必须知道设备可见地址、长度上限、layout/quant 版本、完成 token 与 epoch；缓存和所有权协议见共享数据章。Ara/NPU 任务划分与完整教学案例见模型协作章，拓扑方案不能替代算子和性能实测。

28.4 每个 IP 共同需要的集成交付

28.4.1 寄存器与软件

NPU/ISP 应交付寄存器偏移、允许访问宽度、RO/RW/W1C、复位值、保留位、启动和忙状态的合法操作；LVDS 接收应定义训练/字对齐/帧状态，DDR 应定义初始化与故障状态。基址、IRQ 编号尚待本工程分配。软件提供完整 init→submit→wait/error→stop/recover 流程和实际结果校验，不能仅给一张宏列表。

28.4.2 时钟、复位、中断与带宽

IP时钟/复位与事件数据边界与验收
LVDS传感器源同步域→解串/CDC；失锁、错码、丢帧通知lane/字/帧同步模式，输入不接受背压时的溢出策略
ISP行/帧状态与系统域交接；复位后从明确帧边界重启输入输出像素格式、stride、边缘算法、每帧读写量和黄金图像
NPU任务队列、完成/错误/超时；复位与取消不混淆旧 token算子、精度、布局、实际长度、最大在途量与独立数值参考
DDR控制器/PHY 时钟、训练与校准、失锁和 ECC 事件容量/地址映射、AXI 限制、刷新压力、错误模型与供应商约束

设备是否有内部 SRAM、是否可保持状态、哪一类错误可恢复，都待实际 IP 规格确认。共同的软件共享规则集中在所有权与元数据契约。

28.5 用数据率反推 FIFO 与 DDR 压力

只作算例：1920×1080、每像素 2 字节、60 帧/秒，单向有效载荷为 248,832,000 B/s；一帧约 3.96 MiB。写一次再读一次至少 497,664,000 B/s，不含 blanking、padding、协议和中间结果。若输入不能背压，100 μs 的下游停顿要吸收至少 24,884 字节有效数据，还需裕量。设计 FIFO 深度时应采用最大连续到达率和最坏停顿，而不是只用平均帧率。

ISP 若产生多份中间图、NPU 若多次读权重，上述流量继续增加。先画每块数据的写读次数和生存期，再决定行缓冲、tile、双缓冲或整帧 DDR。丢帧后要在明确帧边界重新对齐，不能将残留半帧当作新任务输入。
