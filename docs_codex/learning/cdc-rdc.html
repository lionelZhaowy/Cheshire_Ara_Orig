35 · 跨时钟与复位域的事务交接

跨域信号同步、事务传输与生命周期协调。

本章任务

为一个配置命令、一段连续数据和一次正常域复位分别选择跨域交接方式。前置：AXI 握手、真实时钟域、复位与就绪。本章是机制与本地单元契约，未完成目标 CDC/RDC 签核。

35.1 异步采样与跨域命令传递

CPU 所在系统域要把“采用新分频值”交给另一个时钟域。两个时钟边沿没有固定关系时，接收寄存器可能在输入变化附近采样，输出需要额外时间才稳定，这就是亚稳态问题。同步寄存器链给它更多稳定时间；所需级数、频率和可靠性指标由单元及时序条件决定。但“最终能采到稳定的位”还没回答命令是否被收到、多个配置位是否属于同一份值。

若发送端只拉高一个快时钟周期，整个脉冲可能落在接收域两个采样边沿之间。加两级寄存器仍可能看不到它。若把一个二进制计数值的每一位分别同步，各位可能在不同拍到达，得到从未发送过的组合。先说明传递对象，才有办法选择跨域结构。

35.2 多位配置的保持与两相握手

对低吞吐配置命令，可由源端锁存完整数据，再改变一个请求状态；接收端同步请求，发现新请求后在约定的稳定窗口取得数据，交给本域逻辑。对方完成接收后改变应答状态，源端同步应答后才允许覆盖配置。两相握手用状态翻转区分相邻事务，不要求发送一个恰好被看见的窄脉冲。

本地 cdc_2phase 正是这种入口：源端只有在 src_valid_i && src_ready_o 时接受一笔数据；它把数据保存在源域并翻转请求。目标的 dst_valid_o && dst_ready_i 是目标接收事件，随后应答返回。源端提交完成、目标收到命令、目标硬件完成配置，是三个不同时间点；若软件需要第三个状态，还须由设备协议返回完成确认。

数据总线并非“每位都装两级寄存器”。它依靠保持数据与控制握手形成稳定窗口，物理实现还要满足该单元明示的异步数据/请求/应答路径延迟约束。只设 false path 让报告安静，不能建立这个窗口。

35.3 不同信号类型的跨域传递方式

传递对象正常交接方法及原因必须约定的条件
长期稳定的单 bit 状态同步链让接收域得到稳定电平允许延迟；状态保持足够长；同步输出再扇出
一次事件握手或带事件记账的结构，保证每次事件有身份源端能否等待、事件最短间隔；单纯 toggle 若连续翻转太快也会漏事件
多位配置锁存整组数据，经控制握手交接一次快照应答前不能覆盖；物理数据路径满足稳定窗口
持续 ready/valid 数据流异步 FIFO 在源端写、目标端读，用同步后的指针判断空间吞吐与突发决定深度；两端遵守满/空及复位协议
AXI 事务协议专用 CDC 在五通道各传递 payload 与握手，维护原 AXI 约束AW/W/B 与 AR/R 的关联、在途计数、背压及两侧复位；不能只同步 VALID

本地 cdc_fifo_gray 把读写指针变成 Gray 编码后同步。一次指针推进只改变一位，降低采到不一致多位指针的可能；数据先存入 FIFO，等可见的写指针传到读域后才读取。同步延迟使满/空判断偏保守，是安全地晚一点开放，不是丢数据。Gray 位的物理传播仍需约束，否则相邻更新可能在接收端重叠；编码不能代替布局后的时序条件。

35.4 当前 DDR wrapper 的 AXI 跨域路径

本地 dram_wrapper_xilinx 先适配 AXI 数据宽度和 ID，再在 cfg.EnCdc 分支实例化 i_axi_cdc_mig：源端采用 SoC 时钟/复位，目标端采用 DDR UI 时钟与对应复位。由此可把一笔写连续读成：系统侧接受 AW/W → 跨域结构保存 → DDR UI 域接受 → B 经返回通道跨回 → 系统主设备完成这一笔写。

CDC 接受数据只说明有空间保存，不能作为 DDR 已完成写入的证明。系统若要正常停止 DDR 支路，需要同时停止新增事务并观察已有响应全部返回；空的某一个 FIFO 不能代表五通道和控制器都无在途。DDR 章继续解释训练和可访问条件。

35.5 跨域接口的复位协调机制

复位会清掉握手的历史。假设请求/应答原来都为 1、表示空闲，只把源端复位成 0，目标端仍看到旧应答状态；再次运行时，0 与 1 的差异可能被解释为一笔新事务。FIFO 只清一边指针也会破坏双方对哪些位置有效的共识。因此正常复位必须让两端重新建立同一空闲状态。

当前随附 cdc_2phase 和 cdc_fifo_gray 的说明要求上电复位同时异步断言、分别在各自时钟域同步释放；普通版本不能直接当成支持任意单侧 warm reset 的接口。库另有 clearable 单元，但其说明也要求遵守隔离/清除握手，并指出清除期间撤销 valid 可能不适合更高层协议。选用它仍需处理已被 AXI 另一端接受的事务，不能把“可清 FIFO”写成“可取消内存写”。

正常域停用可以按“停止接收新请求 → 两端确认排空 → 按单元协议复位或清除 → 在有效时钟下各自释放 → 确认新空闲状态 → 重新开放”理解。若有一侧时钟会停止，控制器须在停钟前拿到需要该时钟才能产生的确认。涉及未能排空的异常恢复，转到系统调试入口，不能混进正常停用步骤假定成功。

35.6 CDC/RDC 约束与验收范围

CDC 检查要识别真实源时钟、目标时钟、同步器、握手数据保持与组合扇出；RDC 检查还要识别“同一时钟、不同复位”的路径，因为一侧异步复位也会在另一侧采样窗口内改变数据。复位同步释放并不自动处理另一域仍运行时的异步断言。

本章读者应能在上述 DDR 路径标出两端时钟/复位、五通道、正常 drain 完成条件，并为多位配置选择握手而非逐位同步。工程验收则需实际域表、约束、结构检查与协议断言/动态场景：改变相位与速率、施加背压、分别安排合法复位。有限仿真不会给出亚稳态平均失效时间；静态规则通过也不会证明 AXI 没有被静默丢弃。

依据当前本地 cdc_2phase 契约、Gray FIFO 契约与约束、clearable 的高层协议限制及本地 DDR wrapper。这些是源码确认，不是本轮 CDC/RDC 工具结果。

为什么把 CDC 的所有路径设为 false path 仍不够？

同步/握手要在电路中实现；多位数据和 Gray 指针还有具体最大传播或相对到达约束。时序例外只改变分析，既不会锁存快照，也不会替两端排空事务。
