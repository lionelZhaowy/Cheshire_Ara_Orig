学完能做什么

解释字符如何进入发送移位器；配置 GPIO 输出而不误改相邻引脚；验证 GPIO→PLIC→CPU 的软件链路。前置：第 10 章寄存器语义。场景：printf 没输出，或者 GPIO 中断持续进入。

UART：一笔 THR 写并不等于引脚已经发完

UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）没有随数据传输的时钟，收发两端约定波特率和帧格式。本项目 reg_uart_wrap 先把 Reg32 转 APB，再将地址 PADDR[4:2] 送入 apb_uart，所以寄存器每 4 字节一个槽。别按 PC 上常见的连续字节端口写地址。

基址 0x03002000 + 偏移语义驱动动作与硬件结果
0x00DLAB=0：读 RBR / 写 THR；DLAB=1：DLL读取 RX FIFO / 写入 TX FIFO；或改 divisor 低 8 位
0x04DLAB=0：IER；DLAB=1：DLM中断使能；或 divisor 高 8 位
0x08读 IIR / 写 FCR查中断原因 / FIFO 控制；不能用读回 FCR 的方式验证写入
0x0cLCR；bit7 DLAB0x80 打开 divisor 窗口，0x03 恢复 8N1（8数据位、无校验、1停止位）
0x10MCR原初始化写 0x20；须同时确认 CTS/RTS 接法
0x14LSRbit0 接收可读；bit5 THR empty；bit6 transmitter empty
0x18MSRmodem/流控状态；当前基础示例不用它验收数据内容

uart_init 的次序：关闭 IER → LCR.DLAB=1 → 写 DLL/DLM → LCR=3 → FCR=0xC7 → MCR=0x20。整数除数 div=f_core/(16×baud)，实际波特率 f_core/(16×div)。例如 50 MHz、115200，div=27，实际约115740.7，偏差约+0.47%；这只是算术示例，能否容忍要看两端采样实现，不能保证任意偏差都成功。

// sw/lib/dif/uart.c 中发送逻辑的含义，省略封装
while (!(LSR & (1u << 5))) { /* 等 THR 可接收 */ }
THR = byte;
// 返回后移位器仍可能在发最后一个字符
// uart_write_flush 等 THR 和移位器均空，再结束程序

完整 printf 路径是 printf.c 格式化 → _putchar → uart_write → THR → TX FIFO → uart_transmitter → tx 引脚 → UART VIP 解码。这里 TX/RX FIFOs 在 RTL 用 slib_fifo（地址尺寸参数 6）实例化，运行中还受 FCR/FIFO 模式约束。接收端是采样器/接收 FSM → RX FIFO → RBR。UART 中断汇总到 PLIC source 1；中断服务需按 IIR 指示处理 FIFO/线路原因，而不是往任意状态位写 1。

无 UART 输出的有序排查

  1. PC 是否进入 main？是否卡在 RTC 测频？先读 mepc/mcause/mtval，不先改波特率。
  2. 读取 LCR、DLL/DLM 时遵守 DLAB；确认 core clock 与 divisor。调试读取 RBR 会消费字符。
  3. THR 的 Reg/APB 写握手有没有发生？TX FIFO 是否收到了目标字节？
  4. TX 是否有起始位、8 个数据位与停止位？核对 CTS 绑值、VIP 的波特率和极性。
  5. 结束前是否 flush，UART 行是否带换行，VIP 是否记录了完整标识？无输出不等于没执行。

GPIO：数据、输出使能、输入和中断是四条路径

GPIO（General-Purpose Input/Output，通用输入输出）有 32 位。输出数据锁存器决定 gpio_o；输出使能寄存器决定 gpio_en_o；输入 gpio_i 经同步/可选滤波形成 DATA_IN，再与上一拍比较产生事件。写 DIRECT_OUT 不会自动把引脚变成输出。fixture 把 gpio_i 绑为 0，没有自动连接 gpio_o 回输入。

基址 0x03005000 + 偏移含义操作示例
0x00/04/08INTR_STATE(W1C) / ENABLE / TEST写 TEST bit0 注入事件；写 STATE=1 仅清 GPIO0
0x10DATA_IN（采样输入）不等于输出锁存器；仿真绑零时应始终读零
0x14DIRECT_OUT整组写，可能覆盖其他所有者的位
0x18/1cMASKED_OUT_LOWER/UPPER写数据低16位，写掩码高16位；upper 操作 GPIO[31:16]
0x20/24/28DIRECT_OE / MASKED_OE 两半组以同样 mask/data 方式仅启用选定输出位
0x2c/30/34/38上升/下降/高电平/低电平触发使能依据场景选一种；低电平输入绑零时会持续触发
0x3cINPUT_FILTER_CTRL逐位滤波控制；同步级与滤波阈值要看 RTL 参数，不能猜固定延迟
// 只操作 GPIO3；教学片段，板级执行前核对原理图和引脚所有权
*reg32(&__base_gpio, GPIO_MASKED_OUT_LOWER_REG_OFFSET) = 0x00080008;
*reg32(&__base_gpio, GPIO_MASKED_OE_LOWER_REG_OFFSET)  = 0x00080008;
// 顺序先设值后开输出，避免使能瞬间输出旧值。
// 恢复为输入：写 OE mask=bit3、data=0，即 0x00080000。

边沿事件通常锁存在 INTR_STATE；电平源若条件持续有效，清状态后会再置位。PLIC complete 只是通知网关允许下一次事件，不能替代外设清源。GPIO source ID = 20 + pin，依据 cheshire_int_intr_t 的 packed 顺序推导；不要从结构体书写的第一行开始编号。

两个层级的实验

G1：可构建的软注入。需要默认 PLIC、GPIO，CLIC/IRQ Router 关闭，单 hart；不驱动板级输出。

# 仓库根；只构建，在新目录保存日志
bash docs_codex/learning/scripts/build_advanced.sh gpio
# 漏触发的反例：应在运行时超时失败，不能报成功
OMIT_GPIO_TRIGGER=1 bash docs_codex/learning/scripts/build_advanced.sh gpio

输入 advanced.c ADV_STAGE=1。产物 advanced.spm.elf/map/dump/build.log；运行采用 统一命令，主机300秒，目标100ms，程序轮询上限10000000 mcycle。成功需 ADV stage=1 gpio=1 timer=0 errors=0（gpio 至少一次）及 VIP SUCCESS；坏例应 rc14。目标待验证

G2：引脚层，需独立验证环境补齐。在独立 TB 给一个 GPIO 输入施加 0→1→0，同时记录原始 pin、同步后值、DATA_IN、INTR_STATE、intr_o。成功需恰好预期边沿次数；短脉冲是否被滤除由实际 filter 参数确定。当前 fixture 不支持这项激励，本轮未改共享 TB，也未做板级 GPIO 写。G1 通过不能抵扣 G2。

1. 写完 THR 立即返回会丢最后一个字符吗？

可能在仿真提前结束时截断。THR/FIFO 接收和移位器发完是不同状态，退出前应 flush。

2. GPIO DATA_IN 不跟随 OUT 是芯片坏了吗？

不一定。先确认 OE、PAD/外部连线、同步及 TB 刺激；当前 fixture 输入固定为 0。

3. complete 后立刻再次进 ISR 查什么？

外设事件是否清除，电平是否仍有效，FIFO 是否仍满足阈值；再查 PLIC enable/priority。不要先怀疑 mret。
