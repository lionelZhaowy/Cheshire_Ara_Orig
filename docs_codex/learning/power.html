现有 RTL 的电源边界与候选低功耗契约。

本章任务

以“完成一帧后暂时关闭计算域”为任务，说明状态、事务和缓冲区怎样正常交接。前置：复位与就绪、缓冲区所有权。

33.1 候选计算域的帧间关断

设未来 NPU 已处理一帧，下一帧要过一段时间才到。先观察系统中仍有用的对象：结果可能留在 DDR，完成通知可能还没被 CPU 消费，设备配置和内部临时状态仍在寄存器。把“计算已经结束”分解到这些对象，才能决定只停时钟，还是保存一部分状态后关电。下述例子围绕尚未实现的 NPU 电源域，不把候选图画成现有结构。

电源域是一组由同一供电控制条件管理的逻辑。断电后普通寄存器状态会丢失，输出也不再是接收域可依赖的逻辑值。时钟门控减少翻转功耗；电源关断还需处理供电、状态与跨域信号。

隔离（isolation）单元把掉电域输出钳到指定的已知值；状态保持（retention）使用仍供电的保持资源保存选定状态；电平转换（level shifter）在不同电压域间转换信号电平。它们分别解决输出有效性、状态保存和电压兼容，不能相互替代。

UPF（统一功耗格式）描述供电、域、隔离及保持策略，实际电路由工艺库单元承接；PPA 表示功耗、性能、面积的联合取舍。CDC/RDC 分别检查跨时钟/复位域问题；DFT 是便于制造测试的设计，低功耗模式也需保留其测试通路。DDR self-refresh（自刷新）由存储器维持刷新以保留数据，进入和退出遵循控制器/PHY/器件要求。

实现状态

下述开关电源例子是候选方案。当前 SoC/FPGA 连接尚未构成已验证的多电源域实现；电压、域边界、库单元与恢复时序待工艺/IP 资料确定。

本次审读顶层和平台连接未建立电源意图证明。未来电源表应逐域记录供电/开关、隔离位置与钳位值、保留寄存器、SRAM 保持方式、level shifter、上电顺序、复位来源及测试模式。电压、频率、关断收益都需工艺库和 PPA 数据；实现时再形成 UPF、CDC/RDC、低功耗仿真与物理验收。

隔离和电平转换的单元职责参照 Synopsys 低功耗库单元说明；电源意图白皮书说明 UPF 与实现/验证工具的关系。本工程未选定这些库产品。

33.2 候选电源域的责任划分

33.2.1 当前 RTL 的电源控制边界

当前审读的 SoC 端口、Link 隔离连接和 FPGA wrapper 没有构成可签核的多电源域实现。时钟门控减少翻转，电源关断切断供电；关时钟也可能留下有效状态和在途事务，因此二者不能互相替代。

33.2.2 候选电源域的设计输入

候选域必须确定的状态与接口资料或验收
常开控制唤醒/复位原因、任务超时、隔离控制供电、复位、低频时钟与软件可访问性
CPU/Ara 与 SRAM上下文、VRF、cache/写缓冲、SPM 中代码和栈哪些保持、哪些丢弃并重建；SRAM retention 与启动恢复
NPU/ISP描述符、完成令牌、在途 AXI、输入帧状态停发/排空、隔离钳位、epoch 与错误完成
DDR/PHY/PAD存储保留、self-refresh、训练状态、外部电平供应商低功耗顺序、I/O 供电与唤醒时间

33.2.3 时钟域、复位域与电源域的组合

这三种“域”分别按采样时钟、复位控制和供电边界分组。同一电源域可以有多个时钟域；同一时钟来源可以送到可分别复位的模块；一个可关断电源域内也可能有保持供电的状态。画 ASIC 图时，应分别标出三种边界，再逐条检查跨边界接口，不能按一个 IP 一个电源域机械划分。

例如把未来 NPU 放入可关断域，而控制器和中断逻辑保留在常开域：CPU 写任务前要等 NPU 恢复；关断前要停止新任务、处理 AXI 在途、保存所需状态，再隔离输出。保留一个 done 信号并不足以描述在途 DDR 写。共享缓冲区属于哪个存储域，也影响断电后是否仍保留结果。

当前 Boot ROM 的调用栈可能在 LLC/SPM 中。若计划把这块 SRAM 随计算域一起断电，恢复代码就失去保存状态的空间；设计需另行分配常开存储或定义完整的冷启动恢复。电源域选择因此会反向约束链接布局、任务所有权和启动方式，而不只是 UPF 文件中的模块列表。

本地tech_cells_generic 说明将技术映射视为平台责任；存在电源单元抽象不等于当前芯片已有低功耗意图。图中的候选域须由工艺库、供电规格和后续验证落实。

33.3 候选电源域的关断、保持与恢复

33.3.1 关断前的事务与缓冲区所有权

一次正常关断先由软件停止给该域分配新帧，设备停止接收新描述符。已经接受的最后一帧继续执行，直到所有必要的内存响应回来、结果达到共享存储契约要求，再把完成信息交给仍供电的控制域。CPU 此时可以按所有权协议消费结果；控制域也能区分“结果已完成但通知未消费”和“设备可关断”。

然后列出恢复所需状态：可重写的配置由固件保留副本，不必全部 retention；必须保持的内部状态才需要专门资源；临时队列在确认排空后可丢弃。若 DDR 自己也进入低功耗，数据保留必须先按控制器/PHY/器件协议建立。存储所有者和计算域是两个判断，不能因为 NPU 关闭就假定 DDR 中的结果消失或已经持久保存。

候选流程是停止调度→停止新访问→排空或受控终止→保存必要状态→隔离跨域输出→按 IP 规范关时钟/电源。生产者尚未排空的缓冲区保持隔离所有权，不能因为 CPU 停止等待就给下一帧复用。

33.3.2 设备完成信号的隔离与恢复示例

假定设备域向常开控制域输出 done。设备域掉电后，若直接连接，未知电平可能被当成完成事件。先停止新提交，等所有已接受的读写完成或按约定受控失败，再把尚未消费的完成状态转存到常开域；随后隔离单元将 done 钳为 0。钳位值来自接收方协议：有效高通知可选 0，而有效低控制线不能机械照搬。

若需保留配置，关电前把指定寄存器保存到保持资源；队列、未确认响应和软件缓冲区所有权仍需单独处置。保持少量寄存器不等于保住全部 cache、VRF 或 SRAM。恢复时先供电、时钟及规定复位，再恢复可保留配置、重建被丢弃状态，确认输出有效后解除隔离。若允许任务编号跨恢复复用，候选设计可由控制域使用新的 epoch（任务代次）区分恢复前后任务；当前没有交付这一机制，旧完成归属必须由实际协议明确。

关断请求到达时若仍有 B 或最后 R 等待，控制器应等待排空或走已设计的错误恢复，不能直接钳低 VALID 抹掉已接受事务。隔离使信号电平确定，事务协议负责让未完成工作有明确结果。未能正常排空时的恢复另见系统诊断，不能用超时自动释放缓冲区。

33.3.3 电源域恢复与任务重新开放条件

下一帧到来后，常开控制者按供应商顺序恢复供电、等待稳定并提供时钟，在隔离仍有效时释放该域复位或恢复保持状态。固件重写已丢弃配置、重新初始化队列，设备宣布本次启动的接口就绪后，控制者解除隔离并开放任务入口。完整结果是下一帧使用新状态执行，上一帧结果仍按原所有权交给 CPU。

这一过程的收益取决于空闲长度、保存/唤醒成本和工艺漏电；电源域划分会增加隔离、保持、控制和验证成本。本项目未提供这些数据，不能宣称关电一定节能。若只需要短暂停止翻转，门控可能更适合，但仍要明确停钟时哪些协议能够等待。

恢复时先保证供电与时钟，再按各域要求释放复位、恢复或重建状态、确认接口就绪并解除隔离。UPF 定义电源意图，库单元实现 isolation/retention/level shifter；还需低功耗仿真、CDC/RDC、DFT 与物理检查。这里列出设计输入和验收责任，不给未经工艺资料支持的电压、频率或节电比例。
