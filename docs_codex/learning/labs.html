本章任务

六项实验服务于主线中的六种能力：解释程序布局、验证执行与失败传播、服务异步事件、分层验证串行存储、证明向量计算、检查设备接口契约。简单源码搜索和环境查询留在正文，不另设实验。

共同环境与记录约定

全部构建命令使用 Bash，工作目录为仓库根。需要 Python 3、交叉 GCC/binutils；目标运行另需匹配的 RTL 清单、模拟器许可、DPI 和设备模型。先执行 command -v riscv64-unknown-elf-gcc python3 g++ vsim vcs vlogan bender 记录可用工具。自选工具链用 CROSS_COMPILE 设置带末尾连字符的前缀。

每份 ELF 使用独立空输出目录，记录 HEAD、完整构建日志、ELF 哈希、map/dump 和运行参数。主线目标配置为单核、向量 profile/真实 decoder、SelectedCfg=3、BOOTMODE=0/PRELMODE=0，默认 LLC 全 128 KiB SPM，CLIC/Router/RT 关闭。标量示例也因原 crt0 而需要 F/D。

软件构建预算 60 秒；SoC 单阶段起始墙钟预算 300 秒，Questa 目标运行 100 ms。预算是终止条件，不是保证耗时。旧测频和串行驱动有无界轮询，因此保留独立的墙钟限制。所有下述运行现象均为目标环境验收预期，原始构建记录见09-28 记录，扩充构建见09-29 深度记录，本次组织与导航检查见结构修订记录。

实验 A · 同一程序的构建与存储布局

目的与前置：完成运行模型与工具链两章，区分文件字节、运行空间和初始化责任。输入是 journey.c、原 crt0/UART/CLINT/printf、spm.ld/common.ldh；只需主机交叉工具链。

LEARN_OUT=$(mktemp -d "$PWD/docs_codex/learning/evidence/journey.XXXXXX")
JOURNEY_OUT="$LEARN_OUT" timeout 60 bash docs_codex/learning/scripts/build_journey.sh scalar spm
cat "$LEARN_OUT/readelf.txt"
rg -n '(_start|main|make_value|seed|result|greeting|__bss|__stack_pointer)' "$LEARN_OUT/symbols.txt"
rg -n '\.misc|\.bss|greeting|seed' "$LEARN_OUT/journey.map"
sha256sum "$LEARN_OUT/journey.spm.elf"

产物与判据：输出目录有 journey.i/.s/.o、crt0.o、libsupport.a、journey.spm.elf、journey.map/dump、symbols.txt/readelf.txt/build.log。入口应为 0x10000000；result 大小 548 字节，位于 BSS；seed 和 greeting 进入 .misc；栈符号为 0，表示继承 ROM 栈。应能从 map 对上每个对象的输入与输出节，并从 dump 找到 main 和 make_value 调用。

有价值的对照：用新目录以 bash docs_codex/learning/scripts/build_journey.sh scalar dram 只构建另一个布局，检查入口 0x80000000、栈符号 0x807ffff8。该对照只解释链接，DRAM 运行需要模型/控制器覆盖段和栈。

失败首查：缺工具查前缀；undefined reference 查对象及库；找不到符号查 stage、优化和实际输出路径；布局异常查链接脚本。此次结果属于主机软件构建，未执行 CPU。

实验 B · 装载执行与错误传播

目的与前置：承接实验 A，按启动、调试与仿真章节完成自洽清单导出、RTL 编译及展开。使用 A 的正常 ELF。先在准备节设置 LEARN_SIM/LEARN_REPO/LEARN_ELF，再按所选工具的精确Questa 命令或VCS 命令运行；产物为 compile、elaborate（VCS）、simulate 日志。

# RTL 已按第 17 章编译；这里给出完整的 Questa 运行动作
LEARN_ELF="$LEARN_OUT/journey.spm.elf"
(
  cd "$LEARN_SIM/vsim" || exit 1
  timeout 300 vsim -c -do "onerror {quit -code 2 -f}; set SELCFG 3; set BOOTMODE 0; set PRELMODE 0; set BINARY {$LEARN_ELF}; source start.cheshire_soc.tcl; run 100 ms; quit -f" > journey-normal.log 2>&1
)
python3 docs_codex/learning/scripts/check_run.py "$LEARN_SIM/vsim/journey-normal.log" --stage array
LEARN_BAD=$(mktemp -d "$PWD/docs_codex/learning/evidence/journey-bad.XXXXXX")
JOURNEY_OUT="$LEARN_BAD" INJECT_ERROR=1 timeout 60 bash docs_codex/learning/scripts/build_journey.sh scalar spm

把 LEARN_ELF 改为 $LEARN_BAD/journey.spm.elf，重复同一运行命令，但日志名改为 journey-injected.log，检查命令改读这个文件。VCS 同样只换 BINARY 并另存日志。

结果与原因：正常初态检查通过、sum=28085/errors=0、[JTAG] SUCCESS，且无模拟器错误。注错使 result[5] 从 16 变 17，应 sum=28086/errors=1、VIP FAILED、check_run 返回 1。一次正常通过与一次预期失败，才证明返回码和外部判据能发现数据错误。

失败首查：先看首个未完成阶段：RTL 编译 → DPI/展开 → ROM/SPM → halt/load/resume → main → 测频/UART → 校验/结束。回传 PC/CSR、入口/段范围、scratch2 及首错。JTAG 段尾风险仍需独立边界用例；本实验不是 loader 全边界验收。

实验 C · GPIO 事件与定时器协同

目的与前置：完成UART/GPIO 与中断两章，观察清源与 complete 的不同职责。输入保留的 advanced.c，ADV_STAGE=2；要求单 hart、PLIC/GPIO/RTC 正常、CLIC/Router 关闭，handler 只使用整数。

timeout 60 bash docs_codex/learning/scripts/build_advanced.sh timer
# 按输出行选择本次 advanced.spm.elf；沿实验 B 的同一运行命令
# 改 LEARN_ELF，日志另存 timer.log，再检查：
python3 docs_codex/learning/scripts/check_advanced_run.py "$LEARN_SIM/vsim/timer.log" --stage timer
# 可选反例：同一 timer 程序省略 GPIO 触发，预期超时失败
OMIT_GPIO_TRIGGER=1 timeout 60 bash docs_codex/learning/scripts/build_advanced.sh timer

产物：新的 evidence/adv-timer-spm.* 内有 ELF/map/dump、symbols/readelf/build.log。运行日志应有 ADV stage=2、gpio≥1、timer≥2、errors=0 及 JTAG SUCCESS；handler 推进 compare，前台计数满足后结束。反例应返回 14，主机检查器拒绝；程序等待预算 10000000 mcycle，外围仍有 300 秒限制。

失败首查：GPIO 先从 INTR_STATE 跟到 PLIC source20 和 mie；timer 从 RTC/mtime 跟到 compare/MTIE。异常查 adv_mcause/mepc/mtval。该实验只软注入 GPIO，不覆盖绑零 fixture 中的引脚同步和滤波。

实验 D · 两种串行存储的只读对照

目的与前置：完成I2C 与 SPI 两章，用相同“16 字节独立内容校验”比较不同器件协议。输入 storage_read.c 的 stage4/5；默认 VIP 模型已编译并预填 0x9a，未传自定义镜像，I2C/SPI 开启。EEPROM 固定 addr=0、len=16；NOR 为 CS1、1 MHz。

timeout 60 bash docs_codex/learning/scripts/build_advanced.sh eeprom
# 选本次 ELF，沿实验 B 运行，另存 eeprom.log
python3 docs_codex/learning/scripts/check_advanced_run.py "$LEARN_SIM/vsim/eeprom.log" --stage eeprom
# 独立构建和运行另一器件：
timeout 60 bash docs_codex/learning/scripts/build_advanced.sh flash
python3 docs_codex/learning/scripts/check_advanced_run.py "$LEARN_SIM/vsim/flash.log" --stage flash

产物与判据：各自新的 adv-eeprom/adv-flash 目录包含 advanced.spm.elf/map/dump 和构建日志。预期 STORAGE stage=4/5 bytes=16 errors=0 及 JTAG SUCCESS；同时确认 EEPROM 地址/ACK 与 NOR 片选/opcode/地址段。数据不是 0x9a 时应失败，不能修改期望以掩盖错误。

失败首查：I2C 查上拉/释放、ACK、FMT/RX；SPI 查 CS1、0x13/四字节地址、方向与 RX FIFO。HAL 等待无统一 deadline，保留 100 ms 目标/300 秒墙钟限制。本实验只读模型；未对齐 EEPROM 边界、NOR 写/擦除和 SD 模型均另行验证。

实验 E · 同一数组的 RVV 对照

目的与前置：先通过标量运行，再完成LLC/SPM、Ara、RVV 与共享数据章节。输入同一 journey.c 加 rvv_add.S；完整向量配置、VS 初始化、单核和全 128 KiB SPM；物理 [0x10010000,0x10011000) 独占，栈在其上，仅用高别名触碰 a/b/c。

LEARN_RVV=$(mktemp -d "$PWD/docs_codex/learning/evidence/journey-rvv.XXXXXX")
JOURNEY_OUT="$LEARN_RVV" timeout 60 bash docs_codex/learning/scripts/build_journey.sh rvv spm
rg -n 'learn_vadd|vsetvli|vle32.v|vadd.vv|vse32.v' "$LEARN_RVV/journey.dump"
riscv64-unknown-elf-readelf -A "$LEARN_RVV/rvv_add.o"
# LEARN_ELF 指向本次 journey.spm.elf，沿实验 B 运行另存 rvv.log
python3 docs_codex/learning/scripts/check_run.py "$LEARN_SIM/vsim/rvv.log" --stage rvv

产物与判据：ELF/dump/对象属性确认 RVV；目标 PC/退休和 Ara 握手确认实际走到 learn_vadd；日志 RVV checked=137、sum=28085/errors=0、守卫未改变、正常退出确认结果。设置 INJECT_ERROR=1 在新的输出目录构建可复用 B 的错误传播对照，不需要再设计一个独立小实验。

失败首查：首条非法指令的 mepc → profile/decoder/VS → Ara 指令握手 → 向量地址和 R/B → 数据可见性。该例验证当前 SPM 小任务，不估算 DDR 大模型吞吐。向量阶段拒绝 dram 构建，因为预约缓冲与启动栈契约专用于 SPM。

递进：尾部、归约与三种编程入口

继续使用 journey.c 和同一预约 SPM 区，不增加孤立硬件测试。JOURNEY_DEPTH=1 先检查原 137 项与归约 28085，再测试长度 0、1、63、64、65、137；输入包含不同斜率和 uint32 环绕值，参考结果由标量公式独立计算，逐项验证输出、输入保持、归约与尾后守卫。长度 63/64/65 对当前 e32,m1 的边界有意义，但算法按返回 vl 推进。

# 每次自动创建新的 evidence 输出目录；先记下 Output 行。
JOURNEY_DEPTH=1 timeout 60 bash docs_codex/learning/scripts/build_journey.sh rvv spm
JOURNEY_DEPTH=1 timeout 60 bash docs_codex/learning/scripts/build_journey.sh rvv-intrinsics spm
JOURNEY_DEPTH=1 timeout 60 bash docs_codex/learning/scripts/build_journey.sh rvv-auto spm
# 每个 ELF 分别按实验 B 装载，保留配置/波形/日志，不能沿用旧 rvv.log。
python3 docs_codex/learning/scripts/check_run.py "$LEARN_SIM/vsim/rvv-depth.log" --stage rvv --depth
# 错误传播对照：另建产物并运行，检查器必须拒绝。
JOURNEY_DEPTH=1 INJECT_ERROR=1 timeout 60 bash docs_codex/learning/scripts/build_journey.sh rvv spm

编译阶段检查对应内核中的 vset、load/add/store 与 vredsum，自动向量化另读 vectorization.txt；CRT、主程序、参考循环和支持库保持标量。目标阶段对 PC/CPU trans_id、Ara req_valid/ready、VRF/VLSU 活动和内存地址建立关联。结果阶段要求 RVV checked=137、RVV_REDUCE n=137 sum=28085、RVV_DEPTH cases=6 errors=0、LEARN errors=0 和正常完成，同时保留首错诊断。

日志检查器只能验证日志契约。独立数值校验能发现重复元素、少算尾部、错误步长和归约累计等问题，但 UART PASS 仍不证明目标配置或时序路径正确。性能另按计时条件建立实验；本轮没有目标运行或周期成绩。

实验 F · 独立寄存器设备契约

目的与前置：完成第 27 章，检验字节写、启动/完成和 W1C/IRQ。输入 lesson_reg_adder.sv 与 tb_lesson_reg_adder.sv；只需 vlib/vmap/vlog/vsim，无生产 SoC、DPI 或 ELF。

bash docs_codex/learning/scripts/run_hw_unit.sh

产物与判据：脚本在新 /tmp/cheshire-hw-unit.* 建 work 库，打印 setup/compile/run/injected 日志路径，建库各步骤 30 秒，编译与每次运行各 60 秒预算。正常应出现 HW_UNIT_PASS 并通过 35 项检查，注入 +INJECT_FAIL 后检查器必须拒绝。工具进程码与日志判据共同判断，历史 Questa 在 fatal 后仍可能返回 0。

失败首查：工具/许可 → 编译首错 → 首个断言时间点及寄存器事务。历史 2026-09-23 运行记录保留；本轮是否重跑以证据页为准。该两文件单元没有接入 Cheshire，系统地址、中断 handler、AXI 桥和 DDR 仍需集成验证。

旧实验的取舍与证据分类

原环境检查并入共同前提，Hello 与数组构建、ELF 观察合并为 A；数组正常/注错与仿真合为 B；scratch 回读和 timer 轮询改为正文机制说明，GPIO 与 timer 中断合为 C；EEPROM/NOR 合为 D；RVV 与同一数组闭环合为 E；硬件模型零散练习改为正文推导，保留独立 SV 单元为 F。DMA/capstone 保留源码和阻塞说明，退出当前运行路线；Link 加载对照、VGA/USB/SD 环境不齐的项目改为明确的后续验收条件。

源码阅读说明连接与语义，主机构建说明产物形成，独立单元说明局部 RTL 行为，完整 SoC 仿真才覆盖加载执行及设备协同。六项实验各自记录证据层次，不以其中一个层次的 PASS 替代另一个。
