13 · SPI、NOR 与 SD

控制器负责移位，设备协议决定命令、地址、忙等待和数据校验。

SPI 控制器与命令队列NOR Flash 命令与访问协议SD 卡 SPI 模式与协议状态机S1/S2 · NOR 读取与 SD 错误路径验证
学习目标

把一个 SPI 事务拆成 opcode/address/dummy/data 段；解释 NOR 和 SD 为什么共用控制器却不能共用初始化协议。前置：第 10/12 章。场景：SCK 在动，读回全是 0xff。

SPI 控制器与命令队列

SPI（Serial Peripheral Interface，串行外设接口）由 host 驱动 SCK 和片选 CS，数据用一条或多条 SD 线移位。CPOL 决定空闲电平，CPHA 决定采样/更新相位。本 SoC 用 OpenTitan spi_host：每个 CS 的 CONFIGOPTS、命令 FIFO、TX/RX FIFO、移位器和状态机构成执行路径；普通写 TXDATA 只是入队，COMMAND 才定义怎么移出。

0x03004000 + 偏移寄存器关键字段/顺序
0x00/04/08INTR_STATE/ENABLE/TESTerror 与 spi_event 两个汇总输出，分别 PLIC17/18
0x10CONTROLSPIEN bit31、SW_RST30、OUTPUT_EN29；输出使能与内部使能不同
0x14STATUSREADY31/ACTIVE30；TX/RX空满、stall、队列深度；READY不是外部设备已就绪
0x18/1c/20CONFIGOPTS_0..2CLKDIV、CPOL/CPHA、FULLCYC、CS idle/lead/trail
0x24CSID选择后续命令片选；本地模型 NOR 在 CS1
0x28COMMANDLEN[8:0]为长度减1、CSAAT bit9、SPEED[11:10]、DIRECTION[13:12]
0x2c/30RXDATA / TXDATAFIFO 取数/入数，深度头文件 TX=72、RX=64 个32-bit字，命令深度4
0x34/38/3cERROR_ENABLE/STATUS、EVENT_ENABLE区分错误来源和事件阈值，再开中断；不要只看总 IRQ

dif_spi_host_configure_cs 用输入频率和目标 SPI 频率选 divider，配置 CPOL/CPHA 与 CS 时序。dif_spi_host_transaction 把每个 segment 转 COMMAND，配合 FIFO 搬数据。连续 opcode+address+data 之间应保持 CS；CSAAT（Chip Select Active After Transaction）保持片选的语义和最后一段是否释放必须一致。长度字段的单位随段类型而异：普通数据用字节，dummy 段描述时钟周期。

NOR Flash 命令与访问协议

// 当前 spi_s25fs512s_single_read 的三段事务
opcode  = 0x13;                  // 4-byte address single read
address = 4 字节器件内部地址;    // 不是 CPU 的 0x03004000
rx      = len 字节到 RAM;
// HAL 每块最多 4 * RX_DEPTH 字节，避免一次接收超过 FIFO容量。

这里有三类地址：CPU 的 SPI 寄存器地址、RAM 接收缓冲区地址、Flash 内部地址。控制器输出的四字节 address 是最后一种。HAL 初始化默认 CPOL=0、CPHA=0；示例选1MHz/CS1，先以低速确认字节，再提高频率。SCK 活动但读全 0xff，先查 CSID、IO方向/上拉、opcode/地址长度/器件就绪，再查 FIFO字节顺序。

写入路径需要 write-enable 0x06，program/erase 命令后通过 status 0x05 的 WIP 位等待，并检查错误位；页、扇区粒度和擦除状态是器件协议。当前 HAL 的闪写函数会擦大扇区，不是本轮实验。另有一处需审读：写 CR3V 的0x71段却构造了 Rx 类型；应以设备模型验证事务方向后独立修复，不能宣称完整烧写已可用。

SD 卡 SPI 模式与协议状态机

SD 在这里不是独立 SDIO 控制器，而是 spi_sdcard.c 在 SPI host 上实现协议：上电 dummy clocks → CMD0 → CMD8/响应校验 → CMD55+ACMD41 循环激活 → CMD58 确认状态，再进行块读写。代码有命令 CRC7、数据 CRC16、不同响应长度/忙等待与 token 处理；不能只发0x13读取SD。

__spi_sdcard_xfer_csaat 保持片选完成多段命令，__spi_sdcard_csfree 通过 dummy CS 再发8个周期，促使卡释放数据线。驱动假定的 CSID、dummy CS 与卡类型/块寻址要从 handle 与板级连线核对。当前 VIP 没有与 NOR 同级的 SD 模型；VCU118 宏未启用 USE_SD。故本章的 SD 验收是源码协议表和测试规划，不能伪造一条现成 SD 测试命令。

S1/S2 · NOR 读取与 SD 错误路径验证

S1 输入 storage_read.c ADV_STAGE=5，基于现有 NOR 模型预填0x9a；SPI=1、模型已编译、无自定义镜像覆盖。工作目录仓库根：

bash docs_codex/learning/scripts/build_advanced.sh flash
rg -n 'spih_norflash_preload|CSNeg|9a' target/sim/src/vip_cheshire_soc.sv
rg -n 'CMD0|CMD8|ACMD41|CMD58|timeout|crc16|csfree' sw/lib/hal/spi_sdcard.c

新目录 evidence/adv-flash-spm.XXXXXX 有 ELF/map/dump/build.log；按 统一运行代入 ELF。预期 STORAGE stage=5 bytes=16 errors=0 和 VIP SUCCESS。目标100ms/主机300秒；若 READY/FIFO/WIP等待不退出，外层必须终止。最小波形：CS1/SCK/SD0/SD1、COMMAND、TXQD/RXQD、ERROR_STATUS。运行待验证

S2 不启动硬件：列每个 SD init 命令、期待响应、超时单位和错误码；确认数据 CRC 是否参与返回码。后续端到端需要 SD模型/真实接线、已知只读扇区内容、卡类型与 timeout选择。成功需512字节内容/CRC正确和缺卡超时失败两个用例，不能用“初始化返回0”结束验收。

NOR 初始化/读/闪写；SD 命令与 CRC；配置/事务/FIFO；SPI 核心 RTL；字段。
1. READY=1 能证明 Flash 不忙吗？

不能。READY描述控制器可接受命令；Flash忙状态通过设备status命令读取，属于另一层协议。

2. 为什么不能把 COMMAND.LEN 直接写 len？

数据命令通常编码为长度减1；写错会多传一个单位。应跟踪 DIF 对长度与 dummy 的分别处理。

3. 只读 Flash 成功能证明启动镜像和 SD 正确吗？

不能。启动还涉及分区/GPT/镜像布局与执行地址；SD又有独立初始化、token和CRC协议。
