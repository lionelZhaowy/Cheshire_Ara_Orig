本章任务

沿“上电 → 有效时钟 → 释放复位 → 存储和软件就绪”理解正常启动，再解释一次受控域重启怎样交还事务。前置：时钟与 PLL。

复位先建立控制状态，再由启动流程建立可用系统

复位给状态机、有效位和控制寄存器规定起点。它不自动完成 SRAM 初始化、DDR 训练、软件栈建立或外部器件上电。设 CPU 复位 PC 指向 Boot ROM，平台先保证时钟与取指路径有效，再允许 CPU 开始执行；ROM 随后准备启动所需存储，应用启动代码最终建立 C 环境。每一步的输出成为下一步的前提。

当前几个复位入口分别控制什么

入口本地连接与正常职责使用边界

JTAG TRST/TCK调试传输侧复位/时钟，DMI 与系统域交互不能视为所有设备的统一重启

USB/Serial Link 的接口状态接口有各自时钟/局部控制，按实际连接建立就绪局部复位与系统在途事务须遵守接口协议，未形成独立关电闭环

本地 FPGA wrapper 先将外部/VIO 复位请求组合后送 rstgen，它在系统时钟下产生 rst_n。复位域由真实连线和寄存器敏感列表决定，不能按 IP 名字想象已经具备可独立重启能力。

为什么释放必须等本域时钟

本地 rstgen_bypass 默认有四级同步寄存器。普通模式下异步断言把链清零；外部复位撤销后，常数 1 随本域时钟逐级前进，最终输出解除复位。如果时钟没有运行，这条链不会前进。它把释放动作收敛到本域边沿；级数、库单元和测试模式仍需按目标条件验收，不能用“四级”替代可靠性分析。

先沿图读出供电与时钟条件，再看系统域复位释放；DDR 初始化和接口开放位于它们各自前提之后。PLL lock 不直接等于 DDR ready，系统域 released 也不能替 DDR 域完成同步。不同域共同参与一条事务时，还须重新建立握手和 FIFO 状态，详见复位域交接。

用可观察里程碑连接硬件和软件

从第一条指令到应用 main

本地保留内部 LLC 的启动路径会先等待 tag BIST、配置 SPM 并调整栈，然后才调用 Platform ROM 钩子和继续 ROM 服务。无内部 LLC 的配置跳过该初始化，平台必须在首次栈访问前提供替代可写存储与有效 sp，或用不依赖栈的早期汇编建立它们。因此复位释放和“可以安全调用 C 函数”之间有具体存储步骤。

JTAG VIP 在 LlcNotBypass 时轮询 CFG_SPM_LOW.bit0 后发 halt；这一位不是 ROM C 已执行完或测频完成的标志，也不能独自证明随后的栈调整已执行。正常接管要按JTAG 装载章的实际流程判断。

外存前提放在首次访问之前

DDR 的控制器、PHY 和存储器按供应商协议完成初始化/训练，平台才应允许依赖 DDR 的取指、栈与数据访问。可先把早期初始化代码和栈放在已知可用的片上存储，再做外存校验。外设也按自己的上电、引脚与时钟条件初始化；MMIO 寄存器可读只证明控制路径，不代表器件已经完成操作。

一次正常重启，怎样把接口先停下来

停止新请求，再等待已接受事务

设软件已决定暂时重启一个未来设备域。先关任务入口，让已提交工作继续推进。AXI 写若已接收 AW，仍可能等待 W 和 B；读若已接收 AR，仍可能有多拍 R。只有设备、桥和相关队列共同满足定义的 idle/drained 条件，控制者才能按契约断言复位。停止 CPU 轮询或看见一个 FIFO 空，并不具有这种含义。

复位期间保留访问隔离；重新提供时钟并同步释放后，重建配置、描述符和握手状态，再允许新任务。若完成编号会重复，还要定义恢复前后任务的区分。正常重启的预期是旧任务已经得到明确结果，新任务不会收到旧响应。该域独立复位能力是待设计契约，当前通用 SoC 并未提供任意 IP 的统一重启 API。

验证正常重启及异常边界

未来验证首先检查空闲重启与排空后重启，再在地址、数据或响应等待时安排重启请求，确认按协议等待。未能排空、突然断电和强制复位的终止/恢复属于独立诊断与验证场景；不能靠直接掉时钟让已接受事务无声消失。验证记录须明确范围，本轮没有实现或运行这些目标场景。

撤销 rst_ni 后，为什么还不能马上把 DDR 当栈？

同步释放只建立相关控制状态；DDR 初始化/训练、地址与访问路径可用仍需独立建立。早期栈先在已经可写的存储中。
