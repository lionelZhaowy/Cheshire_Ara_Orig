进程地址空间与地址翻译

前置：链接布局、存储与缓存、特权与 trap。本章从单个数组的物理存储，推导进程地址空间和 Sv39 页表，再解释为什么用户指针不能直接交给设备。数字例是教学映射，不分配本工程地址。

裸机数组的物理存储与访问条件

裸机 journey 的链接器为静态数组安排地址，启动阶段准备其内容，CPU 用地址读写它。在地址翻译关闭、权限允许的路径上，软件有效地址直接作为物理访问的依据；物理地址再经过互连译码到 SPM 或 DDR。可路由的窗口、实际存在的 RAM、已经初始化可用的容量，是三个不同条件；某地址落在 DDR 窗口内并不证明 DDR 已经可用。

现在希望同时运行两个用户程序，各自有一个数组，且一个程序写错指针时不能破坏另一个。只让链接器把 A、B 放到不同位置，并不能阻止 A 执行一条指向 B 的 store。需要硬件检查访问权限，还需要 OS 管理地址与所有权。保护回答“能不能访问”，翻译回答“这个地址对应哪里”；两者相关，却不是同一个功能。

PMA、PMP 与页权限的职责

物理内存属性（PMA）描述区域的固有访问条件，例如设备区域与普通 RAM 的差异、是否可缓存以及支持哪些操作。它与实际存储/互连实现关联，不是应用随意写一个指针修饰符即可改变。物理内存保护（PMP）按物理区域限制访问，通常由更高特权的软件设置；具体条目数量、锁定行为和对不同特权的作用需按本地 profile 与 CSR 实现核对。

分页启用后，页表还给每个映射赋予读、写、执行、用户可访问等权限。U 模式程序不能因为知道内核地址就直接读取内核页；一次翻译成功也不代表后面的物理访问必然获准或设备已就绪。M 模式、S 模式和 U 模式是权限级别，不是三套处理器。本章 Linux 示例采用常见的 M 模式固件、S 模式内核、U 模式用户程序分工，其他启动模式须单独说明。

本地 cv64a6_imafdcv_sv39 profile 具有 MmuPresent=1、RVS/RVU 配置；SoC 又通过 gen_cva6_cfg 形成实际 CPU 配置。因此学习 Sv39 有本地硬件落点，但不能由 profile 文件存在推断当前 bitstream 已用该组合或 OS 已验证。配置来源与运行证据仍应分别记录。

Sv39 的 4 KiB 页地址翻译示例

页把地址空间划分成固定大小的块。用基本 4 KiB 页时，地址的低 12 位是页内偏移，翻译只替换高位的页号；这样一页里的第 8 个字节在映射后仍位于物理页的第 8 个字节。Sv39 使用 39 位虚拟地址，三个 9 位虚拟页号索引加 12 位偏移；RV64 地址高位还须符合符号扩展形式。下面选择低地址示意，避免把地址合法性与权限例子混在一起。

教学条件：进程 A 的 VA 0x0000000040001008，执行一次 32 位 load
VPN[2] = 1，VPN[1] = 0，VPN[0] = 1，页内偏移 = 0x008
satp.PPN → 根页表物理页
根表第 1 项 → 下一层表；下一层第 0 项 → 最后一层表
最后一层第 1 项 → 物理页 0x80021000，权限允许 U 读
最终物理字节地址 = 0x80021000 + 0x008 = 0x80021008

这不是把每一层表串成普通指令 load。CPU/MMU 在翻译未命中时按页表遍历规则取表项（PTE），确认它是下一层指针还是叶子映射，并检查有效性及访问权限。以本例普通 4 KiB 页为前提走完三层后，得到物理地址；TLB 缓存近期翻译，后续命中时无需再次读取所有表项。页表本身也占用真实 RAM，根地址来自 satp 的物理页号，不应放在尚未可用的 DDR。

Sv39 PTE 的 V 表示有效，R/W/X 表达叶子访问权限，U 区分用户访问条件，A/D 记录访问/写入状态。表项的合法组合、A/D 更新策略和超级页有专门规范；首次推演只使用预先准备好、权限与 A/D 均满足需求的普通页。这样读者可以先连续解释一次正常翻译，再学习 OS 如何按需建立映射。这里没有把“页表字段齐全”当成本地全部扩展都已实现。

规则以本地随附的官方 Supervisor 规范：satp、Sv39 与地址翻译算法为依据；实现能力看 本地 profile 和 gen_cva6_cfg。随附规范包含本核未必支持的新扩展，本章只使用已存在的基础 Sv39 语义。

进程地址空间与页表切换

让进程 B 也访问 0x40001008，但 B 的页表将这页映射到物理 0x80031000。A 读到 0x80021008 的内容，B 读到 0x80031008 的内容。两者的指针数值相同，数据并不共享；地址只有与“哪个地址空间”一起解释才有意义。OS 为进程管理映射，线程则可以共享同一进程地址空间而分别持有寄存器和栈。

OS 切换进程时，除了调度上下文，还要选择对应页表及地址空间标识。satp 含 MODE、ASID、根 PPN；ASID 可帮助区分 TLB 条目，实际实现多少位应核对，不能默认全部位可用。改写 satp 本身不代替所有页表同步工作。OS 按规范使用 SFENCE.VMA 协调页表写入与本 hart 后续地址翻译；多 hart 时还需其他 hart 的协作，不能把本地一次 fence 当作全系统广播。

希望 A/B 共享一块结果时，可以由 OS 明确把同一物理页映射到各自地址空间，并规定谁生产、谁消费、何时交接。共享映射解决“能访问同一份存储”，互斥、内存顺序、缓存一致性解决“怎样可靠地观察更新”。两者不能互相替代。没有页表的 RTOS 也能调度任务，只是一般不由这套机制给每个任务制造独立的虚拟地址空间。

按需分页与页异常处理

操作系统不一定立即为申请到的每个虚拟页分配 RAM。若应用第一次访问一个合法但尚未驻留的页，CPU 按规则进入页异常；内核检查访问属于合法映射后，分配并初始化物理页，更新页表，完成必要同步，再让原指令重新执行。这个过程是按需分页的正常机制。若访问不在程序获准范围内，OS 的处理结果不同，但具体故障定位不在本章主线展开。

从 MIPS 背景迁移时，先区分 TLB 未命中与页异常：本书的 CVA6 Sv39 路径可由硬件页表遍历填充 TLB，TLB 未命中并不自动等于软件异常。页表或权限不满足时才按相应原因进入异常处理。也不能把普通数据缓存 miss 当成页表 miss；前者是在已经确定的地址上找数据副本，后者在确定地址解释。

用户虚拟地址与设备 DMA 地址

CPU 运行用户程序时使用它的虚拟地址；设备作为 AXI master 发出的地址通常不经过这个进程的 CPU 页表。把上例 0x40001008 直接写进设备地址寄存器，设备不会自动找到 A 的 0x80021008。即使某平台设备地址数值等于物理地址，软件也必须经平台提供的映射契约获得它；本工程尚未由此建立通用 IOMMU 或统一 DMA 一致性能力。

名称由谁解释在一次设备操作中的用途
用户虚拟地址进程页表与权限应用填写、读取数组
内核虚拟地址内核映射内核访问自己的 buffer 或经授权处理用户数据
CPU 物理地址物理地址图及访问属性描述实际 RAM/设备资源
DMA/总线地址设备所在总线与平台 DMA 映射驱动提交给设备；不从用户指针强转得到
MMIO 映射内核设备映射与寄存器访问规则驱动读写设备控制/状态；不是数据缓冲区

以“用户提交 137 个数，设备处理后返回结果”为条件化设计例：应用提出请求；驱动验证长度和权限，把输入复制到合适的内核缓冲，或按系统约定固定用户页并建立受控映射；驱动取得设备可用的 DMA 地址，完成方向对应的同步，将所有权交给设备。收到真正完成事件后，驱动确认设备不再访问这块存储，按 API 归还 CPU 访问权，再把结果交回应用。用户程序退出或释放内存的时机也必须纳入生命周期，不能让设备继续写已被重用的页。

Linux 的 dma_map_single 等映射 API 返回 dma_addr_t；方向描述设备读写，映射失败要检查，map/unmap 或 sync 调用承担平台约定的同步责任。API 正确使用仍依赖平台 DMA 支持真实反映硬件：本地 CPU L1、Ara、LLC 和未来旁路 DDR 的一致性条件见共享存储，不能用“Linux 有 DMA API”关闭 M01 缺口。上面的设备流程是设计教学，不表示本地 iDMA 已有可运行 Linux 驱动；其现有门槛见iDMA 诊断。

Linux DMA 语义依据：本地 v6.5 随附 Dynamic DMA mapping Guide；CPU/Ara/LLC 当前连线仍以 SoC 源码及共享存储章为准。

地址空间切换的推演与验证条件

现在在纸上准备 A/B 两张映射表：A 的虚拟页 0x40001000 指向物理 0x80021000，B 指向 0x80031000；分别在物理页偏移 8 存入 11 和 22。执行 A load、切换页表与现场、B load、切回 A load，应依次得到 11、22、11。若再把 B 改为共享 A 的物理页，期望值随共享存储改变，且需明确同步顺序。这一练习不对本工程 RAM 做任何写入。

目标实验需先提供实际 MMU profile、OS 页表管理、可用 RAM 和观测入口，再记录进程标识、映射、访问权限与读回值。本轮只核对源码及文档；没有建立页表、运行内核或执行用户程序。最小验收不是背下 satp 位号，而是能指出：哪个地址被翻译、谁提供根表、哪一步检查权限、TLB 缓存什么，以及设备为何不能直接使用该用户地址。

同一用户指针复制给另一个进程，是否就共享数据？

不一定。要比较两进程的映射是否指向同一物理对象，并确认访问权和生命周期。即使已经共享物理页，也须满足同步与缓存契约；若改交给设备，还要获得设备使用的 DMA 地址。答案可沿两个地址空间和设备地址逐层推导。
