# L01 教材重构设计（2026-09-28）

## 重构判断

旧站覆盖广，但读者必须在入门、进阶、硬件三套顺序中自己组装依赖。架构/系统/硬件平台重复解释层级；配置/CPU 配置/结构展开/拓扑生成分散了同一参数的来源与消费者；访存/执行机制/DMA-LLC/硬件存储反复切换软件和硬件视角。外设硬件原理在硬件路线，驱动步骤在进阶路线，配置又在另一章，难以连续追踪一笔事务。

旧 lifecycle 很早使用 ELF、段、栈、启动对象与 ABI，却缺少面向 RTL 背景读者的运行模型：函数为何要返回地址；局部变量、全局变量、常量和 BSS 为什么具有不同初始化责任；sp 是指针而不是一块固定“硬件栈”；软件函数库和硬件模块实例有什么区别。基础术语分散在后文，会造成“先执行命令、后猜命令含义”的倒置。

因此正文从实际源码重新写作，不把旧段落换目录拼起来。每章以一个能推进后续理解的问题为中心，在首次需要时定义术语；硬件机制、配置消费者、驱动和可观察结果在同一设备章汇合。保留重要限制，但集中到相关行为及证据页，避免每一段重复状态标签。

## 实验取舍

1. **A：对象和布局。** 一次构建就能观察运行模型，保留 SPM/DRAM 布局对照；不单列环境探测、Hello、反汇编三项重复实验。
2. **B：装载到结果。** 同一正常/注错程序验证 UART、退出码和独立结果检查器；不是看到 Hello 就完成。
3. **C：定时器与 GPIO 中断。** 保留真正的事件闭环和遗漏触发负例；MMIO scratch 与轮询示例降为正文辅助，不再各占一项。
4. **D：两类器件读取。** EEPROM/NOR 各读 16 字节，以相同结果问题对照协议；排除未经模型支持的 SD、擦写路径。
5. **E：同一任务的 RVV。** 延续 137 项数组，加入独占缓冲区、尾部保护字和三层证据；替代彼此割裂的数组/RVV 演示。
6. **F：独立 Reg IP。** 35 项访问/握手检查与注错示范控制契约，再映射 SoC 接入责任；不扩张为生产 RTL 验收。

原 DMA 与 capstone 中 DMA 数据实验暂不进入主线验收：本地 64/32 位控制路径和 HAL 访问语义尚未通过专项核验，不能让初学者把默认拒绝启动误当作实验通过。原 Python 拓扑/仲裁/位宽模型转为理解辅助；Serial Link 备选装载作为启动和接口章节内容。删除正式编号不等于删除历史文件，原样例和原结果仍可追溯。
