解释ROM、系统寄存器、JTAG、UART debug与Serial Link怎样交接控制权；区分内存模型与真实DDR。前置：第04/05/08章。场景：ELF已加载，CPU却仍在ROM循环。

SoC系统寄存器：软件认识硬件的第一张表

0x03000000 + 偏移作用使用边界
0x00..3cscratch0..15并非全是自由暂存：启动/多hart/退出协议占用低几个槽
0x40 BOOT_MODE板级/fixture启动选择读到模式不证明相应设备模型或介质存在
0x44 RTC_FREQRTC频率声明clint_get_core_freq据此测核心频率；声明错会连带UART/I2C/SPI错误
0x48 PLATFORM_ROM平台ROM入口非零时Boot ROM调用平台代码；须核实映射与返回契约
0x4c NUM_INT_HARTS内部hart数量驱动同步/所有权依此重新设计；教材例限定单hart
0x50 HW_FEATURES配置能力位确认IP是否生成；不能替代pin/clock/model验收，也没有一个位包办RVV profile
0x54 LLC_SIZE物理容量不等于当前所有way都已配置SPM
0x58 VGA_PARAMSRGB位宽解释frame buffer格式，不能推导时序分辨率

scratch2写 (return_code<<1)|1 表示结束，bit0是完成；外部被动启动用scratch1:0拼64bit入口，scratch2的掩码2（bit1）请求启动。ROM注释有“bit2”“scratch1是start”的旧说法，但执行表达式是 scratch[2] & 2，这里按代码解释。scratch4/5在boot_next_stage中广播入口，多hart暂停/恢复还占用其他协议槽，不能随意拿来调试。

reset之后：先建立能运行C的环境

cheshire_bootrom.S 清寄存器、暂停其他SMP hart、设安全栈/gp；若有LLC，等待BIST，再把CFG_SPM设全1、提交，按LLC_SIZE把栈移到SPM尾部。随后可能调用平台ROM，再进入ROM的C代码。应用 crt0.S 是第二段启动：设置trap向量、gp/栈、清BSS、初始化FS和FP寄存器、调用main、编码退出码。

模式0是被动装载：ROM服务UART debug或等待scratch启动。模式1为SD、2为SPI NOR、3为I2C EEPROM，设备HAL通过 gpt_boot_part_else_raw 找启动分区/处理raw回退，把下一阶段搬到SPM。tb_cheshire_soc对模式1直接fatal，因为其当前测试环境不支持SD启动。设备驱动源码存在不等于该TB支持它。

ELF直接装载根据PT_LOAD地址复制段，并按entry运行；Flash/GPT镜像由ROM读设备协议和介质布局。把ELF原文件按字节烧进Flash并不能自动得到相同启动效果。原 sw/boot/flash.c 是会改介质的工具，不作为本轮学习自动执行项。

JTAG / Debug Module：两种总线角色、两类地址

JTAG DTM（Debug Transport Module，调试传输模块）在TCK域处理调试协议，通过DMI（Debug Module Interface）连接系统域的DM。DM含控制/状态寄存器、abstract command执行和SBA（System Bus Access，系统总线访问）。SBA是AXI发起者，可在hart停止时读写内存；DM还有供hart进入debug mode执行的ROM/数据目标窗口，两个方向不能合并成“一个调试端口”。

DMI地址（不是CPU MMIO偏移）寄存器VIP用法
0x10 / 0x11DMCONTROL / DMSTATUSdmactive、haltreq、resumereq；轮询allhalted/状态
0x04 / 0x05DATA0 / DATA1abstract command的数据/entry低高字
0x16 / 0x17ABSTRACTCS / COMMAND检查busy/cmderr；VIP命令写DPC使执行入口改变
0x38SBCSSBA宽度、自动增址/触发策略及错误状态
0x39 / 0x3aSBADDRESS0 / 1要访问的系统物理地址
0x3c / 0x3dSBDATA0 / 1搬运ELF字节到内存；触发顺序按VIP实现

VIP JTAG路径的真实顺序：reset释放 → 等ROM完成LLC/SPM初始化 → 请求halt hart0并确认 → DPI解析ELF → SBA写内存 → 写DATA/COMMAND改变DPC → resumereq → 轮询scratch2。它不是往scratch1:0写entry的被动启动路径。Serial Link则借远端AXI把entry和启动信号写入scratch；UART debug用自定义READ0x11/WRITE0x12/EXEC0x13协议与ROM交互，不能等同OpenOCD/JTAG。

现有loader还有段尾检查缺口。

jtag_elf_preload按8字节写，循环条件是i<=sec_len，并索引bf[i+7]；对整段边界/非8倍数段需独立验证，不能因打印Preload complete就认为装载没有越界。后续最小单元用例：1/7/8/9字节段、BSS、相邻段、入口与装载区守卫读回。此问题原入门证据页已列，仍未修复。

外部存储：TB与MIG分别证明什么

默认UseDramSys=0时fixture用AXI行为内存；它可验证系统总线和软件地址语义，但不模拟真实DDR PHY训练/刷新/板级信号完整性。FPGA wrapper使用MIG、宽度/ID转换和CDC；VCU118只送低31位DRAM地址，SoC地址0x80000000对应控制器低地址0。LLC外部窗口大小不等于开发板可用物理容量，访问上界必须结合wrapper译码与器件规格。

未来外购AXI4 DDR需要重新定义时钟/复位/ready、地址容量、最大burst/outstanding、ID响应顺序、ECC/错误与软件内存属性。不能把MIG实例名替换一下就称为ASIC支持；也不能拿旧FPGA filelist当工艺SRAM/PLL/PAD清单。

1. JTAG修改DPC与写scratch启动是否重复？

它们是不同路径：JTAG在halt状态改变调试PC并resume；Link/UART借ROM协议跳转。不能混写到同一时序图而不说明分支。

2. 链接成功但SPM不可用可能卡在哪里？

ROM的LLC BIST/SPM配置或栈初始化可能尚未完成；也可能Cfg.LlcNotBypass关闭后失去SPM存储。先看reset/ROM PC和配置状态。

3. 为什么外部内存行为模型通过不是DDR验收？

它没有证明PHY训练、真实频率/时序、刷新、引脚、电源以及板级容量等物理条件。
