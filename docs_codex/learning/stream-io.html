本章任务

分别追踪一次远端写读、一帧像素输出和一次 USB 控制传输。三者共享系统存储，但协议和完成条件各不相同。

19.1 Serial Link 的远端访问

本章的链路是相同协议两端间的 AXI 延伸，可连接另一个集成兼容 Serial Link 的 SoC/验证对端；不是 UART、PCIe 或任意串口模块，当前没有经确认的外部商用器件型号。最小任务是在对端已预约 RAM 中写一个字，再读回同值。

19.1.1 分层与远端 AXI

Serial Link 是把 AXI 通道封装到串行链路的模块，和 UART 的字节终端协议不同。network 层组织请求/响应，data_link 层处理流控，physical 层用源同步双沿数据传输。远端访问既有请求又有返回，链路内部要保存队列状态并处理背压。

Cfg.SerialLink 控制实例。当前生成常量为 1 channel、NumBits=8，对应 4 个双沿 lane；地址窗口 0x1_00000000..0x1_ffffffff 按 mask=0xffffffff、domain=0 映射到对端低 32 位。接收侧又作为本地 AXI 发起者访问本地存储，因此配置口、远端目标口和本地发起口要分别理解。

SoC 的 slink_rcv_clk_i 和 slink_i 接收对端发送时钟/数据，slink_rcv_clk_o 和 slink_o 输出本端源同步时钟/数据；本地生成配置是一组4位双沿 lane。两端收发交叉相接，电平/PAD/走线由平台落实。这里是 Link 的专用数据线，不能因为名称 serial 推出 LVDS 电气规范。当前 clk_i、clk_sl_i、clk_reg_i 都接系统 clk_i，复位都接低有效 rst_ni，不额外虚构异步域。

19.1.2 Serial Link 的发送时序配置

控制基址 0x03006000，Reg32；CTRL(+0) 含 enable/reset/isolate 控制意图，ISOLATED(+4) 为状态，TX_PHY_CLK_DIV/START/END(+8/+c/+10) 默认8/2/6用于转发时钟。CTRL寄存器字段复位值为clk_ena=0、reset_n=1、两isolate=1，RAW_MODE=0；这描述寄存器意图，当前实例未接出的控制不能据此解释成真实隔离。RAW_MODE 和收发 FIFO 用于原始模式专门测试，正常 AXI 保持正常模式。当前系统未接成隔离闭环，不能用 CTRL 完成安全停止；具体连接限制。

19.1.3 Serial Link 写读流程与加载实例

这是机制步骤例：先确认双端复位释放、相同链路时序及远端 RAM 预约，再在本地远端窗口写入一字。AXI AW/W 经链路送达远端，远端存储接收后 B 返回；接着发 AR，R 把同地址内容带回，比较字值。结束前双方停止新请求并排空已发事务。地址窗口会去掉高位域映射到对端，不能把同一数值随意当作本地 RAM。没有在此捏造控制器 C HAL。

现有可追踪实例是 VIP 的 PRELMODE=1 ELF 加载、scratch 入口通知及 [SLINK] 结束，见被动加载协议；这是主机/VIP 访问流程而非目标应用库。fixture 有兼容 Link 对端，VCU118 当前输入绑常量、输出未接；板端步骤待真实链路。check_run 目前只接受 JTAG，Link 结果需独立验收，不能套用其成功判据。

19.2 VGA 帧缓冲与像素输出

VGA 面向按同步节拍取像素的显示端。本工程数字输出是 RGB565 与同步信号，接传统 VGA 模拟显示器还需适当 DAC/电阻网络和匹配电平；未确认板载显示器或转换器型号。本章用已知彩条帧解释取数和显示，不提供虚构的现成显示驱动。

19.2.1 取帧、队列与像素输出

VGA 控制器的 fetcher 通过只读 AXI 发起口从帧缓冲取数据，队列和 credit 协调取数，timing FSM 生成可见区和消隐同步。显示消费像素有固定节奏，存储服务停顿过久会造成欠载，因而平均带宽和最长等待都影响输出。

19.2.2 VGA 参数与关键寄存器

Cfg.Vga 选择实例；当前 RGB 位宽为 5/6/5，共 16 位，横纵计数宽为 24，BufferDepth=16、MaxReadTxns=24。寄存器基址为 0x03007000：CONTROL(+0) 启用及同步极性，CLK_DIV(+4) 生成状态机使能（0 按 1 处理），水平/垂直时序在 +8..+0x24，START_ADDR(+0x28/+0x2c) 是帧起点，FRAME_SIZE(+0x30) 是字节数，BURST_LEN(+0x34) 直接进入 ARLEN。

本地VGA HJSON规定enable复位0、CLK_DIV复位1、帧起点和FRAME_SIZE复位0；所以复位后还没有可显示的帧。系统 clk_i/rst_ni 驱动控制器，复位低有效；CLK_DIV 产生内部像素使能，不是独立 PLL。RGB 输出5/6/5位，HSYNC/VSYNC为输出，同步极性按模式配置，无像 I2C 那样的双向数据使能。帧缓冲必须经当前 AXI 路径可达；新画面发布前完成可见性交接。

19.2.3 初始化与帧缓冲预算

软件先 disable，准备设备可见的帧缓冲，写时序、分频、起点、字节数和 burst，排序后 enable。16 拍 burst 编码为 15。640×480 RGB565 一帧需要 614400 字节，超过默认 SPM；60 帧/秒仅可见像素读取就约 36.864 MB/s。消隐、突发效率和内存延迟还要另留余量。

19.2.4 VGA 输出与结果观察

条件步骤例：禁用取数，准备彩条 RAM，写时序/分频/起点/字节数和 ARLEN=15，排序后使能；fetcher 持续读帧，FIFO供给像素，计数器到行末进入消隐、到帧末回卷。检查至少两帧的 HSYNC/VSYNC 周期、RGB 顺序和地址回卷，再停止新取数并等待在途读取排空后复用 RAM。FRAME_SIZE 是字节数，不是像素数；控制写返回不是一帧完成。

当前没有本教材现成帧校验器或完整 C HAL；fixture 输出悬空，VCU118 未启用 USE_VGA。这里只能按 RTL/寄存器理解流程，显示运行待模型或板级条件。中断中的 VGA BusErr 是错误提示，不是帧完成 IRQ；尺寸限制见诊断入口。

19.3 USB OHCI 控制器与传输任务

USB host 管理连接的设备，OHCI 定义软件怎样描述工作。可以用“读取设备描述符”理解最小控制传输：向端点0发送 SETUP 请求，接收描述符字节，再完成状态阶段。本工程没有经过验证的 USB 设备型号、设备模型或完整枚举栈，下面是依赖 PHY/软件栈补齐的机制例。

19.3.1 描述符和 DMA

OHCI 是主机控制器的软件接口，软件在 RAM 中建立 HCCA（主机通信区）、ED（端点描述符）和 TD（传输描述符）。控制器经 DMA 读取任务，用 PHY（物理收发接口）传包，更新完成描述符并发中断。枚举设备还需要端口复位、控制传输、地址分配和描述符解析的软件流程。

Cfg.Usb 选择实例，UsbDmaMaxReads 默认 16，生成包 NumPhyPorts=4。spinal_usb_ohci 将 Reg32 转控制 AXI32，再把 32 位 DMA 数据口转换到 SoC 位宽；DMA 原生地址 32 位，按 UsbAddrMask/Domain 扩展，默认 domain=0。系统域与 PHY 域有独立时钟复位，描述符应放在实际可达且满足对齐的范围。

19.3.2 寄存器、状态和对齐

控制基址 0x03008000：HcRevision(+0) 返回版本，HcControl(+4) 管列表使能和 HCFS 状态，HcCommandStatus(+8) 提交复位/新任务提示。InterruptStatus/Enable/Disable 在 +0xc/+0x10/+0x14，WDH、UE、RHSC 分别表示完成链、不可恢复错误和根集线器变化。HCCA(+0x18) 保存 256 字节对齐基址，Control/Bulk ED 与 DoneHead 在 +0x20..+0x30。

以 SoC 为参照，usb_dp_i/dm_i 为各端口实际输入，usb_dp_o/dm_o 与 usb_dp_oe_o/usb_dm_oe_o 为输出及使能，端口数4；最终 D+/D− 双向连接需要相应 PHY/PAD、电气终端和 host VBUS 供电管理，不能把逻辑端口直接当成完成的板级 USB。系统 clk_i/rst_ni 与 usb_clk_i/usb_rst_ni 分别服务控制和 USB 域，低有效复位。当前 fixture 后一时钟为0、复位输入为1；这不是可运行收发环境。

19.3.3 USB 描述符准备与数据接收

先保证 PHY、端口电源和时钟有效，控制器软复位后读 Revision 确认控制通路；软件在32位DMA可达区准备256字节对齐 HCCA、对齐ED和TD，设置帧调度与根集线器。端口连接并复位到可通信状态后，排入 SETUP/DATA/STATUS 的控制列表并开放调度。DMA读描述符、PHY传包，控制器把状态及实际长度写回完成链；CPU收到WDH提示后按所有权协议取回TD，检查条件码、长度和描述符内容，才算读取成功。

这里没有真实 API 名可供调用：仓库有硬件 wrapper/寄存器实现，但无完整裸机枚举库。本地OHCI软复位路径清列表使能、MIE及HCCA/列表头等状态，软件显式初始化后才能开放调度。HcControl/列表基址是配置，HcCommandStatus写入有动作语义，InterruptStatus按实现清状态；使用32位控制访问，寄存器与设备返回的USB描述符属于不同空间。重复初始化会影响全部端口与列表，必须由统一host管理者调度；回收前停止新列表工作并确认设备不再访问这些描述符。

19.3.4 USB 示例的执行条件

控制域寄存器可读只证明一个层次。本例需USB时钟、PHY、设备模型或板级设备及host软件；目标验收为描述符内容/长度正确和正常任务回收。当前VCU118关闭USB；详细未决和症状见USB诊断。

19.4 三类设备的验证重心

Link 应观察远端请求与响应的归属及链路流控；VGA 应观察有期限的像素消费和帧内容；USB 应观察描述符生命周期、包协议和端口状态。它们都复用共享数据章的所有权原则，但完成事件来自各自协议。把寄存器读写、主动访存和外部行为分别验收，才能确认缺的是哪一层。

19.5 链路、显示与 USB 的完成语义

Link 以远端响应和读回内容结束一项操作；VGA 正常运行连续消费帧，没有一次提交对应一次通用 done；USB 以完成链中的条件码和长度回收描述符。三者的寄存器均通过Reg32控制，Link字段见group-8，VGA见group-9；当前索引未生成OHCI组，USB字段回到实际RTL寄存器译码。新增设备应先补实际连接和任务接口，再声称支持某型号；调试统一从诊断章进入。
