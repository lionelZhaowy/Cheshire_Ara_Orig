本章任务

配置章已经确定发起者和目标。本章解释请求如何到达目标、响应如何返回，以及适配器保存什么状态。读完能为新增端口、位宽转换与跨域连接设计有针对性的验证。

五条通道与一次传输

AXI 是本工程的内存映射互连接口。读事务用 AR 传地址、R 传数据和状态；写事务用 AW 传地址、W 传数据、B 返回状态。每条通道有 VALID 和 READY：发送端准备好有效内容后置 VALID，接收端能接收时置 READY，二者在同一个时钟边沿为 1 才完成这一拍。接收端暂时拒收形成背压，发送端需保持 VALID 和对应内容，不能等到 READY 才首次提出 VALID。

一笔请求可以包含多个数据拍，称为 burst。LEN 编码拍数减一，SIZE 编码每拍字节数的二进制对数；WSTRB 逐位指定有效写字节，LAST 标记最后一个数据拍。ID 标记事务身份，让同时在途的请求和返回能够关联；BRESP/RRESP 携带成功或错误状态。

发送方可以先提出 W，也可以 AW 和 W 错开到达。AW 握手表示接受地址，W 最后一拍握手表示数据传完，B 握手才结束写响应。这个区别决定了何时能释放路由状态，也决定了设备报告任务完成前要等待哪些响应。

按图逐拍检查：AW 等待时地址/ID 不变；第一拍 W 等到 WREADY 才推进；第二拍即使已经 LAST，也必须等自己的握手；BVALID 后若 BREADY 尚未开放，响应继续保持。一个验证器应同时检查稳定性、拍数、LAST、ID 和响应，不能只计 AW 次数。规范语义参照 Arm AMBA AXI 官方资料，本地队列行为以源码为准。

两级地址译码

Crossbar 是多发起者到多目标的交叉互连。各输入先根据 AW/AR 地址选择目标，目标端再仲裁不同输入。CPU 访问 UART、DMA 访问主存可以走不同目标；二者访问主存时需要竞争目标资源。返回方向根据保存的归属和 ID 回到发起者。

当前第一层把 [0x02000000,0x0c000000) 路由到寄存器桥。桥转换协议和位宽后，第二层再次译码，选出 UART 的 [0x03002000,0x03003000) 等窗口。区间含起点、不含终点。关闭 UART 后，该地址仍可到第一层桥，随后在第二层进入错误目标。

本地译码对重叠规则采用高下标优先，新增窗口应消除意外重叠。第一层不匹配通过 AXI 错误目标返回 DECERR；Reg 层不匹配经 i_reg_err_slv 返回 error 和错误数据 0xBADCAB1E。错误也需要完整应答：写事务仍要接受规定的数据，读 burst 仍需完成相应返回拍。

Crossbar 内部保存的事务状态

axi_xbar_unmuxed 为输入配置译码和 demux（分流器），axi_xbar 在每个目标配置 mux（汇聚仲裁器）。mux 给请求 ID 添加来源编号。例如原 ID 两位、两个来源时，来源 0 的 ID=01 变为 001，来源 1 的同号 ID 变为 101；响应按前缀分送，再恢复原 ID。

AXI4 的 W 没有 WID，所以 mux 需要记录已接受写地址的来源，demux 需要记住目标。若 CPU 的 AW 已选中，后续这个 burst 的 W 都应来自 CPU。W 来源 FIFO 直到 WLAST 真正握手才推进，写响应跟踪继续等待 B。W 可以早于 AW 提出，本地互连会在路由条件未建立时对其背压。

同一个输入的同方向、同 ID 请求还要保持顺序。假设先访问慢目标 A，再访问快目标 B，直接全放行可能使 B 先返回。本地 demux 用“ID 对应目标 + 在途计数”限制跨目标切换。减少用于跟踪的 ID 位会增加别名冲突；UniqueIds 是对发起行为的约束，本 SoC 配为 0。带 ATOP 的写请求还可能产生读返回，跟踪时需考虑这种跨通道关系。

当前 Crossbar 使用 CUT_ALL_PORTS、FallThrough=0、PipelineStages=0，MaxMstTrans/MaxSlvTrans 均为 24。cut 保存协议拍和有效状态，以分割组合路径；这些深度分别控制不同资源。IP 暴露内部 PipelineStages 参数，同时本地设计说明记录了内部切分的写通道死锁风险；调整时应检查依赖关系并运行长背压场景。

位宽、协议和 ID 转换

64 位总线的一拍有 8 个字节位置，称为 byte lane。访问地址 +4 的对齐 32 位寄存器时，SIZE=2，有效数据位于高四个 lane，完整写使能通常为 0xf0。例如 0x11223344 在总线上可呈现为 0x1122334400000000。桥接到 32 位目标后，应得到数据 0x11223344、使能 0xf；单纯截低 32 位会丢失此次写入。

宽转窄还可能把一个输入数据拍拆成多个输出拍，调整长度与 LAST，并重新组装读返回。对齐 INCR 的 4×64 位全宽数据是 32 字节，转成 32 位需要 8 拍；窄访问、部分写和非对齐请求按转换器支持范围分别验证。4 KiB 边界、错误响应、在途容量和原子扩展都属于转换契约。

Regbus 把一次寄存器请求合成 valid/write/addr/wdata/wstrb，响应含 ready/rdata/error。普通 MMIO 使用 i_reg_atomics → cut → axi_to_reg_v2(RegDataWidth=32) → reg_demux。协议转换把分离的 AXI 通道恢复成一次寄存器访问，副作用在成交时触发。iDMA 控制口采用另一条旧桥，第 12 章会分析它的宽度缺口。

CPU 原始 ID 为 4 位，经 axi_id_serialize 适配成系统输入的 2 位，再由 Crossbar 扩展来源位。缩窄需要映射、队列和并发约束，直接丢高位会混淆返回。ATOP 是 AXI4 之外、来自 AXI5 的原子操作扩展，当前主存原子单元在 LLC 上游处理相应语义，下游普通 AXI4 DDR 按这个接口边界接入。

跨时钟与复位边界

跨时钟域传输（CDC）面临两端采样时刻不同的问题。单比特状态可采用适当同步结构；整组地址或数据若逐位同步，可能把不同时刻的位拼在一起。AXI CDC 通常用异步 FIFO 保存数据，通过同步后的指针表达队列占用，并维持各通道关联。FPGA DDR wrapper 使用实际的 axi_cdc 实例。

复位跨域（RDC）还涉及事务生命周期。目标已接受 AW、尚未返回 B 时，单独复位目标会让上游永久等待。系统需约定停止新请求、排空或隔离、复位、重新初始化和恢复服务；对端不再响应时还需定义有界恢复。这也是未来 DDR 就绪与设备时钟门控要共同设计的部分。

由修改影响设计验证

新增发起端时，用两个发起者的相同 ID 同时访问，检查返回归属；修改路由时，检查窗口首尾和未映射地址；修改位宽时，覆盖 +0/+4、部分 WSTRB、长 burst 和错误响应；修改流水或 CDC 时，错开 AW/W 并持续背压 R/B，停止激励后检查排空。同 ID 先慢后快目标能检验顺序限制。

排查时沿一笔事务记录输入握手、译码目标、下游握手、返回握手四个位置。VALID 长等可能来自目标未就绪、队列已满或 ID 冲突，应指出具体等待资源。独立教学 Reg 单元将在第 15 章验证副作用契约；生产 Crossbar 的动态回归仍需专门执行。

CPU 的 cached、executable、non-idempotent 属性是另一组规则，不等于 Crossbar 译码。本地低 SPM 和主存可缓存；高 SPM 用作非缓存数据别名。当前执行属性把低 SPM 从起点覆盖 2×SizeSpm，即默认到 0x10040000，超过实际低窗口，且不包含高别名；多出的属性范围不会创造 RAM。调试/ROM/主存另有执行规则，设备空间按非幂等处理。生成地址、PMA 属性、链接脚本三者应逐项对照。

Regbus 的最小设备契约

Regbus 在 valid 与 ready 同时成立的边沿完成一次访问。等待期间 addr/write/wdata/wstrb 保持；读数据和 error 与该成交关联。没有独立地址/数据队列时，设备不得把持续多周期 valid 当成多次写。W1C 只清被选中字节中的 1 位，命令寄存器每次成交只触发一次，读弹出只能在读成交时发生。

/* 教学契约：clear_mask 由本次处理的事件产生，不把整个旧状态写回。 */
mmio_write32(base + INTR_STATE, clear_mask);
/* start() 先验证 idle 和参数，再写 START；写响应仅代表寄存器成交。 */
/* 等待 COMPLETE/ERROR + 有界计时，读取结果，最后归还 buffer。 */

这个小接口仍需验证 byte-enable、RO/WO/W1C、非法偏移、背压、复位中断及请求稳定性。独立教学设备展示可执行契约，DDR/NPU 的控制寄存器则必须来自实际 IP 规范。
