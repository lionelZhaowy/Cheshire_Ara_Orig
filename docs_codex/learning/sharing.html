26.1 缓冲区所有权与可见性

缓存一致性关心同一地址的多个副本，内存排序关心访问先后，原子性关心操作能否被其他访问打断。三者分别建立契约。CPU 交出缓冲区时，要确保设备能看到刚写的内容；设备完成后，CPU 重新取得所有权时要确保不会继续读旧副本。

一种容易验证的方案是独占共享区域，所有相关路径采用已确认的非缓存属性，配合提交和完成前后的排序。若保留缓存，则 CPU 交出数据前需要可用的 clean/排空流程，收回数据前需要必要的 invalidate；这些操作必须覆盖实际缓存层级。volatile 和 fence 分别约束编译器与顺序，无法独自完成上述缓存维护。

后续 RVV 小实验独占物理 SPM [0x10010000,0x10011000)，CPU 只通过高别名访问 a/b/c，分别从 0x14010000、0x14010400、0x14010800 起，每个使用 548 字节并加守卫。要求单核、全 128 KiB SPM、应用静态区位于低 64 KiB、栈始终高于 0x10011000，期间不切 way、不混用低别名。这个预约是教材示例条件，并未修改生产地址图。

26.2 当前 CPU/Ara 协作覆盖到哪里

26.2.1 当前 CPU/Ara：WT、pending 与失效通知

当前向量 profile 使用 WT L1D；写穿仍保留读副本和待排空写缓冲。CPU 的 CSR_ACC_CONS（0x7c2，bit0）在加速器启用时复位开启。acc_dispatcher 根据标量 store_pending、向量 load/store pending 与 barrier 协调访存，Ara 写地址经过 axi_inval_filter，按 CPU cache line 生成失效请求，并以 inval_ready 接收背压。过滤器保存已接受的 AW 范围；队列不足会反压写地址。

这套机制覆盖接入该专用协议的 CPU/Ara 组合，不自动覆盖 DMA、USB、Link 或未来 NPU。关闭一致性 CSR、改 profile、改地址别名或绕开失效过滤，都改变其前提。失效是控制动作，真正的写数据还要经 W/B 排空；精确的后继观察点依赖 pending 和排序。Ara VRF 是显式寄存器状态，NPU 只能通过约定内存交换其中存出的数据。

26.2.2 Ara VRF、缓存与 NPU 共享张量

向量寄存器文件（VRF）保存 v0…v31 的架构状态。指令中的寄存器编号选择它们，不是 AXI 地址；当前 SoC 没有让 NPU 通过系统总线寻址 Ara VRF 的窗口。即使 VRF 物理实现使用 SRAM，也不意味着它就是 NPU 可以直接访问的共享 SRAM。缓存则按内存地址保存副本，软件管理的共享缓冲区又是第三种对象。

假设 Ara 负责归一化，NPU 负责后续矩阵乘：Ara 先从共享内存加载一块输入，在 VRF 中计算，再把结果存回约定缓冲区；完成可见性交接后，CPU 为 NPU 提交该缓冲区的物理地址、尺寸和布局；NPU 读取并计算，输出完成后再交回 CPU/Ara。两者交换的是约定地址处的张量，不是“借用对方缓存”。

如果分析表明这些存回/重读占用过多带宽，可考虑直接流接口或专用共享 SRAM，但这会增加数据格式、背压、队列、复位和异常恢复的硬件契约。先用下表选择存储策略，再用所有权状态机定义交接；不能只增加一根数据连线就宣称异构共享完成。

26.2.3 共享存储方案的选择条件

候选交接方式适用范围与收益必须建立的条件
共享 SPM / 专用 SRAM小块或分 tile；低延迟，容易界定所有权容量扣除代码/栈/队列，所有使用者看到同一物理字节；CPU 不留缓存别名副本，NPU 有可达端口
DDR 的非缓存缓冲较大张量；避开 CPU/LLC 副本可降低维护复杂度CPU 与 Ara 实际路径也绕过或按有效策略不分配 LLC；仅 CPU PMA 非缓存不足以证明 LLC 不缓存
DDR 缓存缓冲 + 维护CPU/Ara 反复使用局部数据可能获益经过验证的 L1/LLC clean、invalidate、排空及错误处理；不得假设当前 profile 已有可直接调用的标准 CBO 指令
直接流接口 / 一致性接口可减少中间往返，适合稳定数据流或大量细粒度共享新增 backpressure、缓冲、格式/序号/复位协议；一致性还需 snoop、排序与原子机制，验证成本明显增加

26.2.4 Ara 写入与 CPU 观察

Ara 写路径通过 axi_inval_filter 向 CVA6 L1D 发失效通知，受 acc_cons_en 控制，并根据实际 L1 行宽处理。此组合的 CvxifEn=0，端口中的 cvxif 名字承载专用 accelerator 协作，不能据名当作任意 NPU 通用插槽。其他 DMA 发起者没有自动加入这条 Ara 路径。

实验 E 使用实验 E 约定的独占非缓存 SPM 缓冲，不混用低别名，并在提交前后排序。它要求单核，并检查 LLC_SIZE=131072，三个槽各有一个尾部守卫，计算后把 c 的有效元素复制到全局 result，继续使用相同公式和总和校验。全 SPM way、栈边界与独占条件仍需由启动和布局保证，运行时读容量只覆盖其中一部分。

26.3 从取得缓冲区到交还缓冲区

软件分配器维护所有权表：FREE → PRODUCER → PUBLISHED/QUEUED → CONSUMER → RECLAIM → FREE。生产者取得唯一写权限后填充数据；publish 操作确保已定义范围对消费者可见，然后写描述符并通知。消费者取得匹配的任务/epoch 后读取并计算，在输出写响应排空之后报告状态；CPU 校验完成令牌、执行 acquire 所需的排序和失效，再允许后继 Ara 使用。最后一位使用者释放缓冲区。

26.3.1 地址、布局、所有权与完成元数据

元数据维护者与检查
物理地址、长度、容量、对齐分配器提供，驱动做溢出/范围/可达检查，设备拒绝非法描述符；虚拟地址不能直接冒充 DMA 地址
维度、stride、布局、量化类型与 scale/zero-point模型调度器和算子接口约定，描述符携带格式版本；生产者和消费者使用同一版本
所有权、buffer ID、epochCPU 软件任务表维护；epoch 区分复用后的新任务，设备回传同一身份
完成、实际长度、错误码设备在写排空后发布；驱动读状态确认，中断只是提示
deadline、取消、隔离与回收驱动/系统管理器执行；超时不得立即复用仍可能被写入的 buffer

26.3.2 旁路写与缓存副本

如果 NPU/ISP 绕过 LLC，而 CPU/Ara 仍经 LLC 读同一 DDR 地址，即使 CPU L1 无副本，LLC 也可能返回旧行；若旧行脏，稍后写回还会覆盖设备新数据。非缓存高 SPM 别名只解决其预约片上区域的特定路径，不能直接用于 DDR。缓存行共享还会让无关 CPU 字段被整行失效或写回，应按真实行大小隔离描述符、状态与数据。

26.3.3 AMO 与 LR/SC 的观察边界

原子性另有边界：当前 AMO/LRSC 处理在 LLC 上游；NPU 的普通旁路写若不被 reservation 监视器看到，CPU 的 SC 可能错误地成功。把原子单元移到 DDR 入口也未必能看到 CPU 的缓存命中或所有副本。初期可规划严格隔离的原子控制区和单写者邮箱；若需求确实要求跨设备共享原子数据，必须设计所有访问者共同遵守的监视/一致性协议并注入竞争写验证。

DMA 不发原子指令，普通旁路写还会影响 LR/SC 吗？

会。LR/SC 的保留状态必须能观察相关地址的竞争写；绕过上游监视器的普通写同样会破坏预期共享原子语义。
