本章任务

上一章已在主机得到 ELF。本章把“主机准备字节”和“目标复位执行”画成两条时间线，说明当前 testbench 如何让它们汇合。读完能解释 _start、main、UART 输出和退出，为下一章实际运行定位阶段。

主机与目标的两条时间线

主机可以在启动模拟器之前完成软件构建。目标 CPU 的复位逻辑只知道 BootAddr，默认指向 0x02000000 的 Boot ROM；它不会自行读取主机路径里的 ELF。仿真启动后，VIP 先提供时钟和复位，ROM 开始执行，另一边的加载任务等待目标存储达到可装载状态。两条时间线在装载和入口交接处汇合。

ROM 先建立可用的片上环境

cheshire_bootrom.S 等待 LLC 内建自测（BIST）完成，设置 CFG_SPM 的 way 位图并提交配置。默认 8 个 way 全部作为 SPM。随后用 LLC_SIZE 把早期栈放到阵列高端，128 KiB 时相应早期 sp 为 0x1001fff8；后续启动汇编还会调整它以建立调用上下文。平台 ROM 若被配置，则按源码约定调用。

Boot ROM 的 C 代码负责启动策略。模式 0 提供被动加载服务，模式 1/2/3 分别访问 SPI SD、SPI NOR 和 I2C EEPROM。JTAG VIP 等待 LLC 的 SPM 配置标志后就请求 halt，因而主线无需假设 ROM 的 C main 已执行完。删除 LLC 或改变其阵列容量会同时改变这里的启动存储和栈条件。

JTAG、Debug Module 与实际装载

JTAG 是调试传输链路。DTM 在 JTAG TCK 域接收调试操作，再通过 DMI 接口访问系统域的 Debug Module（DM）。DM 可以停止/恢复 hart（一个硬件执行线程），执行寄存器访问命令，还能通过 SBA，即系统总线访问，主动读写目标内存。DMI 地址属于调试协议空间，不是 CPU 的 MMIO 地址。

TB 从 +BINARY 取得主机 ELF 路径。C++ 的 elfloader 通过 DPI（SystemVerilog 与 C/C++ 互操作接口）向 VIP 提供 entry 和装载段：用 p_paddr 作为地址，从文件取 p_filesz 字节。VIP 请求 hart0 停止，写 SBADDRESS/SBDATA，DM 便发出 AXI 事务，经过互连写入 SPM。这条路径可以检查真实总线应答。

装载后，VIP 通过 DATA 和 COMMAND 写 DPC（调试状态中的恢复执行地址）为 ELF entry，再发 resumereq。应用开始从 _start 执行。常用 DMI 位置是 DMCONTROL/DMSTATUS=0x10/0x11、ABSTRACTCS/COMMAND=0x16/0x17、SBCS=0x38、SBADDRESS0=0x39、SBDATA0=0x3c；排查时还要观察 busy 和错误状态。

当前 loader 对 p_memsz 大于 p_filesz 的部分打印未补零提示，应用 BSS 仍由 crt0 清零。JTAG 写段循环为 i <= sec_len 且按 8 字节步进，最后一次索引/写入存在段尾越界风险。这是源码检查发现，尚未动态复现或修复；目标环境应以 1/7/8/9 字节段、相邻段和守卫区读回做专项验证。

应用启动代码建立 C 环境

应用 crt0 首先关闭 M/S 全局中断并停住非零 hart。机器态（M）、监管态（S）和用户态（U）是 RISC-V 的权限层级，本书沿机器态裸机路径。crt0 根据非零栈符号决定是否换栈，建立 gp（访问全局数据的辅助指针），保存进入时上下文，再把 mtvec 设为异常入口。

接着清除 __bss_start 到 __bss_end，把 result 等零初始化对象置零；设置 FS 并初始化浮点寄存器，然后 fence 并 call main。即使 C 只做整数运算，当前原始 crt0 仍执行双精度浮点指令，所以本例要求 F/D 硬件。VS 未在原 crt0 统一设置，向量变体由标量 main 在调用向量函数前开启。

异常是当前指令引起的事件，如非法指令或访存失败；中断是计时或设备等异步事件。两者统称 trap。CPU 把原因和位置记入 mcause、mepc、mtval 等 CSR，并跳到 mtvec。当前弱 trap_vector 是自循环，故“无输出”也可能是 main 之前已陷入异常。中断章会加入保存现场和返回流程。

系统寄存器参与初始化与结束

SoC 寄存器位于 0x03000000。它们向软件提供硬件信息，避免把某个平台频率硬编码进每个应用。RTC_FREQ（+0x44）供 CLINT 测频使用；NUM_INT_HARTS（+0x4c）报告核数；HW_FEATURES（+0x50）报告配置能力；LLC_SIZE（+0x54）报告阵列容量。容量和当前 way 用途需分别查询，硬件能力位还需结合引脚、时钟和设备模型理解。

scratch0..15 每项 4 字节，低几个槽承担启动交接。主线程序读取 RTC_FREQ，用 RTC 与 mcycle 测系统频率，再配置 UART。printf 把结果变成字符，经 _putchar、uart_write、MMIO 写到 UART，VIP 采样串行数据并在换行后输出日志。返回前调用 uart_write_flush，确保末尾字符发完。

main 返回值在 a0，crt0 的 _exit 把 (返回值 << 1) | 1 写到 scratch2（+0x08）。VIP 观察 bit0，右移得到返回码；0 输出 [JTAG] SUCCESS，非零输出 FAILED。源码注释写 wait forever，而实际末尾是 ret；验收应以完成寄存器和日志为准。这个协议相当于测试环境的程序结束通知，不是操作系统的 exit 服务。

Serial Link、UART 与自主启动

PRELMODE=1 通过 Serial Link 远端 AXI 装载，再把 64 位入口写到 scratch1:0，向 scratch2 写掩码 2。ROM 的被动轮询看到 bit1 后调用 boot_next_stage。源码某些注释把该掩码误称为 bit2，本书按实际表达式解释。PRELMODE=2 则使用 ROM 的 UART 二进制调试服务，READ/WRITE/EXEC 命令为 0x11/0x12/0x13；这与终端发送 ELF 原文件不同。

自主启动没有主机 loader 替 ROM 解析 ELF。ROM 使用设备 HAL 读介质，gpt_boot_part_else_raw 检查 GPT 分区表并选载荷，或采用 raw 区间，然后复制到 SPM、跳到下一阶段。GPT 描述介质分区，裸机也可使用。当前初级载荷上限为 96×512=48 KiB；rom.ld 给连续载荷提供 SPM 运行、外部镜像装载的布局。镜像格式、内容位置和入口必须与此流程匹配。

根软件的通用裸机 GPT 打包规则已注释，ROM 的 GPT/raw 解析仍在；当前 TB 明确拒绝 BOOTMODE=1 的 SD 启动。NOR/EEPROM 自主启动依赖相应模型镜像，和 ELF 直载分开验收。板级 OpenOCD/GDB 流程还取决于探针及连接配置，应沿用已确认的下载方式；本章不执行板卡或介质写入。

每条启动路径的入口、搬运者与失败点

共同起点是复位 PC 进入 ROM，完成 LLC 自测/SPM 配置并建立栈；随后 ROM C 读取 BOOT_MODE 和 RTC_FREQ，以 CLINT 测系统频率。不同介质最终都要让程序字节落到可执行存储、确定入口并转交控制。文件格式、介质读取和入口选择分别完成，不能把主机读 ELF 的逻辑想成 CPU 自动解析 ELF。

路径当前实现的实际动作首要诊断

Serial Link / 被动模式外部主设备写内存，scratch[1:0] 拼 64 位入口，scratch[2]&2 通知；ROM 清 scratch2 再跳转远端地址映射、写排空、入口高低半与通知排序

gpt_boot_part_else_raw 根据介质内容选择分区或原始区，最多读取 ROM 允许的 96×512=48 KiB 启动载荷到 SPM，再转交入口。这里的 ROM 限制与教材 ELF 可用的 64 KiB 链接区不同。三个介质路径共享加载函数不代表共享初始化协议。SD、NOR、EEPROM 的故障应先定位读取层，再定位 GPT 和应用。

Debug 的寄存器地址空间与复位责任

本地 riscv-dbg 的 README 声明 Debug 0.13.1；JTAG DTM 承载 DMI，DM 支持 abstract register、program buffer 与 SBA。DMI 地址是调试寄存器编号，不是 CPU MMIO 的字节偏移。DMCONTROL(0x10) 控制 dmactive/haltreq/resumereq，DMSTATUS(0x11) 查询 halted/running 等；ABSTRACTCS(0x16)/COMMAND(0x17) 管理抽象命令，SBCS(0x38)/SBADDRESS0(0x39)/SBDATA0(0x3c) 管理系统总线访问。

调试程序应先激活 DM、轮询目标状态，再执行命令；busy 时不重发，cmderr/sberror 应按字段语义清除并记录。读取 SBDATA 若启用 read-on-data 会触发后续读，不能把调试窗口自动刷新当成无副作用。复位时 DM 状态、hart reset 和系统 rst_ni 是不同边界；本地 ndmreset 未接入系统复位，需未来 wrapper 明确实现。

SoC 的 16 个 scratch 是普通 RW、复位为 0；BOOT_MODE/RTC_FREQ/HW_FEATURES 等由硬件输入和参数提供，是 RO，不应把 RO 的初始显示值当成可编程时钟控制。应用退出的 scratch2 编码是软件/VIP 约定，不是调试规范。可用 scratch6/7 做隔离的教学写读验证，但应先确认没有与当前固件约定冲突。

主机生成 ELF 时，CPU 已经执行了 _start 吗？

尚未发生目标执行。ELF 只是主机文件；只有目标完成复位准备、程序字节装载和入口交接后，CPU 才能执行其中的 _start。
