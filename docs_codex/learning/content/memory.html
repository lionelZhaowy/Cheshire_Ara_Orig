地址、缓存副本与物理存储

缓存把数据行保存在近端，用索引选择候选组、标签和有效位判断命中。缺失时从下级取回，写回缓存还可能先把被替换的脏行写下去。写回（WB）允许修改暂留缓存；写穿（WT）把写向下传播，但仍有读副本和写缓冲。外部设备访问同一物理地址时，必须明确这些副本如何同步。

同一阵列的缓存与 SPM 用途

SPM 是软件直接管理固定地址的方式，SRAM 是实现存储阵列的技术，两者描述不同层次。当前 LLC 阵列可按 way 分给缓存或 SPM；默认容量为 8 ways × 256 lines × 8 blocks × 64/8 bytes = 128 KiB。启动全部分为 SPM 后，CPU 代码和栈实际依赖这份阵列。

LLC/SPM 的配置和访问路径

CPU 的低 SPM 窗口从 0x10000000 起，可按地址属性进入 L1；0x14000000 是同一阵列的非缓存数据别名，在 LLC 前重映射回低地址。两个窗口共享物理字节。若先用低别名产生缓存副本，再用高别名访问，不同观察者仍可能看到不同内容。当前高别名未包含在默认 SPM 执行区中，本书把它用于共享数据，代码仍从低地址执行。

容量参数与出口组合

Cfg.LlcSetAssoc/LlcNumLines/LlcNumBlocks 与 AxiDataWidth 决定阵列容量。LlcOutConnect=1、LlcNotBypass=1 保留 LLC/SPM 和外存出口；1/0 走外存旁路并移除内部 SPM；0/0 关闭该出口；0/1 会导致地址生成与实际实例不一致，应避免采用。取消缓存用途时也要安排原本驻留于阵列的启动空间。

寄存器提交与 way 切换

LLC 控制基址为 0x03001000。CFG_SPM(+0/+4) 是 way 位图，CFG_FLUSH(+8/+0xc) 选择清理的 way，COMMIT(+0x10) 提交，FLUSHED(+0x18/+0x1c) 用于观察清理完成，BIST_STATUS(+0x48) 表示自测状态。软件写配置后要等相应完成状态；切走 SPM way 前应迁移其中代码/栈/数据、停止相关发起者并处理脏数据和在途请求。axi_llc_reg32_set_spm 只承担寄存器操作，不替应用迁移栈。

从启动 SPM 到共享缓冲区

应用链接区、运行栈和共享缓冲区要在同一物理阵列预算内。运行时切换 way 前迁移占用、排空访问并处理缓存状态；只改 CFG_SPM 寄存器不能替软件完成这些动作。多个访问者同时使用数据时，进一步阅读共享数据章；DMA 和 Ara 各自的完成语义分别在对应章节。
