学完能做什么

说明一个 memcpy 请求怎样变成 AXI 读写；为缓存和 DMA 定义所有权；解释 LLC way、预算与错误 FIFO。前置：AXI、cache、MMIO、中断。场景：DMA“完成”但数据不对，或提交后一直等不到完成。

iDMA 内部：寄存器前端 → 排队 → 分解 → 搬运

直接内存访问（Direct Memory Access，DMA）由硬件主动搬数据。当前 cheshire_idma_wrap 用2D寄存器前端、job FIFO、ND midend和backend；前端把地址、长度、stride、repetitions构成请求，midend将多维请求分解为burst工作，backend发读写AXI并处理缓冲/回压。NumAxInFlight=16、JobFifoDepth=2只说明可配置资源，不保证实际每拍吞吐。

0x01000000 + 偏移（生成头的32位寄存器）含义协议点
0x00 CONFDECOUPLE_AW0、DECOUPLE_RW1、burst约束；ENABLE_ND10参数必须在提交前稳定；旧HAL第二个decouple表达式也用了AW位号，当前值均0掩盖了问题
0x04 STATUS_0stream0忙状态集合不能用一个 busy=0代替整个系统数据正确性
0x44 NEXT_ID_0读取产生提交侧副作用，并返回任务 ID不是普通查询；前端read_happens驱动arb_valid
0x84 DONE_ID_0已完成任务 ID示例只允许单个未完成任务；多任务/回卷需更严格策略
0xd0/d4 DST、0xd8/dc SRC目的/源地址低/高32位不要假定一个sd会同时更新两个生成寄存器
0xe0/e4 LENGTH单次长度当前 wrapper TfLenWidth=32；零长度和极大长度需边界验收
0xe8/ec、0xf0/f4、0xf8/fc目的stride、源stride、reps2D步进语义查ND midend；不能把复制次数当字节数

完成 ID 由请求被接受/响应被退休推进。wrapper没有完成IRQ端口，intr.intn.bus_err.dma 是AXI错误中断，不是DMA成功通知；backend配置 NO_ERROR_HANDLING。因此即使看到done，仍需检查错误、数据和缓冲区守卫。不要因为“DMA通常带中断”就为本工程虚构一个source号。

必须先解决的适配缺口：名字含64，不等于寄存器是64位

DMA运行暂不作为可直接执行实验。

静态链路：wrapper的 dma_regs 使用 AxiDataWidth=64；deprecated axi_to_reg 与 axi_lite_to_reg 保持64位数据/字节使能；生成 idma_reg64_2d_reg_top 却固定 DW=32，直接截取wdata/wstrb，返回rdata零扩展，未显示按addr[2]搬移字节lane。+0x44/+0x84处的32位AXI访问位于64位总线的上半lane，而寄存器返回在低32位。这是强静态不匹配证据，尚未通过波形运行复现。

软件侧，原 dif/dma.h 对STATUS/NEXT_ID/DONE使用 volatile uint64_t*。本机GCC15.2.0在 -mstrict-align 下把对NEXT_ID_0的一次读取拆成 lwu @+0x44 和 lwu @+0x48 再拼接；DONE同理读+0x84/+0x88。当前NumStreams=1，未用stream1返回0，不意味着该方式是正确接口。更换编译器还可能生成其他访问序列，不能依靠这个偶然行为。

独立修复建议交给S01/V01：优先保持生成寄存器32位，明确把DMA控制桥改成正确的64→32适配（参考SoC普通MMIO的axi_to_reg_v2用法），并用明确32位访问的HAL；或者一致地重新生成真正的64位寄存器和配套头，重审全部偏移。两种方案会涉及生产RTL/软件，需要独立任务，本轮没有实施。最小验证必须包含偏移%8=0与4的读写、WSTRB、跨高低地址、一次NEXT_ID只提交一次、非零ID、DONE以及错误响应。

进阶 advanced.c 用单次32位ID访问及显式地址高低写，保留可审阅的数据路径；adv_allow_dma 默认0，程序报告BLOCKED并返回16。只有接口独立验收后才用 DMA_INTERFACE_VALIDATED=1 构建。该开关是验收声明，不是硬件修复。原入门dma例同样受影响，旧“构建通过”记录仍只代表软件构建。

CPU、Ara、设备的一致性边界

CPU标量load/store可能命中L1；Ara VLSU走自己的AXI，在本SoC的WT配置下通过axi_inval_filter向CVA6 L1D发送失效；iDMA、VGA、USB、Serial Link不都经过这条Ara专用路径。LLC服务多个master并不自动等价于带目录/侦听的全系统L1一致性。即使CPU写通，设备写之后CPU还可能保有旧的cache line。

LLC/SPM：如何在同一阵列上分配 ways

末级缓存（Last-Level Cache，LLC）与片上暂存存储器（Scratchpad Memory，SPM）不是当前设计里各自再加一块RAM。默认8way×256line×8block×8byte=128KiB，way配置决定其中哪些作为SPM。CFG_SPM是way位图，不是字节容量。ROM等待BIST/配置完成，把ways设为SPM来放启动代码、数据和栈。

0x03001000 + 偏移含义
0x00/04 CFG_SPM低/高32位way选择
0x08/0c CFG_FLUSH；0x10 COMMIT选择待flush ways并提交配置；写配置不等于已完成
0x18/1c FLUSHEDflush完成位；等待须有超时且确认语义
0x20/24 BIST_OUT；0x48 BIST_STATUS存储自测输出与done，不是整SoC功能回归
0x28/2c、0x30/34、0x38/3c、0x40/44set associativity、num lines、num blocks、version

axi_llc_reg32_set_spm 写位图再写COMMIT。切配置前必须停止发起者/排空事务、处理脏数据，并确保执行代码和栈不位于将被回收的SPM区域。不能从SPM里运行一段“all_cache()测试”然后期待自己继续正常执行。未来DDR+NPU的buffer规划应从这个生命周期约束开始。

AXI RT：限制资源消耗，不给应用凭空保证实时性

AXI RT把每个manager的地址分到region，按周期budget决定可继续接受多少读/写流量。RTL的字节成本计算是 (AXLEN+1)<<AXSIZE；不是“一个burst算一个字节”。周期时钟和仲裁/存储延迟仍影响最后服务时间。软件先claim guard，再配置region起止、read/write budget/period、LEN_LIMIT，最后开RT/IMTU；查看剩余预算和隔离状态后release。

关键控制偏移：RT_ENABLE+0x0c、RT_BYPASSED+0x10、LEN_LIMIT组+0x14/+0x18、IMTU_ENABLE+0x1c、IMTU_ABORT+0x20；区域/预算数组完整偏移见索引。这里IMTU_ABORT的注释是重置period/budget，不是终止任意DMA的abort。guard地址0x020c1ffc，不是PLIC claim。

生成头固定6 managers×2regions；打开Ara且保持全部默认外设将产生7个manager，必须重新核对生成配置/索引。现有 __axirt_poll_isolate 写法为 (value>>mgr_id)!=1，会受更高位影响，而且无超时；独立修复应掩码单bit并加入deadline。此功能默认关闭，本轮只有源码练习。

Bus error：先读地址与meta，最后弹出错误码

每个axi_err_unit_wrap占0x40字节：write子块+0x00，read子块+0x20。VGA基址0x03009000，DMA0x03009040，CPU0为0x03009080。每子块ERR_ADDR+0、ERR_ADDR_TOP+4、ERR_CODE+8、META+0xc；META记录请求ID，错误码低位包含AXI响应。读取ERR_CODE触发FIFO pop，因此先取地址/高位/meta，最后取code，不能按地址顺序随意循环打印。

监视器在AW/AR握手时记录地址/ID，在B/R返回时匹配错误。CPU同步访问异常和总线错误IRQ可能指向同一根因，但不是同一种交付。错误FIFO只有有限深度；overflow/drop策略、每ID outstanding上限不匹配会损失诊断。本配置VGA最大读事务24，而其错误跟踪采用CoreMaxTxns=8，需作为单独容量/压力检查，不能用一次短读覆盖。

1. NEXT_ID返回0和DONE_ID也为0就是复制完了吗？

不成立。需要确认提交握手、有效非零任务ID、寄存器lane映射以及结果。错误的读取路径可能让两个值碰巧相等。

2. DMA超时后为什么不能立即再次写目标数组？

硬件可能仍有在途写事务，软件结束等待没有取消它。要隔离缓冲区，直到证明排空或经受控复位。

3. 为什么开Ara后AXI RT软件也要重新检查？

Ara增加发起者并改变后续索引；生成寄存器的manager数量仍可能是旧6，配置表和硬件数量必须一致。
