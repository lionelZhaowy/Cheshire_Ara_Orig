学习目标

选择正确的仿真入口，把第一条错误定位到软件编译、RTL 编译、展开/DPI、加载或运行。前置：第 04 章；先完成 Hello/数组 ELF 构建。本章所有 RTL 编译和运行命令均为待验证示例，本轮不执行大型仿真。

独立工作目录与仿真源码清单

本轮实测：仅导出与静态检查脚本复用 cheshire.mk 和 Ara 集成 Makefile 的 targets/flags，但输出到新目录。需要已有 Bender、本地依赖、g++、生成 RTL、两个外部模型；模型有文件不代表许可或版本已经验收。脚本使用 --local，不自动下载缺失内容。

# 工作目录：仓库根；每次得到新的 evidence/sim.XXXXXX
bash docs_codex/learning/scripts/prepare_sim.sh
# 将打印的绝对路径填到这里；路径建议不含空格
LEARN_SIM='/实际输出路径/evidence/sim.XXXXXX'
LEARN_REPO="$PWD"
LEARN_ELF='/实验构建打印的绝对路径/lesson.spm.elf'
test -s "$LEARN_ELF"
rg -n 'config_pkg.sv|first_pass_decoder' "$LEARN_SIM/vsim/compile.cheshire_soc.tcl"

接受标准：恰好一个 cv64a6_imafdcv_sv39_config_pkg、一个真实 decoder，没有 stub 和标量 profile；导出脚本自动检查这些条件。独立副本仍引用当前仓库源码绝对路径，不是可搬迁 ASIC 提取。不混用旧 work/simv。USE_DRAMSYS 留空：默认 UseDramSys=0，用 axi_sim_mem 行为内存，不验证 DDR PHY/校准。

本轮导出有 Bender W28：两个 .svh 的文件类型未知。清单核对只能说明 profile/decoder 已选择对，W28 涉及的 include/trace 输入是否充分仍需实际 RTL 编译判断；不为此升级 Bender。

QuestaSim/ModelSim 编译、展开与运行

本轮只读查询为 Questa Sim-64 2024.1；没有测试 ModelSim 的其他版本/许可等级。ModelSim 需具有本设计所用 SystemVerilog、优化与 DPI 功能，不能凭兼容 Tcl 名称保证可用。以下在 Bash 中执行，变量沿用上节；单阶段 300 秒墙钟预算只是起始上限。

(
  cd "$LEARN_SIM/vsim" || exit 1
  timeout 300 vsim -c -do 'onerror {quit -code 2 -f}; set r [source compile.cheshire_soc.tcl]; if {$r eq "1"} {quit -code 2 -f}; quit -f' \
    > compile.log 2>&1
)
# 先确认上一步退出码为 0 并检查首错，再执行后续运行。
(
  cd "$LEARN_SIM/vsim" || exit 1
  timeout 300 vsim -c -do "onerror {quit -code 2 -f}; set SELCFG 3; set BOOTMODE 0; set PRELMODE 0; set BINARY {$LEARN_ELF}; source start.cheshire_soc.tcl; run 100 ms; quit -f" \
    > simulate.log 2>&1
)
python3 "$LEARN_REPO/docs_codex/learning/scripts/check_run.py" \
  "$LEARN_SIM/vsim/simulate.log" --stage array

命令中的 stage 要与 ELF 对应，如 hello/dma/rvv。Questa 的展开信息在 simulate.log 前部；这里的 100 ms 是目标仿真时间，timeout 300 是主机墙钟秒数。先检查许可证和 compile.log，再看运行日志。退出码 124 表示墙钟超时，不是计算失败码；没有 SUCCESS 也不能记通过。若日志显示持续正常加载，只能记录超时并有依据地调整预算，不能把“多等一会儿”当作唯一排错办法。

start.cheshire_soc.tcl 把 SELCFG 转为 -GSelectedCfg=3，其他变量转成 +BOOTMODE / +PRELMODE / +BINARY。SELCFG 并不是加在 ELF 编译器上的选项。原清单 catch 后 return 1，因此外层特意检查 r，避免静默继续。

VCS 编译、展开与运行

本机无 VCS / vlogan，版本与兼容性待目标服务器核查先在服务器执行 command -v vcs vlogan，记录安装版本/工具启动日志 banner、主机 C++ 和许可证可用性。本教材不把历史讨论的“VCS 2018”当作实测版本，也不声称该版本支持当前 SV 源码。

原 start.cheshire_soc.sh 的 shebang 被注释，调用应显式用 bash。它用 vcs 编译链接 DPI 与展开，再启动 simv；日志管道没有可靠传播前一命令失败，展开失败后还可能继续运行旧 simv。下面从原入口拆出步骤，在全新工作目录逐个验收。

# 沿用 LEARN_SIM / LEARN_REPO / LEARN_ELF；服务器需重新导出本机路径
(
  set -e
  cd "$LEARN_SIM/vcs"
  timeout 300 bash compile.cheshire_soc.sh > compile.log 2>&1
  # 参数取自当前 start.cheshire_soc.sh，目标 VCS 对参数的接受情况待验证。
  timeout 300 vcs -full64 -kdb -O2 -debug_access=r \
    -debug_region=1,tb_cheshire_soc -cpp "$(command -v g++)" \
    -pvalue+SelectedCfg=3 ../src/elfloader.cpp tb_cheshire_soc \
    > elaborate.log 2>&1
  timeout 300 ./simv +BOOTMODE=0 +PRELMODE=0 +BINARY="$LEARN_ELF" \
    > simulate.log 2>&1
)
python3 "$LEARN_REPO/docs_codex/learning/scripts/check_run.py" \
  "$LEARN_SIM/vcs/simulate.log" --stage array

VCS 这组命令只设置墙钟超时；没有虚构通用的目标周期限制选项。若需要统一仿真时间上限，由 V01 在独立 TB 中加入明确 watchdog。不要把 Questa 的 -G、-do、vopt 或工作库复制给 VCS。原 VCS 脚本中 VCSARGS 只影响默认分支，却未把其内容追加到命令；设置它不是可靠的附加参数途径。

SystemVerilog 兼容性与错误分类

缺文件/重复定义、package 顺序、接口数组层次索引、普通变量索引、固定宽度 indexed part-select、DPI/C++ ABI 是不同问题。保存第一处错误及上下文做最小复现，再提出独立修复；不要全仓机械展开数组或删除语法来“让编译过”。

仿真实验与验收要求

先做“只导出清单”的练习，再在有许可的环境跑 array。成功必须同时满足：加载正确 entry、UART stage=1/sum=28085/errors=0、VIP SUCCESS、没有模拟器错误。随后用 INJECT_ERROR=1 重建，预期 errors 非零、VIP FAILED、检查脚本退出 1。两次日志证明失败确实能被发现。原驱动测频/UART 等待没有内部超时，故必须保留主机 timeout。

1. 看到 “Preload complete” 就能宣布程序通过吗？

只能说明加载任务走到该位置；还要 resume、执行、gold 校验与结束协议。甚至装载段尾风险也需要单独验证。

2. VCS compile 成功，为什么还缺 DPI？

此入口 vlogan 编译 RTL，elfloader.cpp 在 vcs 展开阶段编译链接。目标端 gcc 不能替代主机 C++。

3. shell 返回 0 而日志有 FAILED，算通过吗？

不算。流水管道、$error 的工具处理和 quit 会影响状态传播；应用结果与模拟器日志都要检查。
