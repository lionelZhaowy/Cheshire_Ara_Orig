进阶毕业任务

拿到一个外设，能够从地址译码找到寄存器语义，再沿驱动、FIFO、状态机和总线追到引脚或内存；能够指出验证缺口。前置：完成入门主线的 C→ELF、启动、MMIO、AXI 与缓存章节。

本轮按你的选择同时扩充两条线：CPU/Ara 内部执行和中断、DMA、所有权、超时恢复综合案例。范围是当前 Cheshire 顶层实际接入及可配置接入的组件，不把依赖目录里所有 IP 都称作本 SoC 已支持。以下“默认”指 cheshire_pkg::DefaultCfg，不是板级实测；SELCFG=3 只在默认上打开 Ara，CPU profile 仍须另选。

每个实验交什么证据

源码练习提交“寄存器偏移 → 驱动调用 → reg2hw/hw2reg → 状态机 → 引脚/AXI/IRQ”五段索引。构建练习提交 ELF、map、dump 和完整命令。运行练习还要加初始化配置、加载方式、目标/墙钟超时、UART、结果返回码与最小波形。网站可正常显示、软件成功链接都不能替代运行证据。

新发现优先于旧操作建议

当前 iDMA wrapper 以 64-bit Regbus 接入一个 DW=32 的生成寄存器文件，桥未显示逐 lane 搬移；旧 HAL 又以 uint64_t 指针访问 +0x44/+0x84 的 32-bit ID。进阶 DMA 示例默认返回阻塞码 16，不提交任务。GPIO/定时器、软件构建和所有源码课程可继续；详见 证据与独立修复建议。

基准：cheshire_pkg::DefaultCfg / gen_axi_in / gen_reg_out；各 gen_* 实例；fixture 端口绑定；VIP 设备模型；VCU118 / Genesys2 宏。均为源码静态确认。
为什么“所有外设”不等于“一条脚本全部跑通”？

有的只有 RTL 接口，有的缺引脚、时钟、设备模型或软件协议栈。有意义的完整覆盖必须同时写明这些缺口；空读一个寄存器不证明传输、错误处理或真实应用可用。

如何判断自己真的理解了一个驱动？

能够预测删掉一次 W1C、换错访问宽度、漏掉一次所有权交接分别导致什么现象，并指出第一处可观察的硬件信号。
