时钟与复位决定请求何时有效

通用 SoC 的 CPU、Ara、互连和 LLC 主要使用 clk_i/rst_ni。RTC 是实时时间参考输入，经同步后驱动计时器计数。仿真默认系统周期 5 ns、RTC 周期约 30518 ns；VCU118 shell 连接 50 MHz 系统时钟并声明 1 MHz RTC。软件必须使用所在平台的实际频率来配置 UART 和串行设备。

系统时钟与平台 DDR 时钟

DDR 的控制器侧时钟来自 MIG 的 UI 接口，通过跨时钟桥连接系统；USB PHY 另有时钟，Serial Link 接收侧有源同步时钟。VGA 的分频寄存器形成状态机使能，本地顶层没有因此新增一根独立像素时钟输入。跨域传输和事务恢复将在互连及系统接入章继续解释。

当前 FPGA 连接中，时钟向导 locked 和 MIG 校准完成没有纳入完整的放行协议；这需要在平台启动验证中专项检查。已有 VCU118 HelloWorld 是用户历史报告，覆盖当时的具体程序和输出路径。后续每个实验按自己的存储、设备和结果判据记录证据。

把时钟域、分频和同步器区分开

时钟域由真正采样寄存器的时钟决定。UART 的波特率计数、SPI/I2C 的串行节拍和 VGA 的像素使能都可在系统时钟内实现；有一个分频寄存器，不等于已经建立独立时钟域。当前 CPU、Ara、AXI Crossbar、LLC 及 Reg 主通路采用同一 clk_i/rst_ni。SoC 暴露的 LLC 下游 AXI 也在该域，跨 DDR UI 时钟的桥放在平台 wrapper。

PLL 与 ASIC 时钟规划

PLL 把参考时钟合成为所需工作时钟，其 lock 是平台就绪条件之一。当前通用 SoC 没有厂商 PLL 控制寄存器；FPGA MMCM/MIG 的寄存器和复位信号不能当作 ASIC 交付。未来应先列出每个时钟的来源、范围、生成关系、门控条件与约束，再决定是否把 NPU、ISP、DDR 与 CPU 分域。

锁相反馈与两域教学例

锁相环（PLL）比较参考时钟与反馈时钟的相位/频率误差，调节内部振荡源；反馈分频和输出分频决定频率关系。用简化整数模型表示为 f_out=f_ref×M/(N×C)，M/N/C 的可用范围由 IP 决定。lock 表示锁定检测满足容差，不代表 DDR 已训练或设备事务已排空。

设系统域取一个 PLL 输出，外设域取另一个分频输出。分频改变采样节拍，门控单元只在安全相位允许或停止时钟脉冲；寄存器 clock-enable 则让状态停止更新，但时钟仍然到达寄存器。外设域复位释放要在自身有效时钟下同步；如果先把时钟关掉，依赖该域时钟的恢复握手就无法前进。

图中的系统域和外设域共用 PLL，分别由 C0、C1 输出。调频前先确定改动哪个参数；仅停止外设不足以覆盖共享反馈环的重配置。

操作影响范围与必要条件切换与恢复责任
只调整外设输出分频 C1在 IP 明确支持独立调整且保证 C0 持续有效的前提下，可将影响限定为外设支路；否则仍须按全部受影响输出处理。禁止外设新任务，排空串行帧及跨域队列，按 IP 规定切换时钟、处理复位和锁定条件，更新外设频率换算及派生时钟约束后恢复任务。
修改共享 M/N 或参考源系统 C0、外设 C1 及其他相关输出均纳入影响范围；即使同步调整分频以维持名义频率，也不能假设切换期间相位、脉冲和锁定状态连续有效。协调所有受影响域停止接收并排空事务，按规范使用安全时钟或复位；控制代码或常开控制器必须有有效时钟和可访问的控制路径。重配、等待规定的稳定/锁定条件后，逐域恢复时钟、同步复位、接口及软件计时。

具体切换与锁定控制必须按实际 IP 验收，不能假设修改 C1 一定无需重新锁定；普通组合逻辑与门直接截断时钟会产生毛刺风险。来自共同 PLL 且相位关系有保证的分频时钟，可按相关派生时钟分析；关系无法保证或动态切换期间，应按接口协议处理跨域风险。跨域连接并不一律需要相同的异步 FIFO，但每条路径都须有时序或同步依据。

generated clock（派生时钟）是时序约束中由已知源经分频等形成的时钟，工具据此计算相关边沿。false path（不作常规时序分析的路径）是需要设计依据的约束例外；它本身不提供同步器或握手。CDC 是跨时钟域检查，RDC 是跨复位域检查，用于检查状态在不同采样/复位条件下的传播。

PLL 锁定概念参考 Intel MAX 10 Clocking and PLL User Guide 的锁定定义；此处仅借助公开原理说明，当前 Xilinx wrapper 及未来 ASIC PLL 的具体行为分别按各自实现验收。

启动安全频率与运行时调频

ROM 固定的是指令字节。若指令向可编程 PLL 寄存器写入初值，改变的是 PLL 的运行状态；以后其他代码仍可在 IP 允许的条件下重写这些寄存器。因此，“ROM 不可改”不等于“时钟频率永远不可改”。初值应选择芯片已验证的安全工作点，性能档位则由后续软件按功耗、温度和任务需求管理。

本项目已确认采用官方 Platform ROM 钩子完成平台早期初始化的方向，保留运行时配置入口。调用钩子的是 CVA6 自己：在执行到这里以前，CPU、ROM 路径、LLC/SPM 和栈已经需要可用时钟。ASIC 必须先由上电硬件提供足以取指的安全时钟/复位条件；这部分不能依赖尚未开始执行的软件。

外部存储中的配置表适合在读取介质已可工作的阶段加载。举例说，先在安全时钟下配置 SPI 并读取一份带版本、长度和完整性检查的频率表，校验其取值处于 IP 允许范围，再执行切换。若读 SPI 又要求先切换同一个 PLL，必须先提供一个能读介质的保守初始配置，否则形成相互等待。配置格式、校验策略和故障回退属于未来平台方案，当前仓库没有对应实现。

动态调频的关键还在执行路径：修改共享 PLL 会影响正在运行控制代码的 CPU；需要按真实 IP 保证安全时钟切换，或由不受影响的控制域执行。若同时调整电压，则还要满足每个工作点的电压/频率限制以及升降次序。当前 SoC 没有电压调节器驱动和已验证 DVFS 表，课程只在电源边界中定义这些交付条件。

依据：官方 Platform ROM 集成契约；_prom_check_run 的实际调用位置；本项目 Platform ROM/时钟决策专题。本地正常返回路径缺口见启动章。

PLL 与约束交付

PLL 规格、抖动预算、参考源、切换流程与最小锁定时间由工艺/IP 资料提供；本工程尚未冻结 ASIC 频率。软件配置 UART/SPI/I2C 时用实际工作频率，改变 PLL 后必须协调已有传输、计时换算和超时。时序约束须描述主时钟与 generated clock，CDC 检查须覆盖域间控制及数据，不能用统一 false path 掩盖协议问题。

本章输出是一张可追溯的时钟表。复位何时释放由平台就绪条件继续约束；独立关电还需隔离和保持协议。
