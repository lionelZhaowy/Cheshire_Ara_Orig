完整系统组件与互连

一个 IP 可以既是被配置的目标（AXI subordinate/slave），又是主动搬运数据的发起者（AXI manager/master）。iDMA 的控制端口接在 xbar 目标侧，数据端口接在发起侧。USB、VGA 通过 Reg32 控制，却从独立 AXI master 取描述符或像素。不能把寄存器访问带宽当作数据口带宽。

时钟域、复位域：分平台看

通用 cheshire_soc 主域的 CPU、Ara、xbar、LLC、控制寄存器都使用 clk_i/rst_ni。RTC 输入经同步器产生计数使能；CLINT 的 mtime 寄存器仍在系统时钟域。VGA 的 clk_div 是 FSM 使能分频，并未在顶层形成另一根像素时钟输入。Serial Link 有源同步接收时钟，并且内部逻辑/寄存器时钟接口在本 SoC 都接到 clk_i。

VCU118 shell 用 IBUFDS、clock wizard 产生 SoC 50 MHz，另有 48 MHz USB 时钟接口。DDR 的 MIG UI 域由 MIG 输出，经 axi_cdc 与 SoC 相连；64→512-bit 转换、ID 适配和低地址截取在 FPGA wrapper 中。RTC 计数到 24 翻转一次，故 50 MHz/50=1 MHz。测试平台默认系统周期 5 ns，RTC 周期 30518 ns；二者不该共用随意硬编码的 UART 除数。

复位仍有需验证的边界。

clock wizard 的 locked 未接复位放行；MIG init_calib_complete 未消费。USB 复位直接接 SoC 的 rst_n，源码注释说脉宽足够，但没有在此证明 PHY 域同步释放。VCU118 关闭 USE_USB 也不意味着通用 USB 集成已经通过 RDC。后续 ASIC 需要重做工艺时钟、复位树与存储就绪握手。

电源域：当前能说到哪里

源码静态确认本轮定向检查 hw/、target/ 及 CPU/Ara 核心目录未发现 UPF/CPF 文件；SoC 顶层也没有完整的开关电源、隔离、保持电源序列接口。因此图中只能标“电源分区未描述”，不能断言真实芯片只有一个电压域，也不能画出已实现的 CPU/NPU 独立断电域。

时钟门控（Clock Gating）减少翻转，电源门控（Power Gating）切断供电；二者不是同一件事。Serial Link 的 CTRL 描述 clk_ena/reset/isolate，但 cheshire_soc 将对应输出悬空、isolated_i 绑零，不能用这个寄存器证明当前集成已有电源隔离。未来划域要决定哪些寄存器保留、谁能唤醒、如何停止 outstanding AXI、何时隔离/复位/断电；这是 P01/M01 的独立交付。

1. USB 寄存器能读，为什么仍可能完全没有 USB 包？

控制接口在 SoC 时钟域，PHY 需要另外的时钟、复位和设备连接；当前 fixture 的 PHY 时钟为 0。寄存器访问不验证 PHY。

2. 为什么同一个 DMA 要画在互连两侧？

CPU 通过目标端口配置 DMA；DMA 通过发起端口访问内存。方向与协议角色不同。

3. 有 isolation 寄存器就能关电吗？

还要确认输出被消费、事务已排空、隔离单元/保持/电源控制已实现。当前 Link 顶层连接并不满足这些条件。
