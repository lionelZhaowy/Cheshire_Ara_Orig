ELF：section 给链接器看，segment 给加载器看

ELF（Executable and Linkable Format，可执行与可链接格式）记录入口、装载段、节与符号。节（section）组织代码/数据；段（segment）描述加载区间。一个 PT_LOAD 可以包含多个节。加载器主要需要 program headers，不是把所有 ELF 文件原样复制到一个地址。

内容本工程的布局用什么验证
.text_start 先放，随后各函数机器码objdump -d；nm -n _start/main
.rodata / .data / 小数据spm.ld/dram.ld 将它们收进 .misc 输出节；seed 初值在这里readelf -S；map 中输入节到输出节的映射
.bss未初始化全局/static 数据，如 result；不靠 ELF 存一大串零__bss_start/__bss_end；运行到 main 前由 crt0 清零
栈 stack调用返回与局部变量，通常向低地址增长；不是自动由 ELF 填满的节__stack_pointer$、Boot ROM 栈设置和实际 sp
入口 entrycommon.ldh 的 ENTRY(_start)readelf -h 的 Entry point，不是 main 地址

VMA（Virtual Memory Address，运行地址）是代码运行时引用的位置；LMA（Load Memory Address，装载地址）是镜像内容应装载的位置。SPM/DRAM 链接通常直接装到运行地址；不要拿一般嵌入式“启动必拷 .data”套用到这里：当前应用 crt0 没有通用 .data 拷贝循环。ROM 链接把可写段放到 SPM 布局，镜像整体如何搬运要结合 rom.ld 与启动加载器单独核对。

链接方式当前地址与栈硬件条件
spm.ld起点 0x10000000，链接 LENGTH=64 KiB；__stack_pointer$=0，沿用 Boot ROM 栈当前默认阵列 128 KiB；程序低区、栈高区；必须先初始化 SPM

128 KiB SPM、链接器 64 KiB 应用区、2 GiB 外部地址窗口和 8 MiB DRAM 链接长度是四个不同数字。链接成功只证明满足该链接脚本约束，不能证明实际存储容量足够。当前 crt0 会额外减 sp 24 字节保存上下文；Boot ROM 给出的初始栈不是普通 C 调用边界，不能只看末尾的 -8 就脱离后续汇编判定 ABI。

ELF 怎样进入仿真内存？

  1. TB 从 +BINARY=… 取得主机 ELF 路径；路径错时 CPU 无法帮你找到文件。
  2. elfloader.cpp 的 read_elf/load_elf 读取 e_entry 和 PT_LOAD，使用 p_paddr 作为装载地址，读取 p_filesz 字节。
  3. jtag_elf_preload 通过 DPI（Direct Programming Interface，SV/C 互操作接口）得到数据，设置调试模块 SBA（System Bus Access，系统总线访问）地址，写 SBData。
  4. 调试模块发出 AXI 事务，经过 SoC 译码，到 SPM 或外部存储模型。这条路径不等同于直接在 TB 中强制给 RAM 数组赋值。
  5. jtag_elf_run 写调试执行入口 DPC 并恢复 hart0；随后 VIP 轮询结束寄存器。
两处加载边界要知道

loader 明确警告 p_memsz 大于 p_filesz 的尾部零字节不会由 C++ 内容拷贝补齐；VIP byte 缓冲的默认值不能代替 crt0 清 BSS 的契约。当前 JTAG 循环为 i <= sec_len，且按 8 字节读写，存在段尾额外写/越界索引的静态风险；本课未修复、未动态判定影响。段尾保护和非 8 字节整倍数装载应作为 V01 独立回归。

reset 后为什么不是 main？

硬件 BootAddr = Cfg.Bootrom ? AmBrom : Cfg.PlatformRom 确定复位取指位置。默认 AmBrom=0x02000000。Boot ROM 汇编等待 LLC BIST（Built-In Self Test，内建自测），提交全 SPM 配置，再根据 LLC_SIZE 把栈置于片上存储高端。默认 128 KiB 时早期 sp=0x1001fff8。

本课 BOOTMODE=0 PRELMODE=0 走 JTAG。VIP 等 LLC SPM 配置标志后 halt，装载并直接改 DPC；不要求 Boot ROM 的 C main 已经完成，也不使用 scratch 入口握手。serial link 则写 scratch0/1 的 64 位入口，并向 scratch2 写掩码 2；Boot ROM C 轮询后通过 boot_next_stage 跳转。源码某些注释把掩码 2 称为 bit 2，实际是位 1，必须以表达式为准。

应用 crt0._start 的顺序：关闭 M/S 全局中断 → 停住非零 hart → 必要时更新 sp/gp → 保存调用上下文 → 设置 mtvec → 清 .bss → 设置 FS 并清浮点寄存器 → fence → call main。它没有初始化 VS；即使 C 只用整数，该原始 crt0 也会执行双精度浮点初始化，因此最小软件仍要求匹配的 F/D 硬件。

本课 RVV 将所有 C/库按标量编译，先在 main 中设置 VS，再调用唯一的 RVV 汇编函数。这避免在“启用 VS 之前”由自动向量化插入向量指令；若以后让整个应用/库按 V 编译，要重新检查启动前缀并由 S01 建立可靠初始化。

ELF 直载与 Flash/GPT 自主启动不是同一实验

ELF 直载时，主机已经知道每个 PT_LOAD 的地址与 entry；Boot ROM 只需完成基础硬件环境，VIP 再装载并接管入口。自主启动时，没有主机替 CPU 解析 ELF，Boot ROM 要自己访问启动介质、选取有效载荷、复制到 SPM，然后跳到约定入口。

GPT（GUID Partition Table，全局唯一标识分区表）用于描述介质分区，并非必须配 Linux。gpt_boot_part_else_raw检查 GPT 签名；有签名时查指定分区，否则按 raw 路径选区间，再用设备 read 回调把内容复制到 SPM，调用 boot_next_stage。当前最大初级载荷为 96 个 512 字节逻辑块，即 48 KiB。

当前 rom.ld 把代码与已初始化数据合并到 .misc，>spm AT>extrom表示在 SPM 运行、从外部镜像布局装载；它不是要 CPU 从外部地址 0 原地执行。不要把这种 .rom.elf 直接交给按 p_paddr 加载的 JTAG 流程；本课选 .spm.elf。根 sw.mk 的通用裸机 GPT 镜像规则被注释，但 Boot ROM 的 GPT/raw 解析仍在；停用打包规则不等于删除启动能力。重新生成 Boot ROM 还受特定工具链可重复性约束，不是编译每个应用的必要步骤。

printf 如何变成 UART 输出与完成结果？

printf("LEARN sum=%u errors=%u\r\n", sum, errors)
  → sw/deps/printf/printf.c：格式化并逐字符输出
  → sw/lib/dif/uart.c：_putchar → uart_write
  → 轮询 LSR.THR_EMPTY；向 THR 寄存器写字节
  → CVA6 MMIO → AXI / reg / APB UART → uart_tx
  → vip.uart_read_byte：按位采样，遇 '\n' 输出 [UART] 行

uart_init 根据 CPU 时钟与 115200 波特率写 divisor、8N1、FIFO 等；本例先用 CLINT 的 RTC 参考和 mcycle 测频。无输出可能卡在测频、UART 就绪轮询、main 之前的异常，也可能只是 VIP 尚未收到换行，不能立即认定 printf 坏了。

main 返回后，_exit 把 (返回值 << 1) | 1 写入 scratch2；VIP 检查 bit0 后右移取得返回值，0 打印 [JTAG] SUCCESS，非零报 FAILED。当前 _exit 写完实际执行 ret，尽管旁边注释写“wait forever”。测试依赖的是已写出的结束协议；不要靠返回后的控制流证明运行时健壮。

本例先 uart_write_flush 再 return，避免末尾字符仍在发送。TB 还等当前 UART 字节接收完成，但这不替代软件 FIFO 排空。程序若自己无限循环，就不会自动产生结束码。

依据：common.ldh、spm.ld、dram.ld、rom.ld；Boot ROM 汇编与C 启动选择；_putchar / uart_write / uart_write_flush。详细启动方法见 软件启动手册。

练习与自测

现在完成 实验 1～3：实际构建后，从 symbols.txt 找 seed、result、_start、main；从 map 判断初值和 BSS 的来源。预期 seed 在 .misc、result 在 .bss，SPM entry=0x10000000。若找不到变量，先考虑优化/裁剪和阶段选择，不要修改硬件。

1. main 地址与 Entry point 不同，是否链接错了？

通常没有。入口是 _start；它建立 C 环境后调用 main。直接跳 main 会绕过 BSS、mtvec、栈与 FS 等初始化。

2. ELF 中没有 548 个零字节，result 怎样成为全零？

548=137×4 是 BSS 需求，由 crt0 按 __bss_start 到 __bss_end 清零；不要依赖未初始化存储模型碰巧为零。

3. 打印了 PASS、shell 返回 0，足够吗？

不够。要证明计算失败会导致非零程序返回，并检查 VIP 结束与错误日志。原 fmatmul_test_4x4 即使校验失败最后也 return 0，不能只看 VIP SUCCESS。
