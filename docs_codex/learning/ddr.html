本章任务

从平台初始化到软件可用建立交付条件。 前置：Cache、LLC/SPM 与存储路径、启动与早期存储。本章先解释时钟稳定、复位和训练就绪的使用条件；平台如何实现它们在后续ASIC篇展开。

28.1 DDR 控制器、PHY 与软件的职责划分

DDR DRAM 需要定时刷新、行列命令和训练后的高速数据采样。控制器把 AXI 读写调度成存储命令，PHY 实现时序、电气训练与引脚收发，DRAM 提供实际存储阵列。AXI 的地址范围不等于容量；行/列/bank 映射、颗粒数量、数据位宽与 ECC 都影响可用字节数。

28.2 DDR 初始化与访问放行

28.2.1 独立于 DDR 的早期启动环境

设驱动正要初始化 DDR。如果驱动的指令、栈、常量表或打印缓冲已链接在 DDR 中，那么初始化尚未完成就发生了 DDR 访问，形成启动依赖环。正确的阶段划分是把这段初始化代码及全部早期依赖放在 ROM/SPM，建立外存可用证据后才装载并跳转到 DRAM 程序。链接 map 需要检查的不只是函数入口，也包括它调用的库和引用的数据。

28.2.2 时钟、复位与训练的前后依赖

训练用于建立 PHY 对实际器件和线路的采样/驱动条件；它不同于 AXI 互连复位，也不同于 CPU 完成 ROM 初始化。当前 FPGA 使用 MIG UI 域与 axi_cdc，未来 ASIC 要根据控制器/PHY 的真正接口建立 ready 放行。校准未完成、失锁或重新训练期间怎样响应上游请求，必须是明确的平台策略。

28.2.3 DDR 初始化与缓冲区可用条件

先由平台阻止尚未就绪的DDR被普通应用访问；初始化程序在ROM/SPM运行，按实际IP要求建立时钟、复位、控制器参数和PHY训练。就绪状态满足供应商定义后，仅允许初始化程序访问划定的测试区，执行已知地址模式与字节写读，核对数据、响应和边界。验证通过后，才向后续软件发布这块内存可用，装载数据或切换栈。这里的“先行测试访问”和“向所有主设备发布ready”可以是不同阶段，具体门控方式由平台契约决定。

例如预留一小块不含栈/代码的测试区，逐地址写与地址相关的模式，再逐地址读回比较，同时检查保护字。模式、范围和缓存访问方法必须由目标平台确认；用缓存命中读回自己的写数据不足以证明DRAM数据往返。成功判据是指定物理范围的独立读写与响应满足约定，不是只看到PLL lock或一个训练done位。

本地尚无ASIC DDR控制寄存器/API，以上是待IP资料落实的正常流程，不能直接运行。当前FPGA wrapper只提供MIG/UI/CDC边界参考；初始化无响应或数据错误时进入DDR诊断。实际超时、状态位及恢复动作仍由供应商手册确定。

28.3 一次 AXI 读取的控制器、PHY 与 DRAM 路径

以 CPU 的一次缓存缺失读为例：请求先沿当前 LLC 下游到平台 DDR 接口。若上层缓存命中，则不会发生这次 DDR 访问。假定控制器接受一笔普通 INCR 读，把 AXI 的字节地址和 burst 信息保存进请求队列；AR 握手完成的是接收请求，数据还没有回来。

28.3.1 地址映射、行命中与行切换

控制器按配置把字节地址拆为通道/片选、bank、row 和 column。bank 是可分别管理开行状态的一组存储阵列；ACT（激活）把指定行打开到行缓冲，READ 选择其中的列，PRE（预充电）关闭已打开的行并准备下次激活。地址相邻不一定映射到同一 bank，具体位分配取决于控制器配置。

假设某 bank 已开行 A：请求 A 的另一列是行命中，可以在时序约束满足后发 READ；请求行 B 则先等前一访问允许关闭，再 PRE、等待 tRP、ACT B、等待 tRCD 后 READ。bank 原本关闭时可直接从 ACT 开始。tRP 表示预充电后到下一次激活的最小间隔，tRCD 表示激活后到读写命令的最小间隔；本章不填未确定器件的纳秒或周期数。

28.3.2 物理收发、数据返回与可见延迟

PHY 把控制器命令送到器件，并在 DQ 数据线和 DQS 数据选通信号上完成高速收发。训练用于校准这些采样/驱动关系，解决板线、器件及工作条件造成的时序偏移；训练成功并不会替控制器调度每一笔正常读。

READ 后的数据经 PHY 采样、对齐和控制器返回缓冲，重组成 AXI 的 RID/RDATA/RRESP/RLAST。一笔 AXI burst 如何拆成器件突发由接口宽度、对齐和控制器决定；两种 burst 不能直接画等号。上游 RREADY 拉低时，已呈现的 R 拍保持，缓冲压力继续影响可接受请求量。

DRAM 的刷新维护存储内容，在对应 bank/器件不可服务期间使部分请求等待；行冲突、仲裁、读写方向切换与返回背压也会增加延迟。因而测量应区分 AR 等待、已接收到首个 R 的时间和最后 R 完成时间，并记录缓存状态与并发负载。下游改成旁路不会取消这些约束。

通用命令机制参考 Microchip DDR 控制器访问说明；时序名还可参照 tRCD/tRP 字段定义。这里仅引用通用含义，不移植其他 SoC 的寄存器编码；具体芯片参数须取最终器件数据手册。当前可核对的是 FPGA wrapper 的 MIG/UI/CDC 连接；供应商 ASIC 寄存器及内部调度仍待交付。

28.4 AXI4 接入与接口交付

28.4.1 当前 LLC 出口与 ASIC DDR 的职责划分

本地 SoC 到主存的接口是 axi_llc_mst_req_o / axi_llc_mst_rsp_i。地址进入默认外存窗口，只说明 Crossbar 可将请求送到这里。cheshire_soc 内没有供应商 DDR 控制器、PHY 或训练固件。仿真 fixture 提供存储模型，FPGA 的 dram_wrapper_xilinx 提供相应板级连接；ASIC 需要在同一边界交付真实 DDR 子系统。

责任方必须交付的行为软件可观察结果
Cheshire/LLC按 AXI 协议送请求、接收响应，处理相应缓存/SPM路径可路由的主存地址与总线错误
AXI 适配层处理双方数据宽度、ID、burst、时钟/复位和支持的事务类型应用地址含义保持一致，错误能被终止并报告
DDR 控制器命令调度、刷新、bank/row 管理，依据已配置时序操作 DRAM访问被接受并最终返回；错误/状态通过实际控制寄存器报告
PHY 与平台电气时序、延迟校准/训练、参考时钟、复位、电源和 PAD就绪状态必须按供应商定义解释，包含失败和超时路径

因此 DDR 章节不能列出一套凭空通用的 PLL/PHY 寄存器地址。可先固定驱动的责任划分：配置控制器、启动 PHY 初始化、读取训练状态、验证小范围存储、最后发布 DDR ready；实际偏移、合法枚举、时序单位和保留位要求由授权 IP 手册补入。前文的正常步骤描述该控制过程，寄存器索引仅收录当前仓库真实存在的寄存器。

28.5 就绪后的最小访存验证

28.5.1 DDR 数据、并发与错误处理验收

记录 ELF、地址范围、数据模式、读写字节及响应；先测单主读写与边界，再叠加 CPU/Ara/设备竞争和长背压。注入训练失败、越界、R/B 错误与中途复位，检查任务有界失败及缓冲区不被错误复用。当前没有供应商 ASIC 模型和对应寄存器，本章交付接口与验收条件。
