实践一：观察构建与初始化

前提：仓库根、RISC-V GCC/ar/readelf/objdump/nm/size在PATH。采用已经存在的 build_journey.sh，输出必须是新目录或空目录：

JOURNEY_DIR=$(mktemp -d /tmp/cheshire-interface-scalar.XXXXXX)
JOURNEY_OUT="$JOURNEY_DIR" bash docs_codex/learning/scripts/build_journey.sh scalar spm
riscv64-unknown-elf-readelf -h -l "$JOURNEY_DIR/journey.spm.elf"
riscv64-unknown-elf-nm -n "$JOURNEY_DIR/journey.spm.elf"

操作：找到ELF入口、LOAD、seed/result、__bss_start/end和__stack_pointer$；从反汇编找到 _start → _zero_bss_loop → main，判断 .data是谁装入。预期：入口在0x10000000、栈符号为0表示继承，结果数组在BSS；具体段大小随工具链变化。失败先查ISA/ABI、库来源、链接脚本和工具路径。

本轮实际标量产物text/data/bss为5328/796/548 byte；RVV depth为6092/908/548 byte，证据来自各build.log，不作为未来产物固定值。

实践二：在匹配环境中加载并检查结果

前提：已经用匹配CPU profile/SoC配置编译、展开的仿真库，或来源明确的VCU118 bitstream与JTAG连接。当前保存的标量仿真清单不能直接用来验收RVV。不在本实践自动重建RTL或覆盖旧清单。

现有Questa启动脚本从Tcl读取SELCFG/BOOTMODE/PRELMODE/BINARY。先把构建返回的绝对ELF路径替换到下面占位符；这是待运行模板，不是本轮命令记录：

# 在已有正确映射的Questa work库环境内执行
set SELCFG 3
set BOOTMODE 0
set PRELMODE 0
set BINARY {/absolute/path/from-build/journey.spm.elf}
source target/sim/vsim/start.cheshire_soc.tcl
run -all

此处SELCFG=3仅适用于已正确编译的Ara组合；标量环境使用与其实际编译/配置匹配的选择。PRELMODE=0为JTAG；=2会经过UART debug服务，条件另含UART时钟/ROM服务正常。

FPGA参考当前HS2适配器配置与公共配置，仓库没有专用openocd.vcu118.tcl，HS2配置只适用于对应适配器，需沿用用户已验证的VCU118连接参数。在用户已有工作流程中用GDB加载 .spm.elf、设置PC到 _start并继续；必须保留Boot ROM初始化后的有效sp，不能在复位后尚无SPM/栈时强跳main。命令形状如下，端口以本次OpenOCD实际监听为准：

riscv64-unknown-elf-gdb /absolute/path/from-build/journey.spm.elf
(gdb) target extended-remote localhost:3333
(gdb) monitor halt
(gdb) load
(gdb) set $pc = _start
(gdb) continue

建议在执行前用GDB检查 $sp、$mtvec及LLC配置，不把这个形状当作自动完成复位/初始化的脚本。OpenOCD连接失败先查板型/线缆/端口；halt/load失败查JTAG与Debug Module；程序异常查mepc/mcause/mtval。

目标预期：INIT seed=1 zeroed=137 errors=0、LEARN sum=28085 errors=0和main返回0。保存UART/返回码/ELF哈希/RTL配置/工具版本，不能只记录“串口有字”。本次没有这些目标运行证据。

实践三：寄存器读取和UART写入

先在已有HelloWorld或journey上观察HW_FEATURES、RTC_FREQ、UART LSR/THR的访问；需要改程序时在独立教学副本中进行，不覆盖 sw/tests。用反汇编区分 lw/lbu/sb和CSR读，用波形追踪RegMap、地址、选通、valid/ready、UART FIFO和TX。

预期：一个待发送字符产生THR写，FIFO/发送器随后工作；flush看到THRE/TEMT。可先打印单字符再打印格式化整数。不要对整段外设地址使用任意内存dump，RBR、claim、NEXT_ID等读有副作用。坏结果回到字符案例逐层排查。

实践四：计时、中断条件和返回

第一步复用现有clint_get_core_freq，观察mtime增长和mcycle增长，理解MMIO与CSR。第二步静态跟踪mtimecmp比较和mip.MTIP，暂不把当前clint_sleep_until作为可靠等待API。

第三步为后续S01/V01准备GPIO INTR_TEST→PLIC案例的最小C处理程序：安装强符号trap_vector、配置三个使能层、注入一个事件、记录一次ISR、清源/complete并返回主循环。仓库缺少可直接运行的完整默认PLIC测试；本轮不实施该新ISR。验收要求包括中断屏蔽期间pending保持、正确返回以及没有重复服务。

已有 clic_basic.spm.S可在匹配CLIC CPU/SoC组合上复用，先读其mtvec/mtvt/mintthresh设置及成功分支；默认Ara FPGA未启用CLIC，不可直接运行此测试并归咎软件。失败位置按中断章的源→控制器→CPU→trap顺序查。

实践五：DMA配置与二维地址推演

先读现有 dma_2d.spm.c，在纸面或主机推演4行，每行15 byte，src起点步长1、dst步长7，总目的写范围到偏移35为止，36/37保存!\0。这种推演只校验地址/期望字符串，不是硬件DMA模型。

再检查本轮probe反汇编和wrapper DW，解释为什么32位ID不能盲目通过uint64_t指针访问。运行阻塞条件：控制接口位宽/拆读副作用、reps=0错误回传、排序/超时尚未验收。后续授权修复后先验证单行不重叠，再跑原2D并对每字节和守卫比较；加入读/写错误、backpressure、零长度、最大有效长度/地址位和取消恢复测试。

不要为了绕过阻塞去调用普通sys_dma_memcpy：当前2D wrapper中reps=0路径也是待处理问题。更不能看到DONE_ID等于提交ID就判定成功。

实践六：最小向量计算

前提见Ara案例中的profile、全SPM/独占范围、栈和一致性机制。构建与标量采用相同现有脚本：

RVV_DIR=$(mktemp -d /tmp/cheshire-interface-rvv.XXXXXX)
JOURNEY_OUT="$RVV_DIR" JOURNEY_DEPTH=1 bash docs_codex/learning/scripts/build_journey.sh rvv spm
rg -n 'vsetvli|vle32|vadd.vv|vse32' "$RVV_DIR/journey.dump"

本轮已得到这些实际指令。目标运行仍待匹配的仿真库或板级输入；预期尾部6例errors=0、归约/总和28085、守卫完整且返回0。输入错误注入可使用现有 INJECT_ERROR=1 在另一个新目录编译，预期目标报告非零错误，检查验收脚本是否真的捕获失败；本轮未运行该负例。

最后再比较rvv-intrinsics或rvv-auto入口，本轮没有重复构建它们。先检查编译器实际生成V指令，再在目标执行；不能以加了-march=...v代替向量化检查。

未关闭项与最小后续检查

未关闭事项 最小检查对象 对本专题结论的限制
Platform ROM普通返回、ROM C栈对齐 cheshire_bootrom.S及实际生成指令；正常返回/启动测试 启用钩子前另行修复验收，默认0跳过返回问题
主Reg桥窄读副作用 axi_to_reg_v2及两个bank请求，PLIC threshold/claim和FIFO布局 窄读不一定只影响一个寄存器；设备测试需观察邻址
CLINT读取/比较/睡眠 clint.c、mtime翻转、mtimecmp分拆更新、trap入口 当前sleep API不能证明定时等待可靠
DMA DW、NEXT_ID拆读与ND错误丢失 wrapper、reg_top、编译probe、Job FIFO/ND响应波形 编译/ID退休不是数据成功；无完成IRQ
Ara B错误和完整可见性 vstu B响应、acc_dispatcher pending/barrier、filter 静态协作机制不能代替错误/并发运行验收
Linux平台资源与缓存维护 当前DTS、选用的kernel/固件、DMA ops、IRQ/clock/reset驱动 配方/源码存在不等于Linux和向量抢占已跑通
