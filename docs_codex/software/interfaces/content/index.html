本专题负责五层结构中的软硬件接口层，借助必要的基础软件和 SoC RTL，把程序的一次操作追到硬件，再追到软件观察到的结果。适合有 RTL/NPU 经验、正在学习 RISC-V 启动和驱动的读者。

新增基础软件与BSP：从HAL/DIF、MMIO辅助代码、库归档和开发工具理解接口的使用。推荐先读本章，再进入构建启动与四类接口；两层区别与联系用UART实例对照。

从软件模块找到实际硬件

DIF（Device Interface Function，设备接口函数）主要操作控制器寄存器；HAL（Hardware Abstraction Layer，硬件抽象层）还可封装片外器件命令。以下不是强制调用层级：应用可以直接调用 DIF，也可以直接 MMIO。

软件对象与关键符号 调用者 → 实际消费者 硬件落点/边界
printf.c printf_、_out_char；uart.c _putchar 应用 printf 宏 → 格式化 → _putchar → uart_write CPU 逐字节写 UART；.a 不在硬件中运行
UART DIF uart_init/read/write/flush 程序或 UART debug → reg8 reg_uart_wrap → reg_to_apb → apb_uart，不是 OpenTitan UART
SPI DIF dif_spi_host_transaction Flash/SD HAL → command/TX/RX 寄存器 spi_host 命令队列和收发状态机
I²C DIF dif_i2c_write_byte_raw EEPROM HAL → FDATA 等寄存器 i2c 主机 FMT FIFO → SCL/SDA；器件地址不同于 SoC MMIO 基址
GPIO DIF dif_gpio_write_masked 应用 → 掩码寄存器 gpio 输出/OE；实际板级引脚另核对
Flash HAL、SD HAL、EEPROM HAL Boot ROM 或应用 → 设备协议 → SPI/I²C DIF HAL 负责命令/等待/校验，RTL 控制器负责电气时序
GPT gpt_boot_part_else_raw；gpt.h gpt_read_t GPT 按字节 offset/length 调用 read(priv, dst, addr, len) GPT 不直接驱动总线；回调把读取转成对应介质事务
UART debug uart_debug_serve Boot ROM → READ/WRITE/EXEC 解释 收到地址后由 CPU 读写内存或跳转；不是 UART 自带 AXI DMA
CLINT DIF clint_get_mtime 等 → reg32 RTC 驱动的 MMIO 计数与比较；get_mcycle 另走 CPU CSR
DMA API sys_dma_2d_memcpy 头文件 inline 写参数、读 NEXT_ID DMA 控制 AXI slave 与搬运 AXI master 分开；当前缺口见案例
LLC API CPU 配置 way/commit/flush LLC/SPM 阵列和配置状态机；不自动刷新 CPU L1
AXI RT API axirt_hello 等配置预算 SoC 可选 i_axi_rt_unit_top；不是通用 memcpy 库
util.h reg8/reg32/fence、mmio.h mmio_region_read32/write32 上述 DIF/HAL 的最低软件访问工具 load/store 或 fence 指令；没有名叫 MMIO 的独立硬件 IP
sw.mk CHS_SW_LIB_SRCS_O、libcheshire.a 链接器从归档取所需对象 格式化、crt0、本地 HAL/DIF、OT base/DIF/autogen、LLC/AXI RT 一同归档；unused 节可被裁掉

params.h 中的 extern ... __base_uart 是链接符号声明。&__base_uart 得到链接器赋的数值地址，不是先从该地址读取一个指针。全库编入归档也不表示最终 ELF 包含所有驱动，更不表示所有外设都启用。
