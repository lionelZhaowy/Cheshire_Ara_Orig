完成、错误和裸机 API

新增完成IRQ与错误IRQ先定义源端锁存状态，再决定共用一根线加原因位还是两根源。沿现有 intr_ext_i 和 NumExtInIntrs/NumExtPlicIntrs/NumExtClicIntrs检查可用源、同步和目标截断；内部新增源涉及 cheshire_int_intr_t时还会改变packed编号，需同步DIF常量、PLIC生成配置和DTS，不能只在top多拉一根线。

裸机API可以仿照现有DIF接受base句柄，但应为新引擎明确定义 configure → submit → poll/wait → get_result → acknowledge → recover 的职责。名称是建议，仓库尚无这些NPU函数。配置成功表示参数被接受，任务成功还要检查ID/错误/传输排空，API不能只返回一个DONE布尔值。

最小验收依次用软件INTR_TEST或模块激励注入完成与错误，确认源pending、控制器claim/complete、ISR计数和返回主循环；再加入忙时重提、完成/清除同拍、IRQ屏蔽期间事件保持、超时和复位后的旧令牌。失败时先停新提交并保存错误信息；是否可取消、如何排空及何时允许重用缓冲必须由IP协议保证。

DDR 初始化与平台启动

2026-10-20 按v1同步：F0（LLC）、F1（GB搬运）、F2（帧写）、F3（ROI帧读）经共享压缩前端接一个Controller的DDR.S0–S3；四口共享物理带宽。压缩区成功需包含数据和元数据发布，普通区域原样旁路；Controller本身的保证由供应商确认，项目另外验证前端/CDC/通知。供应商手册最多8口的能力不等于四口实例已交付。见当前契约。

可复用官方Platform ROM钩子，修复并验收S01-B01后，在片内可执行环境中按供应商流程配置安全时钟、复位、Controller/PHY、训练，再经定义的就绪检查开放DDR。具体先后依赖供应商时序，不能一概规定先Controller或先PHY。DDR不可用前，代码/栈/训练参数必须放在独立可用的片内资源；失败保留片内诊断/被动加载恢复入口，不搬应用到坏DDR。

供应商至少需提供版本manifest、AXI端口数/宽度/ID/在途和支持子集、地址语义、时钟复位/CDC边界、初始化寄存器与训练执行者、ready/error条件、模型/约束及授权范围。验收先做可控模型中的寄存器/复位/超时，再做首尾地址、byte mask、burst、并发和错误注入，最后真实训练/压力。不能以FPGA MIG HelloWorld代替这些验收。

运行中调频要阻止新提交、排空相关master、按IP约定进入安全状态/自刷新、切换并确认稳定、更新软件时基后恢复；具体机制尚未实现。保留运行软件可重复配置接口是用户已确认方向，不授权现在改PLL/DDR或升级依赖。

Linux部分依据当前仓库存在的Linux6.5方向与官方DMA API、设备I/O访问。DMA地址不同于CPU指针，coherent分配也不取消必要的排序；平台没有实现正确cache维护时，调用API名称不会自动补齐硬件/内核缺口。

当前 sw/boot/cheshire.dtsi及板级DTS是历史平台描述，不能直接复制成VCU118或新ASIC定版：ISA字符串rv64imafdc不声明V，PLIC ndev=51而本地生成NumSrc=58（还包括保留源0），axi_llc@3001000长度0x5000超过当前4KiB窗口，memory-controller@3006000标成ddr-link但当前该地址为Serial Link配置窗口。UART节点用reg-shift=2、reg-io-width=4，裸机UART使用reg8；必须各自核对硬件支持和桥副作用。这里只指出静态差异，不擅自改DTS或推断旧镜像必然失败。

新IP Linux资源至少列出compatible与binding、reg/reg-names、interrupt-parent/interrupts、clocks/clock-names、resets/reset-names、DMA mask/地址翻译；reserved-memory/memory-region、dma-ranges或IOMMU只有实际设计需要且硬件/内核支持才添加。不要在DTS随意加dma-coherent来掩盖不一致硬件。 新的clock/reset provider、IRQ描述和缓存维护是跨S01/M01/P01的实施工作，当前不存在已验收的新IP驱动。
