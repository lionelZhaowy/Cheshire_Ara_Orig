### 2.1 模块主责

下表是建议采用的执行责任边界。主负责人负责交付和问题闭环；配合人负责明确的接口或复核，不表示双方重复承担全部实现。

| 工作范围 | 主负责人 | 交付责任与协作边界 |
| --- | --- | --- |
| SoC 架构与顶层集成 | **队长** | 需求取舍、带宽/资源预算、地址与中断分配、时钟复位架构、顶层/config/接口冻结及版本放行；TTY 维护构建和运行入口 |
| 固定工程与平台基线 | **TTY** | 组织独立 `cheshire_ara_asic/` 的构建、静态清单、启动软件、最小测试和可搬迁检查；队长负责固定配置、RTL 提取边界及技术审核，首次提取保持原有最小路径 |
| NPU 硬件、软件与算法 | **队长** | 算法参考、量化/布局、计算阵列与控制、算子、任务调度和运行时；提供可调用接口及独立测试，TTY 集成公共平台服务 |
| GB、搬运与缓存维护 | **队长** | GB bank/仲裁、DDR↔GB 搬运、缓存范围维护硬件、跨口可见性和错误契约；TTY 实现维护 HAL、公共 buffer 生命周期及调用集成 |
| DDR Controller/PHY 接入 | **队长** | 供应商接口确认、四口实例、RTL 适配、训练/ready/error 与工艺交付；TTY 配合初始化固件和板级接口，HYH 配合压缩前端边界 |
| ISP 与图像存储通路 | **HYH** | ISP 算法/RTL、参数生效、RAW 旁路、帧写 DMA、ROI 调度和二维帧读 DMA；TTY 提供 LVDS 收发端接口，队长审核内存/带宽契约 |
| 共享压缩前端 | **HYH** | 无损压缩/解压核、区域与元数据管理、普通旁路、部分写/跨块、事务跟踪/响应归属及恢复；队长审核四口完成与存储同步契约 |
| LVDS、eMMC | **TTY** | LVDS RX/TX、CDC/FIFO、eMMC Host及其 DMA、控制接口、驱动和独立验证；参数使用规则由 HYH/队长分别提供，物理层按真实工艺 IP 适配 |
| SoC 公共软件与 FPGA 环境 | **TTY** | 启动固件、BSP/HAL、中断/异常、公共驱动接口、诊断、FPGA 构建和板级调试；各模块负责人提交本模块基本控制程序和结果检查方法 |
| 系统回归组织 | **TTY** | 回归入口、运行配置、日志和失败汇总；HYH 维护图像/压缩参考检查，队长维护 NPU/存储同步/并发验收，失败项由对应模块负责人关闭 |

“编解码器”在本文指 v1 的 **DDR 共享无损压缩/解压体系**。算法核完成不代表共享前端完成，事务控制、元数据、四口响应及异常恢复都属于交付范围。帧 DMA/ROI 属于图像存储通路，由 HYH 主责；eMMC 内置 DMA 由 TTY 主责；DDR↔GB 搬运由队长主责。底层 DMA 组件可以复用，集成和验证责任仍按上表归属。

CPU/Ara 经主 Xbar 的共享 M5 访问 GB；eMMC 在拓扑上也可达该出口，但软件规划为上电初始化时先 eMMC→DDR，ISP 工作时再 DDR→GB，不采用 eMMC→GB 直达加载。NPU、搬运和 ISP 的本地 GB 服务按总纲协调。分工不新增 Ara 独立 GB 分支，不把四个 DDR 入口解释为四个独立存储器，也不把 GB 本地交接和 DDR 缓存同步合并成同一个完成条件。

### 2.2 每个模块的最小交付包

每个模块负责人都应交付以下内容，再由系统负责人集成：

1. 接口与配置说明：数据、控制、时钟复位、中断、错误、背压，以及完成和资源释放条件。
2. 实现与来源：RTL、依赖版本/许可、配置、约束及必要工艺适配说明。
3. 验证：参考模型或结果检查器、单元测试、边界/异常用例、可重复运行的命令与日志。
4. 软件接入：本模块寄存器语义、基本控制程序、已知输入与预期结果。TTY 统一平台接口，各负责人继续维护自己的模块语义和算法实现。
5. 系统交接：已通过项、未验证项、资源/带宽预算、已知缺陷和接收方。

TTY 组织回归不等于 TTY 独立编写全部验证；队长负责最终技术判断也不等于队长接管所有尚未分配的任务。新工作必须先归到明确负责人，并调整其已有负荷。

### 4.1 不可省略的依赖

- 供应商提供的真实四口实例、Controller/PHY 模型与工艺视图，是相应集成和签核的输入。模型阶段可先行，不能用假设接口填补实际交付缺口。
- 缓存开启的共享缓冲应用依赖范围维护、排空、完成和错误闭环。全路径不缓存只能用于经证明适用的局部测试，不能替代产品同步要求。
- 压缩正式场景依赖普通路径正确、元数据/部分写方案完整、四口逻辑数据可见性成立。算法压缩率通过不等于前端已通过。
- FPGA 可使用平台 DDR/存储资源适配。其结果必须说明与 ASIC 的差异，真实 Controller/PHY、宏语义、PAD、时钟复位和物理路径另验。
- 7 月不是首次获得 PDK 或首次试跑布局布线的时间。若工艺准备拖到此时，9 月目标须重新评估。

| 固定平台与启动 | TTY，队长审核 | 可搬迁构建；复位/ROM/SPM；Platform ROM 返回修复及栈/启动检查；标量、RVV、AMO/LRSC；版本与日志 |
| 图像与应用正确性 | HYH；NPU 数值由队长负责 | RAW/ISP、参数切换、帧所有权、1/256 ROI、输出顺序；参考模型逐项比较；小算子→子图→应用结果 |
| eMMC→DDR 参数加载 | TTY | DDR 就绪后加载、长度/完整性、错误处理及 DDR 源数据就绪；软件拷贝/Host DMA 实现方式待选 |
| DDR→GB 装入及 ISP 参数交接 | 队长主责搬运，HYH 主责 ISP，TTY 配合调度 | 运行时按需装入、范围维护/跨口可见、GB 写入完成后交接与参数生效、使用中数据不被覆盖；沿用已有模块分工 |

| 性能与稳定性 | 队长汇总，各模块提供计数 | 已确认工作负载下的延迟、有效流量、最大等待、维护开销；逻辑字节/实际 DDR 数据与元数据分开记账 |
| 工艺和前端质量 | 队长，TTY/HYH 分项执行 | 真实宏语义、CDC/RDC、复位/时钟、综合、约束、STA、等价；问题与豁免的依据 |
| DFT 与最终签核 | HYH 负责 DFT，TTY 负责物理，队长协调 | Scan/MBIST/ATPG、测试模式、最终网表/库/约束版本一致；工艺所需 STA、等价、DRC/LVS、电源完整性等报告；指导人员复核记录 |

完成一个检查点，需要交付物、实际运行/检查结果和未关闭项说明。已有 ELF、bitstream、文档、静态阅读或编译通过不能自动替代目标仿真、板测、性能或签核证据。

## 6. 日常执行与后续进度对照

### 6.1 每周组织

前端开发期建议每人每周按约三天实现、一天验证、半天集成评审、半天工艺适配及后端学习安排。5～6 月逐步提高验证和收敛占比；7 月后按后端职责投入，保留各模块负责人处理 RTL ECO 和回归的时间。

每周固定一次集成：TTY 维护回归入口并汇总结果，HYH 提供图像/压缩检查，队长审核存储/NPU/全局影响并放行。每月向上级报告实际通过证据、阻塞与关键路径变化、剩余问题和所需支持。

顶层、固定配置、地址图、共享清单和接口版本由队长协调汇总；其他人员负责自己的模块与交接。源码、软件和测试的接口更新必须成套接入。按独立分支/worktree 或明确路径协作，保留已有 FPGA 工程和依赖；任务表本身不是文件锁。

- 人员分工调整、投片日期批准、功能范围变化或关键输入到位时，更新本表并保留日期、原因与来源；技术变化同步到总纲或所属契约。
