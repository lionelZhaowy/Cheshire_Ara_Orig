# Platform ROM、安全启动时钟与 IP 配置约定

日期：2026-10-06。任务：L01 文档整理；后续实施由 S01 / P01 / E01 / V01 协调。

本文记录用户已确认的设计方向及待修复项，不是 RTL 或固件实现报告。当前输入为分支 `mp/ara-pulp-v2`、HEAD `5ddec4fb4`；实施前须重新核对源码、依赖、工作区和 IP 资料。

## 1. 用户确认与适用原则

用户在 2026-10-06 明确要求：

1. 软硬件方案优先采用当前版本适用的官方文档及建议；官方没有覆盖或新增 IP 引入抉择时，再补充自定义设计。
2. 采用 Cheshire 官方 Platform ROM 钩子进行平台初始化：以安全启动频率配置 PLL，并考虑完成其他 IP 的必要配置。
3. 配置接口必须保留给运行软件，使初始化后能够重复配置和受控动态调整，避免 Dremi 的一次性配置事件限制。
4. 上轮发现的 Platform ROM 返回缺陷登记后续修复，本轮不实施代码修改。

外部存储中的可修改 IP/时钟配置可作为后续软件输入；读取阶段、格式、有效配置集合与失败回退尚待设计。附件中的频率、电压、PLL 个数、独立 CPU/AXI/Ara 域、Linux cpufreq 和 DVFS 都是讨论示例，不是已冻结需求或现有能力。不得把超出验证范围的超频数值登记为产品工作点。

近期用户决策及现有工程保护边界优先；官方通用 Bender 用法不改变独立目录和静态清单迁移方向。

## 2. 官方入口与当前实现

官方 [SoC Integration / Platform ROM](https://pulp-platform.github.io/cheshire/tg/integr/#platform-rom) 允许在外部交互前初始化 clock sources、IO pads、memories、PHYs，以及扩展或改写启动流程。它提供钩子，没有给本项目交付具体 PLL、DDR 或 MIPI 初始化程序。

本地对应关系：

| 对象 | 当前源码与行为 |
| --- | --- |
| 平台入口 | `hw/cheshire_pkg.sv::cheshire_cfg_t.PlatformRom`；默认未赋值，通过 `DefaultCfg` 的 `default:'0` 得到 0 |
| 入口寄存器 | `hw/cheshire_soc.sv::reg_hw2reg.platform_rom` 来自 `Cfg.PlatformRom`；`hw/regs/cheshire_regs.hjson` 定义软件只读 |
| 调用顺序 | `hw/bootrom/cheshire_bootrom.S::_prom_check_run` 在保留内部 LLC 时位于 BIST/SPM/栈调整之后；HW_FEATURES.llc=0 则跳过该初始化。随后读取入口，非零则调用 |
| 系统启动时钟 | `cheshire_soc.clk_i` 为外部输入；CVA6、互连、LLC、ROM 访问逻辑须先具备可用时钟，Platform ROM 由同一个 CPU 执行 |
| 配置扩展口 | `Cfg.RegExtNumSlv/RegExtNumRules/RegExtRegion*` 与 `cheshire_soc.reg_ext_slv_req_o/reg_ext_slv_rsp_i`；平台需自己实现配置银行及必要跨域适配 |
| 后续可更新软件 | `sw/boot/zsl.c` 是现有加载器参考；尚未实现本项目 PLL/PHY 管理，不能直接宣称已有调频功能 |

如果 `Cfg.Bootrom=0`，SoC 可直接从 `Cfg.PlatformRom` 启动；这属于另一种引导配置，平台需承担最初运行环境。本文当前方向是保留内置 Boot ROM 并使用它的官方平台钩子，不默认切换此配置。

## 3. 启动与运行时职责

以下是保留内部 LLC 的目标职责，尚未实现。正常返回步骤以 S01-B01 修复并验收为前提。无内部 LLC（例如出口旁路）时，平台须在首次栈访问前提供替代可写存储和有效 sp，或先用不依赖栈的早期汇编建立这些条件；ROM 加载链接栈值不保证对应存储存在。此责任不因 Bootrom=1 而免除。

```text
POR / 有效参考时钟 / 硬件安全初值
  → Cheshire Boot ROM：建立最小运行环境、LLC/SPM
  → Platform ROM：安全启动 PLL、必要 PAD/复位/IP 配置与检查
  → 回到 Cheshire Boot ROM：按 boot_mode 读取介质
  → SPM 中的 ZSL / 可更新早期固件：读取并校验外部配置，按需要调整 IP
  → DDR 就绪后加载后续固件/数据，再按产品需要进入裸机、RTOS 或 Linux
  → 运行软件经保留接口进行受控配置调整
```

### 3.1 硬件平台层

- 上电默认选择有效安全启动时钟，并为 PLL/PHY 控制提供规定的安全复位值；不能依赖外部配置文件才能建立最初可执行环境。
- 管理 PLL 时钟切换、配置请求握手、复位、独立超时和故障恢复。普通组合 mux 或仅写 PLL 倍频寄存器不能替代这些职责。
- PLL/PHY 配置通路应在功能时钟停止、局部功能复位时仍能按契约访问；是否保持配置值及如何重新施加默认值须明确。

### 3.2 Platform ROM

- 按已确认方向配置一个保守且经过验证的安全启动工作点；它是初始工作点，不限制软件之后选择其他合法工作点。
- 完成进入可靠启动介质读取之前必需的 PAD、时钟、复位和 IP 初始化。其他 IP 是否放在该阶段，按实际依赖及供应商启动要求决定，不强制所有 IP 都在此完成。
- DDR 控制器/PHY 初始化或 training 可以由平台代码组织，但必须按交付 IP 的协议实现；在 DDR 首次访问前完成，不能据函数名称宣称训练已通过。
- 若平台代码需要读取外部配置，须先独立建立能访问该存储的时钟/PAD/控制器环境；没有可用外部配置时仍有安全默认启动或明确恢复路径。

### 3.3 可更新固件与运行软件

- 外部存储可保存配置数据，固件读入后检查版本、长度、完整性、芯片/IP 兼容性及允许范围，再经配置接口应用。CRC 只能检查完整性，不等于认证；具体格式及保护要求未冻结。
- 可采用经过验证的工作点/Profile 集合，避免任意配置字直接改写关键 PLL/PHY 参数；这是待细化的设计建议，不固定 Profile 编号或频率。
- 支持重复写入、状态检查、超时和恢复。以用户提供的 PD_BG 先 1 后 0 为例，可执行多个写阶段及等待；实际位号、保持时间和重配条件以供应商资料为准。
- 若需要修改初始化算法本身，应由可更新固件或明确的补丁机制承载。固定 mask ROM 能执行多次写，但不会因为使用软件就变得可更新。
- 现有 ZSL 在跳转后续固件前向 DRAM 加载固件/设备树，DDR 必须提前可用；新增初始化不得放在已依赖 DDR 的程序之后。

## 4. 配置接口与受控调整的验收边界

后续 P01/S01 共同给出接口契约，至少确认：

1. 寄存器的写权限、读回/生效状态、复位值、局部复位保持行为及多寄存器配置一致性；不能只有启动一次性写脉冲。
2. 软件请求已接收与配置/切换已完成是不同状态。跨 RefClk/系统域的多位配置、请求、应答和错误须可靠传递，不能只同步一个脉冲。
3. 时钟修改须覆盖实际受影响消费者。当前 CPU、Ara、AXI Crossbar/Regbus 等共用 `clk_i`；单独调 CPU/AXI/Ara 需要另行设计，附件示意不能当已有分域。
4. 调整系统 PLL 时，在允许重配前保证有效安全时钟和可执行控制路径，按 IP 要求等待稳定并切换；运行中的 DMA、实时串行帧、外部 DDR/跨域事务需按契约协调。
5. PLL 不锁、外部配置非法、操作超时应有安全默认或恢复路径。已经失锁/停止的时钟不能靠 CPU 软件或仅支持双稳定时钟的 mux 保证无损恢复。
6. RTC/超时、UART/SPI/I2C 分频及相关时序约束与实际频率一致。当前 FPGA RTC 来自系统时钟分频，不能无条件照搬到可调频 ASIC。

运行时支持哪些调整、是否要求无损切换、是否涉及电压变化或 DDR 变频，尚未冻结；最终按 IP 能力和验证结果限定。开放接口不等于已经支持所有运行时配置。

## 5. S01-B01：Platform ROM 普通返回缺陷

状态：**未开始；已登记，尚未授权实施。** 发现日期：2026-10-06。S01 主责，V01 验收，E01 同步提取输入。

### 5.1 现象与证据

输入 HEAD `5ddec4fb4` 中，`hw/bootrom/cheshire_bootrom.S:86` 调用平台入口后，紧接 `boot_next_stage`；正常 `ret` 返回会进入把 `a0` 当下一阶段地址的代码，不会自动进入 `_boot/main` 的内置介质启动。当前纳管 `cheshire_bootrom.sv` 的指令核对也确认该布局。

- 调用指令地址：`0x020000b6`；普通返回地址：`0x020000b8`，位于 `boot_next_stage`。
- 内置 `_boot` 地址：`0x02000154`，默认入口为 0 时通过分支到达。
- 影响范围：启用非零 PlatformRom 且预期正常返回继续内置启动的路径；不能据此声称默认启动或已有 HelloWorld 都失败。
- 官方修复：`9b4c222df72f74f90ab9f36d80ba7b527f92e62b`，`hw/bootrom: Fix platform ROM fallthrough to boot (#187)`。补丁把 `_boot/_exit` 放到平台调用之后，将 `boot_next_stage` 移到后面。本地当前尚未包含该修复。
- 详细命令、源码及 ROM 哈希、反汇编见 [发现记录](handoffs/2026-10-06_L01_platform_rom_boot_review.md)。证据为静态核查，不是目标运行。

### 5.2 后续修复范围

获得源码修改授权后，对照官方补丁评估最小适用改动，修复返回控制流及所需对齐；不升级全工程依赖、不发明绕过官方钩子的替代启动协议。保持 `boot_next_stage` 的介质载荷执行契约。

同步重新生成 `cheshire_bootrom.sv`；记录编译器/选项、ELF/dump/二进制/生成 RTL 的身份，并检查文件清单实际引用的 ROM。不能仅改汇编而继续使用旧 ROM，也不能以文本差异替代运行验收。旧 FPGA 产物的保护与新目录接入由实施任务明确。

### 5.3 最小验收

| 检查 | 判据 |
| --- | --- |
| 非零平台入口，空钩子正常返回 | 可观测调用/返回；执行随后 `_boot/main`，没有把返回值当程序入口 |
| `PlatformRom=0` | 保留内置启动；不要求平台 ROM 映射或激励 |
| 主动介质启动 | 至少一种实际模型/介质路径加载 SPM 小程序，结果可判定 |
| `boot_next_stage` 回归 | 原有载荷跳转与返回/退出约定未受破坏；SMP 如保留需核对对应路径 |
| ROM 生成一致性 | 编译 ELF/反汇编与实际使用的生成 ROM 对应；不得仅检查源文件 |

平台初始化超时、PLL 不锁、配置非法及安全切钟属于 P01/V01 后续平台验收，需有效模型及对应实现；S01-B01 的空钩子通过不等于这些场景通过。
