| `dense16rows` | `0x14008068 → 0x14010068` | 120×16 | 120/120 | 两笔通过 | 35.367 |

所有通过项均连续两笔，目标返回 0、SLINK SUCCESS、主机退出 0、无断言；检查全部目的数据、行间空隙、首尾保护区、源区未改写、编号 2→3 及等待。失败项未完成首笔，无成功日志；诊断主动退出的主机 0 不计通过。运行串行、每例主机上限 600 秒，不导出波形，未重建 RTL。

**反例的具体原因：行锁误判造成循环等待。** `dense_rows` 第 32 行（索引 31）为 `0x14008ef0 → 0x14010ef0`、120 B。中间 64 B 对应源块 `0x10008f00` 和目的块 `0x10010f00`：

- 目的写已进入写单元并持锁，但 DMA 数据缓冲为空，`WVALID=0`；所需源读尚未进入读单元（读单元空闲，DMA `RREADY=1`）。
- 源读的锁键是 `0x3c04`（index=`0x3c`、way=`0x04`），目的写为 `0x3c10`（同 index、不同 way），**实际不是同一存储块**。
- Bloom 查找位图为 `0x11`，占用位图为 `0x20011`，前者被后者包含，因此 `look_valid=1`、`locked=1`。实测 `full=0`、`error=0`、锁条目计数 1，两个解锁队列均空；不是过滤器满或已有解锁请求未处理。
- 按实际固定源码计算，源键落在桶 `{0,4}`，目的写键落在 `{0,4,17}`，与采样一致。**源读被误判上锁 → 写等源数据 → 写不能完成并释放锁 → 源读继续等待。** 这与此前 `locked=0`、后续写占住共享流水线的失败不同；同偏移关系只能约束分块，不能排除这种锁依赖。

首次运行 600 μs／2 ms／3 ms 采样停在相同等待状态，运行到 20 ms 仍无完成。新增锁探针复跑在 600 μs／2 ms 再次确认；复跑 `.text` 与首次失败逐字节一致。`dense16rows` 未到该地址而通过，不代表任意 16 行安全；`dense64_control` 覆盖该地址范围仍通过，说明本次访问时序也影响触发，不能仅凭地址对宣称必死锁。

源码依据（服务器固定依赖，与本地所读文件哈希一致）：`axi_llc_hit_miss.sv:180–184` 在 locked 时不放行 SPM 请求；`axi_llc_lock_box_bloom.sv` 拼接 index/way 并以 `look_valid | full` 判锁；`cb_filter.sv:104–105` 做占用集合包含判断；`axi_llc_write_unit.sv:155–165` 在最后写拍完成后解锁。计算及原采样见[必要摘要](evidence/dma_aw_config_20261020/joint_alignment_check/README.md)。

**结论：撤回“8 B＋两项模 64 相等关系足以保证可用”的判断。** 本轮覆盖八种起始偏移、八种步长余数和 8～520 B 中的列示行长，不是全部组合穷举；一个反例已足以否定该充分条件。64 B 对照通过，继续作为保守默认，但不升级为通用安全证明。较细粒度只能使用明确验证过的具体配置；不得据此在 HAL 中普遍放行。未修改 RTL/HAL，也未提出未经验证的新组合规则。

- **默认长搬运：** 2 ms、3 ms 的完整采样相同，`DONE_ID=1`、下一编号 3；LLC 读返回 FIFO 满、DMA `RREADY=0`，写单元空闲而 DMA 已有写数据，读描述符阻塞共同入口。读挡写的循环未消除。

### 对软件参数能下什么结论

1. **三个变量都取 8/16/32 B 整数倍，不足以保证通过。** “只放宽起点”一行的地址、行长、两侧步长全部为 32 B 倍数，仍失败；它也同时否定 16 B、8 B 倍数这一充分条件。
2. **行长并非必须为 64 B 倍数。** 24 B 行长组、123 B 源起点对照组都通过；但不能反推任意行长均安全。
3. **增加同偏移条件仍不足。** 120 B 紧密排列组的两侧起点模 64 相同、两侧步长相同，32 行仍因行锁依赖失败。
4. **64 B 的统一规则也未建立。** AW=0 默认长搬运三变量全为 64 B 倍数仍失败；本轮 AW=1 的两组全 64 B 对照通过，但不是所有地址范围、行数及并发情况下的保证。不能只靠三变量倍数划定通用合法域。

## 11. Serial Link 接收经 LLC 写入 DDR（2026-10-21）

**ROM 镜像与断言定位。** 官方 `rom.ld` 生成 LMA=`0`、VMA/入口=`0x10000000`，唯一 LOAD 段 847 B；沿官方 objcopy binary/verilog 规则，填充 `0x9a` 至 49152 B。offset `0x200` 无 GPT 签名，原 `gpt_boot_part_else_raw()` 读取 96×512 B；不是直接 ELF 预加载。TB 仅初始化 JTAG 并轮询结束，没有 halt/load/改 PC。trace 确认 8.085 μs 读到 BIST 完成，随后提交全 SPM 配置；27.791450 ms 首次执行 `0x10000000`。`spi_copy_check.json` 的对照来自 CPU 已执行的 store trace，不冒充独立读取全部 SPM 模型内存。

原 ROM `0x02001708` 写配置字节 0～3、`0x0200170a` 写字节 4～5，随后 `0x02001710` 从 `0x1001ff90` 按 64 位加载，得到 `xxxx0000000f0f0f`；`0x020004a0` 将该参数保存到栈。未知的两个高字节对应 `dif_spi_host_config_t` 末尾 padding。被调用代码只在栈偏移 8～13 读取六个有效字节，不读取 padding 14～15；配置写入与镜像搬运均完成。证据是原生成 ROM 指令解码、实际 trace 和官方结构体定义，保存在 `original_bootrom.dump`、`spi_padding_trace.txt`。这是已定位的未初始化填充字节触发断言，未见其改变本次功能结果；不删除断言、不改 ROM，也不宣称无 X 或无断言通过。

**RVV 与内存边界。** 整数数组各有 160 个元素，有效区前留 8 个元素；逐项检查两个完整输入数组、全部有效输出和全部未写输出，后保护区随 N 检查。数据通过 SPM 非缓存别名访问，CPU 准备数据后执行 fence，再进行向量操作；FP 数组同样检查输入和前后未写区。`rvv_vl_trace.json` 由 vsetvli 后分支的实际寄存器值提取：67→64+3、133→64+64+5，35→32+3、69→32+32+5。CVA6 tracer 将 RVV 助记符打印为 `INVALID`，该文本不等于异常；对照 ELF 指令编码和 Exception 记录判定。

基础访存程序、数据及栈均在 SPM；程序/BSS 结束 `0x10001d38`，SPM 测试区物理偏移 `0x10000..0x101ff`，远离顶部栈。DDR 区不承载程序。使用已有 CSR `0x7c1` 关闭 L1D，前后 fence，读回为 0；LLC SPM 掩码读回 `0xff`，保持原配置；LLC 在全 SPM 状态下将 DDR 区请求转发到行为模型，没有改为产品规划中的独立 DDR 端口。跨行测试从区内 +56 开始写 40 个 64 位元素（320 B），覆盖 L1 32 B／LLC 64 B 行边界，并检查未写字节。这里只证明上述访问条件，不代表正常缓存下的软件所有权交接。

**运行入口与复现绑定。** 生产入口不动；新增 `$R/run.py` 只调用现有 simv、保存 stdout/stderr 和状态，并检查既有 VIP 完成日志、断言及 timeout。没有成功完成标记也返回非零，不能仅凭 simv=0 放行。SPI 首轮入口已抓到写断言并实际退出 2；其源码保存为 `run_spi_initial.py`。随后 `run.py` 扩充对单独读断言 warning／`READ_DATA_X` 的识别，用原真实日志验证匹配；不是重跑 SPI。其余五例使用最终入口。普通上限 600 秒，全程串行、无波形，未延长运行。
