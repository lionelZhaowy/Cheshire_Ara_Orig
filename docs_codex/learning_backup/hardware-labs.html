实验命令与输出产物

所有命令在仓库根执行。Python只需标准库；不会访问硬件或网络。

python3 docs_codex/learning/scripts/hardware_lab.py topology --scenario default
python3 docs_codex/learning/scripts/hardware_lab.py topology --scenario ara
python3 docs_codex/learning/scripts/hardware_lab.py topology --scenario no-uart
python3 docs_codex/learning/scripts/hardware_lab.py topology --scenario ara-ext2
python3 docs_codex/learning/scripts/hardware_lab.py topology --scenario llc-bypass
python3 docs_codex/learning/scripts/hardware_lab.py lane --offset 4 --value 0x11223344
python3 docs_codex/learning/scripts/hardware_lab.py self-test
bash docs_codex/learning/scripts/run_hw_unit.sh

前七条输出到终端。最后一条使用PATH中的vlib/vlog/vsim，在新的 /tmp/cheshire-hw-unit.XXXXXX 目录建立work库、modelsim.ini、compile.log、run.log；脚本打印真实路径并设编译/运行超时。缺工具返回2，编译/仿真超时或断言/判据失败返回非零。不会运行SoC、DPI或旧编译脚本。脚本还运行 +INJECT_FAIL 验证日志检查器确实拒绝失败；Questa可能在$fatal后仍返回0，不能只看进程码。实际尝试和结果见单元检查记录。

实验步骤与成功判据

练习输入与预期失败优先查
H0 配置推导default：6个发起端，xbar目标侧ID=5；ara：7/5；ara-ext2：9/6profile与SoC是否混淆、是否误把LLC输出ID拿来比较
H1 删除UART无UART规则，I2C索引7→6、地址仍0x03003000内部索引与地址是否混为一谈；第二层错误路径
H2 lane搬移offset4、32位值→64位高半字、WSTRB=f0SIZE、地址低位、WSTRB、目标访问宽度
H3 握手检查器正常trace通过；停顿期间改payload/撤VALID/末尾未完成等人工trace拒绝只有VALID是否被错当成交；期望失败是否被吞掉
H4 独立寄存器单元按TB检查复位、字节写、结果、busy重入、W1C/IRQ、非法访问；必须出现HW_UNIT_PASS且进程成功本地vlog/vsim版本与许可证、编译日志、首个fatal与时间点

场景至少观察正确性判据
两个master同ID读不同目标输入AR、输出AR、来源前缀、R路由每个响应回原master且数据/长度正确
同master同ID先慢后快目标第一次在途、第二次背压与解除顺序保持，无响应丢失；能解释实现的停顿
AW/W错开及W/B/R背压payload稳定、W来源队列、LAST、在途计数无混帧、无提前释放；停止激励后可排空

reset/CDC/并发各域reset、队列空状态、目标ready满足明确排空/恢复契约；不声明任意瞬间复位都安全

本章自测

为什么教学脚本不叫配置展开器？

它只解析有限默认字段并按已核对规则计算几个场景，没有执行SystemVerilog语义。

单元仿真通过后可直接修改SoC吗？

仍需完成地址/类型/IRQ/wrapper契约和系统回归；本轮没有实施接入。

已有本地工具就一定能跑SoC吗？

不一定。还需许可证、匹配的源码配置、DPI/库及模型；VCS与Questa必须独立核验。
