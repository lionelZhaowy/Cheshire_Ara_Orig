RISC-V 指令集与应用二进制接口

同一段 C 可以编给 MIPS、RISC-V 或主机 x86。指令集架构（Instruction Set Architecture，ISA）规定 CPU 能识别什么指令；应用二进制接口（Application Binary Interface，ABI）规定函数参数/返回值用哪些寄存器、类型宽度以及栈约定。编译器能生成某条指令，不能为硬件增加对应的执行单元。

本课会遇到的记号含义与用途
RV64 / I / M64 位整数寄存器、基础整数指令、整数乘除。RV64 的 int 仍可为 32 位
A原子操作，如 AMO、LR/SC；不能推导任何 DMA 旁路都在同一原子观察域
F / D / C单精度/双精度浮点、压缩指令。C 使相邻 PC 可能相差 2 字节
Zicsr / ZifenceiCSR 指令与 fence.i。G 是 IMAFD + Zicsr + Zifencei 的组合简写
V / RVV向量指令；根 sw.mk 默认不带 V；硬件也必须选支持 V 的 profile
lp64dlong 和指针 64 位；浮点参数按双精度硬浮点调用约定传递；所有链接对象 ABI 要兼容

例如函数 int f(int x) 的参数与返回值常经过 a0；sp 是栈指针，ra 是返回地址。寄存器宽度不是 AXI 数据位宽，也不是 Ara 的向量长度。选项语义可查 GCC 官方 RISC-V 选项；本课具体 flags 以本地 sw.mk 和实际构建日志为准。

控制状态寄存器与异常处理

csrs mstatus, mask 修改 CPU 内部的控制状态寄存器（Control and Status Register，CSR），不是向某个内存地址写数据。RISC-V 的 M（Machine，机器）、S（Supervisor，监管）、U（User，用户）特权级决定哪些操作允许。本课沿 Boot ROM 的机器态裸机路径学习，不建立 Linux 页表。

寄存器排错问题
mstatus / mie全局中断、向量 VS、浮点 FS 与具体中断源使能是否正确？
mtvec异常/中断跳到哪里？原 crt0 默认弱 trap_vector 会自循环
mepc / mcause / mtval哪条指令触发？原因是什么？是否有相关地址或指令信息？mtval 的具体内容取决于异常与实现
mcycle / minstret经过多少 CPU 周期、退休多少指令？计数不是主机仿真的墙钟时间

异常（exception）由当前执行引起，如非法指令或访问异常；中断（interrupt）来自异步事件，如定时器。陷入（trap）统称两者；处理器进入处理程序，保存上下文并按事件处理后用 mret 返回。仅打开中断而没有能正确保存上下文的处理程序，会让程序进入默认死循环。

地址空间、MMIO 与存储属性

result[i]指向 RAM；*reg8(&__base_uart, offset)指向外设寄存器。内存映射输入输出（Memory-Mapped I/O，MMIO）让 CPU 用 load/store 访问设备，地址译码决定去向。读取某个寄存器还可能有副作用，不能像读普通数组一样随意缓存或重复读。

cache（高速缓存）保存主存副本，通过标签判断命中；SPM（Scratchpad Memory，显式寻址暂存存储器）由软件安排地址与内容，无需“查找是否已经缓存了该行”。DMA（Direct Memory Access，直接存储器访问）是另一个总线发起者：CPU 写配置，DMA 自己搬数据，CPU 不逐字复制。

volatile要求编译器保留指定的可观察访问，不负责清理 L1 或 LLC；fence用于约束内存/设备访问顺序，不等于任意缓存的 clean/invalidate；fence.i涉及指令获取同步，不是给设备 DMA 的通用缓存维护。实践边界见 一致性章节。

AXI 通道与握手机制

AXI（Advanced eXtensible Interface，高级可扩展接口）有五条独立通道：AR 读地址、R 读数据与响应、AW 写地址、W 写数据、B 写响应。每条通道在时钟边沿 VALID 与 READY 同为 1 时完成一拍传输。发送端不能等 READY 才拉 VALID；阻塞时要保持 VALID 及对应 payload 稳定。

AW 握手只接受写地址。W 可以与 AW 不同拍到达，直到最后一个数据拍被接受、并取得 B 响应，写事务才完成协议上的应答。多拍传输称突发（burst）；AWLEN/ARLEN 编码通常是 beat 数减一，AWSIZE/ARSIZE 表示每拍字节数的 log2；WSTRB 指示有效字节，WLAST/RLAST 标记最后一拍，BRESP/RRESP 报告状态。

事务 ID让互连能区分在途请求并路由响应；不同 ID 的完成顺序需要按协议理解。不要把“一个地址握手完成”当作“内存内容已被所有观察者看见”。AXI4、AXI4-Lite、AXI4-Stream 也不是可直接互换的端口；本课主存用内存映射 AXI，未来像素流可能用不同流式接口。原子 ATOP 是 AXI4 之外的扩展，当前主存路径由 LLC 上游原子适配器处理。

协议术语参考 Arm AMBA AXI 官方规范入口。本地请求/响应类型见 cheshire/typedef.svh，路由见 i_axi_xbar；勿用协议一般能力代替实例参数确认。

1. -mabi=lp64d 会把 AXI 数据总线设成 64 位吗？

不会。ABI 管软件函数边界；总线位宽由硬件参数和接口类型决定。

2. IRQ 已经到达，为什么 CPU 仍可能不进中断？

检查设备事件与使能、中断控制器路由/屏蔽、mie 和 mstatus 全局使能，以及目标特权级。不是只看一根线。

3. WREADY 为 0 时可以把 WDATA 改成下一个值吗？

在 WVALID=1 且该拍还未被接受时不可以；要保持当前数据与控制字段直到握手。
