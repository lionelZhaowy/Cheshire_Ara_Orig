AXI Crossbar 结构与并发访问

交叉互连（Crossbar）让多个发起者选择多个目标；不是所有访问都共用一条单总线。CPU 读 UART、DMA 读主存可以走不同目标；二者都读主存则争用该目标的 AR 仲裁。最终并发还受目标接收能力、队列和响应背压限制。

层本地结构保存的关键状态/原因
地址选择axi_xbar_unmuxed：每输入各一个 AW/AR addr_decode地址决定目标；匹配 [start,end)，高下标重叠规则优先。本 SoC 使用静态 localparam 地址图
分流axi_demux → axi_demux_simpleID 对应目标及在途计数；写选择状态，防止错序与 W 路由丢失
交叉连接Connectivity[i][j]可达矩阵。当前 SoC='1；断开的连接走错误目标，不是任意悬空
汇聚每目标一个 axi_muxAW/AR 仲裁、AW 选择锁定、W 来源队列、来源 ID 前缀
错误终结axi_err_slv吸收事务并返回 DECERR；写仍需处理数据，读需按 burst 长度返回

读地址译码与响应路由

  1. CPU 的 AR(id=1, addr=主存) 在输入端成交，译码选择主存输出。
  2. 若 DMA 也请求该输出，AR 仲裁决定本次接受谁；未获接受者必须保持请求稳定。
  3. mux 为 ID 加入来源前缀。教学例中来源 0/1、原 ID 两位，CPU 的 01 变为 001，DMA 的 01 变为 101。
  4. 内存返回 R(id,data,last,resp)，mux 根据前缀分送并去除前缀；demux 合并各目标返回。
  5. RVALID & RREADY & RLAST 表示该读 burst 最后一个返回拍成交；早先的 AR 成交只表示请求被接受。

硬件队列保存事务归属与顺序，并据此维护响应路由。两个不同 master 用相同原始 ID 是正常场景。

写地址、数据与响应的关联

AXI4 W 通道没有 WID。AW 选中 CPU 后，对应 W burst 必须仍来自 CPU，不能因为 DMA 此时有 WVALID 就临时换人。axi_mux 中的 W 来源 FIFO 保存写地址的选择，直到该来源最后一个数据拍完成握手才推进。demux 还保存目标选择，并可能限制切换目标，以避免写依赖形成死锁。

AW 与 W 是独立通道，发起者可以先提供 WVALID；本 crossbar 可背压等待地址路由条件满足。不能规定所有合法 AXI 发起者都必须先等 AWREADY 才拉高 WVALID。反过来，设计也不能依赖“AW 与 W 永远同拍”。下表是刻意加入停顿的教学序列，不含真实 cut 延迟。

阶段观察为何重要
AW 已选、下游未 readyAWVALID 与地址/ID 保持；选择锁住不能在等待时重新选另一个来源而更换 payload
W 中间拍被阻塞WDATA/WSTRB/WLAST 稳定不能因为 VALID 已经拉高就提前递增数据索引
WLAST 成交数据选择队列可推进并不等于 B 响应已返回，也不意味着可任意复位目标
B 成交检查 BID/BRESP，更新写事务跟踪失败响应必须传给原请求者，不能只看数据拍数
写事务步骤演示（教学动画，不是真实波形）
  1. 地址选择
  2. 保存归属
  3. 数据推进
  4. 响应完成

依次阅读下面四步；无JavaScript仍可展开解释。

1. 地址选择

AW仲裁确定来源和目标，等待READY时必须锁住有效请求。

2. 保存归属

写选择状态将后续W burst关联到已选择的来源和目标；不能逐拍重新选人。

3. 数据推进

只在WVALID与WREADY都为1时推进；WLAST也必须握手才结束这个burst的数据。

4. 响应完成

BID把BRESP送回原请求者；数据已发完不替代响应检查与设备完成协议。

事务 ID 跟踪与顺序约束

同一发起端、同方向、同 ID 的两个请求先后访问慢目标 A 和快目标 B。若全部放行，B 可能先返回；本地 crossbar 不靠响应重排缓冲解决，因此会等 A 的相关在途事务完成再允许该 ID 切换到 B。ID 跟踪计数器把“归属目标”和“还有几笔没完成”关联起来。

减少 AxiIdUsedSlvPorts 会让本来不同的 ID 在跟踪时发生别名，增加假冲突；UniqueIds=1 是对发起者行为的强约束声明，不是免费加速开关。当前 SoC 为 0。读写方向应分开理解，ATOP 还可能从写请求产生读响应，不能忽略其跨通道占用。

互连停顿与事务故障定位

先沿一笔事务记录输入握手→译码目标→目标握手→响应返回。输入 VALID 长等时查同 ID 冲突、队列满、目标 READY；数据通道停住再查 AW 路由是否建立、WLAST 是否正确、B/R 是否被上游长期背压。等待状态不是故障结论，需写出它在等待谁。性能统计同时保留有效字节、burst 长度、停顿周期及目标利用率。

本章自测

给每个 W 拍选择当前优先级最高的 master 行吗？

不行。W 没有 WID，必须沿 AW 已确定的 burst 顺序和来源；否则不同事务数据会混合。

地址图是输入端口，所以可随时改吗？

不能。本地 IP 文档要求有 AW/AR VALID 时不要修改地址图；本 SoC 将它接到常量，不提供动态重映射驱动。

连接矩阵允许访问是否等于具备安全权限检查？

不是。它只是结构可达性，不能替代 PMP/MMU、总线防火墙或设备权限机制。
