实验 3 · ELF 布局与反汇编检查

前置：拿实验 2 正常 array 的真实输出路径填 LEARN_OUT。检查是只读，通常数秒；不需要仿真许可证。

LEARN_OUT='/实际输出路径/evidence/array-spm.XXXXXX'

预期：SPM 入口 0x10000000；DRAM 入口 0x80000000。SPM 的栈符号是 0，表示继承 Boot ROM 栈；DRAM 栈符号 0x807ffff8。result 占 BSS 548 字节；有初值的 seed 位于 .misc。common.ldh 丢弃 .riscv.attributes，因此最终 ELF 的 readelf -A 可能为空；ISA 核对还需构建日志、对象属性和实际反汇编。

成功判据：能把 main 的 call、result 的地址和 ELF PT_LOAD 对起来。DRAM ELF 构建成功不证明 DRAM 可用；只有外部模型/DDR 覆盖装载段和栈，才能继续运行。若 relocation truncated，先看 medany、地址间距和对象参数，不先改总线。

实验 5 · 定时器轮询

前置：CLINT/RTC 时钟存在，机器态可读 mcycle；使用 stage=3 的高低高稳定读取。输入：原数组 + 等 8 个 RTC ticks。

timeout 60 bash docs_codex/learning/scripts/build_example.sh timer spm
python3 docs_codex/learning/scripts/check_run.py '/实际 simulate.log 路径' --stage timer

预期：额外出现 timer ticks>=8，errors=0/return 0。RTC=32768 Hz 时 8 ticks 约 244 μs，这是目标时间量级，不是仿真墙钟时间。循环超过 10,000,000 mcycle 返回 11；进入该循环之前的测频仍可能等待，由外部 300 秒预算兜底。

失败顺序：是否卡在最初测频 → mtime 是否递增 → rtc_freq 寄存器 → CPU cycle → 轮询条件。扩展阅读练习：解释 mtimecmp、mie.MTIE、mstatus.MIE、mtvec 的顺序；本轮不给未验收的中断 handler 套上“可直接运行”。

实验 6 · DMA 搬运与数据校验

硬前提：先读 SPM 专用缓冲契约；全 128 KiB SPM、DMA=1、DmaConfEnableTwoD=1（驱动寄存器为 2D 布局）、单任务、无其他 DMA 用户、栈不入保留区。不得切换 LLC way。

timeout 60 bash docs_codex/learning/scripts/build_example.sh dma spm
python3 docs_codex/learning/scripts/check_run.py '/实际 simulate.log 路径' --stage dma

stage=4 保留原数组计算，再把 a[i]=i 复制到 c；sys_dma_memcpy 使用 2D 前端的 1D 拷贝模式，返回任务 ID。轮询 done-id 与该 ID 相等，超时返回 14；无 DMA 返回 13；LLC_SIZE 不符返回 12。预期：DMA copied=548、sum=28085/errors=0、VIP SUCCESS。

失败顺序：硬件 feature → 源/目标均为高别名且未被低别名缓存 → 长度/next-id/done-id → AXI 返回 → 比较结果。原 dma_2d.spm.c 的阻塞等待没有超时，可作为阅读练习而非本课默认运行入口。进一步用纸笔推演其 4 段×15 字节、dst stride=7/src stride=1 的重叠拷贝，区分“总线搬运量”与最终缓冲长度。

只有 VIP SUCCESS观察到返回 0；还需确认被测程序真的检查了结果

1. 为什么每次构建都新建输出目录？

避免 flags/头文件变化被旧 make 时间戳漏掉，也避免覆盖用户旧 ELF；日志与 ELF 可以一一对应。

2. 故障注入有何价值？

证明错误能从逐项校验传播到 main 返回、scratch2、VIP 和外部检查器。只验证成功分支可能漏掉总是 return 0 的测试。

3. DMA/RVV 改成 dram 模式为什么脚本拒绝？

它们依赖本课明确预约的 SPM 非缓存数据区与栈契约。DRAM 共享数据需要另建并验证完整缓存协议，不能只换链接脚本。
